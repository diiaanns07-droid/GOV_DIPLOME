## Метки в тексте

| Метка | Что делать |
|---|---|
| `[ТРЕБОВАНИЕ ВУЗА: …]` | вставить требования кафедры (объём, оформление, обязательные разделы), когда владелец их пришлёт |
| `[ПРОВЕРИТЬ ИСТОЧНИК]` | открыть источник (DOI, официальный сайт, adilet.zan.kz), сверить выходные данные; облачная среда R14 не имела доступа к ним |
| `[РЕЗУЛЬТАТ R03]`, `[РЕЗУЛЬТАТ R13]`, `[РЕЗУЛЬТАТ R04]`, `[РЕЗУЛЬТАТ R02]` | вставить числа из `results/RESULTS.md` / `DELIVERY.json` роли с SHA; не округлять «в лучшую сторону» |
| `[РЕЗУЛЬТАТ R10]`, `[РЕЗУЛЬТАТ R01: FINAL]` | приёмка и состав финальной сборки (B2 уже вписан) |
| `[РИСУНОК …]` | вставить рисунок (Mermaid-схемы — из `docs/birge/ARCHITECTURE.md`, скриншоты — из `research/round-14-results/*/screens/`) |

## Правила для того, кто продолжает

1. Каждое число — из `research/round-14-results/R14/FACTS.md` (там указан файл, ветка и SHA источника). Нового числа нет в FACTS — сначала добавить его туда с источником.
2. Синтетику называть синтетикой; NOT_RUN / NOT_EVALUATED не превращать в результаты.
3. Большие куски кода в текст не вставлять — описывать решения; при необходимости — приложение со ссылкой на файл.
4. Шаблон промпта для ChatGPT/Codex — `docs/birge/CONTINUE_WITH_GPT.md` §3.7 (глава) и §3.8 (источники).
