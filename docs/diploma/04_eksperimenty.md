## 4.1. Эксперимент 1. Классификация казахско-русских обращений при нехватке реальных данных

### 4.1.1. Исследовательские вопросы

Разбиение синтетики — **по шаблонам**: шаблоны тестовой части не встречаются в обучении, поэтому синтетический test измеряет обобщение на «невиданные формулировки» генератора, а не запоминание. Близкие дубликаты между частями отсекаются (коэффициент Жаккара по символьным 3-граммам ≥ 0.8; в synth_v3 таких 0), тексты, совпадающие с оценочными после нормализации, удаляются из обучения. Класс «не жалоба» исключается.

Разметка текстов людей — владелец по правилам `LABELING_GUIDE_v2.md` в офлайн-инструменте `web/labeling`; согласие второго разметчика на подвыборке 100 текстов — каппа Коэна с бутстрэп-интервалом (`ml/labeling/agreement.py`) — [РЕЗУЛЬТАТ R02: κ и 95 % ДИ].

### 4.1.3. Факторы эксперимента

**Режим обучения (6):**

| Режим | Обучение | Выбор гиперпараметров |
|---|---|---|
| `synth_v1` | синтетика v1 → v2 | синтетическая валидация |
| `synth_template` | шаблонная синтетика v3 | синтетическая валидация |
| `synth_llm` | LLM-синтетика | её валидация |
| `synth_all` | v3 + LLM | синтетическая валидация |
| `human` | только тексты людей, стратифицированный 5-fold | 15 % обучающей части фолда (люди) |
| `mix` | v3 + LLM + тексты людей из обучающих фолдов | 15 % людей обучающей части фолда |

**Модель (3 + 2 без обучения):** словарная эвристика (не обучается), логистическая регрессия «метода v1» на символьных n-граммах с признаками словаря, трансформер `FacebookAI/xlm-roberta-base`; без обучения — LLM zero-shot (по желанию владельца, тексты уходят во внешний API) и модель v1 как есть.

### 4.1.4. Протокол оценки

1. **Один оценочный набор — все тексты людей.** Режимы без людей предсказывают их целиком; режимы «люди» и «смесь» — 5-fold, и прогноз каждого текста делает модель, которая его не видела (out-of-fold). Так все ячейки таблицы сравнимы на одних и тех же текстах.
2. Тексты людей **не используются для выбора** эпохи, порога и гиперпараметров в синтетических режимах; в «людях» и «смеси» валидация — только из обучающей части фолда.
3. Если размеченных текстов людей меньше 200, оценка на людях не выполняется (`NOT_EVALUATED`), а не подменяется синтетикой.
4. Словарь эвристики составлен до появления текстов людей и после не меняется.
5. Тесты конвейера проверяют отсутствие утечки (spy-тест k-fold и синтетики) и то, что тексты людей не попадают в файлы результатов.

### 4.1.5. Метрики и статистика

- **Главная метрика — macro-F1** по 12 классам (усреднение по классам, присутствующим в оценочном наборе, как у v1); дополнительно accuracy, weighted-F1, P/R/F1 по классам, матрица ошибок, ожидаемая ошибка калибровки (ECE, 10 корзин).
- **Срезы**: язык (ru / kk / mixed), стиль (официальный, разговорный, опечатки, транслит, сленг, длинный, вопрос), трудные случаи, «сомневаюсь».
- **Доверительные интервалы**: 95 % перцентильный бутстрэп, 2 000 повторов, seed 20261011; на синтетике — **кластерный бутстрэп по шаблонам** (тексты одного шаблона зависимы), на людях — по текстам.
- **Парные сравнения**: разность macro-F1 двух моделей/режимов на одних и тех же бутстрэп-выборках и доля выборок, где разность > 0. Сравнения: трансформер − логрегрессия, трансформер − словарь, логрегрессия − словарь; v3 − v1→v2; **LLM-синтетика − шаблонная**; смесь − синтетика (вклад людей); смесь − люди (вклад синтетики); zero-shot LLM − трансформер.
- **«Потеря на людях»** = macro-F1 на синтетическом test − macro-F1 на людях (разные наборы, не парная разность) — главная величина для вопроса В1.
- **Кривая обучения**: режимы «люди» и «смесь» при доле текстов людей в обучении 25 %, 50 %, 100 % (оценка — на всех текстах людей) — вопрос В3.
- **Устойчивость к seed**: трансформер — 3 повтора с разными seed (по возможности).

Если 95 % интервал разности содержит 0, преимущество считается **не доказанным** на данном объёме данных.

### 4.1.10. Угрозы валидности

1. **Малый и удобный набор текстов людей** (200–400 текстов от знакомых владельца): широкие интервалы, тексты могут быть «аккуратнее» реальных обращений в 109; распределение категорий задано участниками, а не реальным потоком.
2. **Один основной разметчик**: возможная систематическая ошибка разметки; частично контролируется вторым разметчиком на подвыборке (каппа Коэна).
3. **Шаблоны, правила спорных случаев и словарь написаны по одним правилам** — словарь на синтетике завышен.
4. **LLM-синтетика может быть похожа на тексты людей по стилю, но не по распределению тем**; казахский язык LLM может быть неестественным.
5. **Нет реальной базы 109** — выводы относятся к текстам, написанным добровольцами по просьбе, а не к реальному потоку обращений.
6. **Калибровка**: `score` — top-1 softmax, не вероятность; ECE приводится, но порог «нужна проверка» подбирается на ограниченной валидации.

## 4.3. Эксперимент 3. Прогноз территорий с риском жалоб (прототип)

- **Цель**: ежемесячно выбирать K территорий (K = 10, 20, 30), где в следующем месяце будет не меньше N жалоб; показатель кейса Gton — «60–70 % прогнозов подтверждаются».

- **История**: синтетическая, 34 месяца (2024-01…2026-10) × 12 категорий с сезонностью, «горячими» эпизодами, всплесками и влиянием строек (§3.13); **synthetic, `demo: true`**.
- **Признаки**: число жалоб за 1, 3, 12 месяцев по категориям; тот же месяц год назад; тренд; погода месяца (снегопад, оттепели, мороз, осадки, жара) — Open-Meteo (LOCAL-9); тип территории.
- **Модели**: градиентный бустинг (scikit-learn `HistGradientBoosting`); запасная — сезонная наивная + взвешенная частота; базовые линии — «как в прошлом месяце» и «как в том же месяце год назад».
- **Проверка — backtest на скользящем окне**: модель обучается на данных до месяца M, прогнозирует топ-K на месяц M + 1; окно сдвигается по месяцам; никаких данных из будущего (в том числе погодные нормы считаются только по прошлым месяцам).
- **Метрика — precision@K**: доля из K выбранных территорий, где событие действительно наступило; сравнение с базовыми линиями.

### 4.3.2. Результаты

Цель — у территории в следующем месяце не меньше 4 жалоб; в среднем таких территорий 3.3 % (≈ 77 из 2 334 в месяц), поэтому случайный выбор даёт precision@K ≈ 0.03. Прогнозные месяцы 2025-07…2026-10 (16), синтетическая история с тремя seed (2026, 2027, 2028) — 48 прогнозов «месяц × seed»; каждый раз модель обучается только на прошлом. Среда: Linux, Python 3.13.16, scikit-learn 1.9.1; команда `python3 -m ml.civic_forecast backtest --seeds 2026,2027,2028` (`ml/civic_forecast/RESULTS.md`, R13 @ 8705829).

**Выводы.**
1. Модели примерно в 13–18 раз лучше случайного выбора (0.033 по DELIVERY R13) и стабильно лучше обеих базовых линий (выигрыш над лучшей базовой ≈ +0.06 при всех K).
2. **Ориентир Gton «60–70 % прогнозов подтверждаются» не достигнут**: 0.58 / 0.49 / 0.44 при K = 10 / 20 / 30. Чем больше K, тем ниже точность — в топ попадают территории с меньшим риском.
3. **Погодные признаки ничего не добавили** (−0.004 в среднем): при прогнозе на месяц вперёд известна только климатическая норма месяца, а она повторяет сезон, который модель и так видит по истории. Погода может помочь при прогнозе погоды на месяц или при более частом (недельном) пересчёте.
4. **Простая запасная модель почти не уступает бустингу** (разница +0.009) — для пилота разумно начинать с прозрачной модели без зависимостей и переходить к бустингу, только если он выиграет на реальных данных.
5. Разброс по месяцам большой (precision@10 от 0.10 до 1.00) — на одном месяце судить о модели нельзя.

**Важно для интерпретации.** История синтетическая: результат показывает, что конвейер и протокол проверки работают и модель **восстанавливает закономерности, заложенные в генератор** (сезонность, устойчивые «горячие» места), а не то, что прогноз сработает на реальных данных акимата. Погода в этом прогоне — тоже синтетическая фикстура (реальный архив Open-Meteo — задача LOCAL-9). Реальная история короче и шумнее; проверка — в пилоте на обезличенной выгрузке обращений (`ml/civic_forecast/README.md`).

## 4.4. Выводы по главе

1. Разработан воспроизводимый протокол сравнения источников обучающих данных и моделей для казахско-русских обращений с оценкой на отложенных текстах людей, кластерным бутстрэпом и парными сравнениями.
2. Предварительные результаты на синтетике показывают слабый перенос между генераторами и слабость простых моделей на казахском и транслите — это обосновывает и оценку на людях, и проверку трансформера.
3. Для поиска дублей ограничение по месту принципиально: без него текстовое сходство путает одинаковые проблемы в разных местах.
4. Прогноз на синтетической истории: бустинг и простая запасная модель превосходят базовые линии (precision@10 0.58 против 0.47), но не достигают ориентира Gton 60–70 %; погода в виде климатической нормы не помогает.
