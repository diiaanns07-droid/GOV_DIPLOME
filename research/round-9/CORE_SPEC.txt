Фактические поля v2 — schema_version (не schema), координаты lon/lat; API адаптировать к существующему коду. Unicode NFC ID допустимы как в BUILD. Не навязывать ASCII-ограничение старых модулей.

ЦЕЛЬ
Пользователь выбирает исходные записи, которые условно не учитывать в одном или нескольких случаях. Сайт сравнивает ручной, обычный оптимальный и устойчивый планы. Показывает исходные и худшие результаты и цену устойчивости в расстоянии. Это анализ допущений о данных, НЕ прогноз кризиса, закрытия объекта, риска или потребностей жителей.
Исходные записи/QA/лицензии неизменны. QA-флаг не доказывает ошибку и не исключает запись автоматически. Выбор исключений явный и отменяемый. Не добавлять дорожную симуляцию в этот раунд.

ГРАНИЦЫ И ФОРМАТ
Обычный city-plan-v2 остаётся совместимым (до 16 кандидатов). Устойчивость: 1..25 точек, 0..12 кандидатов, 0..5 выбираемых; все остальные v2-ограничения сохраняются.
Файл envelope:
{schema_version:"city-resilience-v1", plan:<полный city-plan-v2>, cases:[{id,label,disabled_source_ids:[]}]}.
cases: 1..7 пользовательских случаев плюс автоматически добавленный base с пустым исключением = максимум 8. id — правила BUILD, уникален, "base" зарезервирован; label непустая строка <=120 Unicode code points, без управляющих символов, отображается только текстом.
disabled_source_ids — уникальные ID исходных записей выбранного города/категории, хотя бы 1 и не больше числа таких записей. Не принимать candidate IDs вместо source IDs; namespace сохранять. Два случая с одинаковым набором допустимы; показывать их совпадение, результат не должен зависеть от дубля.
Исходный snapshot берётся из plan; исключения НЕ подменяют snapshot и НЕ переписывают data.js. Строго проверить полный envelope и plan до вычисления и до смены UI, JSON UTF-8 <=256KiB, duplicate keys/NaN/бесконечности/неизвестные поля отклоняются.
В r9 envelope производные поля не экспортируются и не принимаются. Экспорт состоит из входа; HTML-отчёт отдельно пересчитывается. Старый экспорт v2 и его политика derived_results сохраняются.
При >12 кандидатах устойчивость даёт typed too_many_candidates до предвычислений; v2 продолжает решать свои 16. Не удалять кандидатов, не переходить на эвристику без явного запроса.
Непроверенные объекты при прямом вызове публичных evaluate/optimize/создания поиска валидировать. Внутренний уже проверенный путь допустим; изменение переданного объекта не должно обходить ограничения.

РАСЧЁТ
Повторно использовать проверенную геометрию/ограничения v2 (haversine-mm-v1), не переписывать основной движок.
Каждый случай: baseline — только исходные записи, не входящие в disabled_source_ids; кандидаты и ограничения одинаковы во всех случаях. before/after/delta и nearest считаются внутри конкретного случая.
Исходные места фильтруются в вычислительном представлении, исходный контекст не мутируется.
При отсутствии известных after расстояние/mean/max=null, delta=null при неизвестном before. Покрытие 0 относится только к точкам и выбранным записям.
Потери плана в случае = лексикографический вектор L=(unknown_count, weighted_sum_mm, max_mm), меньше лучше; max=null рассматривается как +infinity только внутри сравнения.
Худший вектор W = lex max L по всем случаям включая base. При одинаковом L перечислить все худшие case IDs, стабильно отсортированные. Не называть максимум отдельных компонент одним реально случившимся случаем.
Обычный план = mean-оптимум v2 на base.
Устойчивый план = допустимый набор, минимизирующий (W, L_base, cost, sorted candidate IDs) лексикографически. Стоимость и ограничения от случая не меняются; недопустимые required возвращают infeasible, не снимаются.
Полный перебор <=4096 подмножеств. Предвычислить расстояния и baseline для каждого случая; не пересчитывать гаверсинус внутри каждого подмножества. При cancel/incomplete не выдавать optimal.
Цена устойчивости = base weighted_mean_mm устойчивого минус base weighted_mean_mm обычного, в метрах /1000; только если обе метрики известны и оба решения optimal. Иначе null с причиной. Разница может быть 0, планы могут совпадать; не выдумывать преимущество.
Для ручного, обычного и устойчивого плана — таблица по каждому случаю (unknown/mean/max/coverage/cost), W и список worst_case_ids. Ручной недопустимый план явно помечать и не рекомендовать.

ПРОВЕНАНС И ВОСПРОИЗВОДИМОСТЬ
resilience_problem_digest включает v2 problem digest, полные case IDs/labels/отсортированные exclusions, версии schema/metric/objective "worst-lex-v1"; от порядка cases/IDs не зависит. selected_ids не входит; resilience_scenario_digest дополнительно включает ручной выбор.
Изменение любого входа/среза/города инвалидирует результат и объяснение; request_id + digest не позволяют позднему ответу перерисовать новый сценарий.
Сохранять исходный source_snapshot и отдельный digest исключений. Доверять только recomputed результатам, не меткам imported/verified.
Никаких вероятностей по равновесным случаям, усреднённого "риска", псевдоэкономии тенге, популяции из весов и пешего времени из расстояний.

API ДЛЯ СОВМЕСТНОЙ РАБОТЫ
Выделенный web/resilience.js или маленький модуль/адаптер, не вторая копия plan.js.
validateResilience(input, ctx) -> clean envelope / typed error
evaluateResilience(ctx, envelope, selectedIds) -> per_case, worst_vector, worst_case_ids, feasible
createResilienceSearch(ctx, envelope, options) -> ограниченный пошаговый поиск, progress/cancel
optimizeResilience(ctx, envelope, options) -> status, nominal, robust, evaluated, feasible_count, resilience_problem_digest, metric_version, objective_version.
Точный формат адаптера задокументировать. Не сравнивать побайтно независимые внутренние digests; сравнивать математические результаты и свойства канонизации.
Во всех внешних JSON вместо infinity — null/явный статус. UI асинхронно уступает event loop; синхронный Node путь для оракула.

ИНТЕРФЕЙС И ПРИЁМКА
Вкладка/панель "Устойчивость к допущениям": реальные source IDs и имена с QA/источником, явный выбор записей, список случаев, сравнение трёх планов, цена устойчивости, таблица по случаям. Применение только кнопкой; не автозамена ручного плана.
Для пользователя видно: "Условно исключаем из расчёта; это не подтверждение закрытия". Пустые исходные данные не означают отсутствие услуги.
Полный доступ через таблицу/клавиатуру, карта дополнительная. Смена города/категории/среза сбрасывает или инвалидирует несовместимые случаи, не переносит ID молча.
JSON roundtrip и HTML-отчёт с перечнем исключений, provenance, версиями, ограничениями. При ошибке импорта исходное состояние неизменно.
Новый функционал после исправления подтверждённых блокирующих дефектов r8. Независимый оракул, фикстуры обоих городов, отмена/устаревание и импорт в браузере. Старые v1/v2 тесты сохраняются.
