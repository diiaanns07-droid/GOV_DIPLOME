СОВМЕСТИМЫЕ ИЗМЕНЕНИЯ КОНТРАКТА (civic-v1 + дополнения R06 раунда 12)
1. POST /staff/feedback/{id}/moderate, поле action:
   approve | reject  — как в v1 (+ необязательные status, duplicate_of). Без status новое сообщение
                       переходит в in_review (или answered, если есть ответ); иначе статус не меняется.
   status            — {expected_revision, status, reason, public_reply?, duplicate_of?}: только обработка.
   note              — {internal_note}: служебная заметка; ревизию не меняет; никогда не публична.
   recategorize      — {expected_revision, category, reason}: категория сотрудника (staff_category);
                       категория жителя не перезаписывается.
   Поля, не подходящие к действию, -> 422. Ошибки: invalid_transition (с allowed), reply_required,
   duplicate_chain, has_duplicates, no_change, stale_revision 409.
2. Статус обработки handling_status: new | in_review | answered | duplicate | closed. Переходы:
   new -> in_review|answered|duplicate|closed; in_review -> answered|duplicate|closed;
   answered -> in_review|closed; duplicate -> in_review; closed -> in_review.
   Это статус работы сотрудников платформы, НЕ статус eOtinish/iKOMEK и не работ города.
3. GET /staff/feedback: status=<список через запятую>|all, q (до 100 символов; текст без учёта регистра,
   ё=е; «#12» — номер), order=oldest|newest; category учитывает исправление сотрудника.
   Без moderation и status — как в v1 (moderation=pending). Ответ: + handling_counts, filters.
4. Новые поля DTO: staff — handling_status/label/next, duplicate_of, staff_category, effective_category(_label),
   handled_by/at; карточка — duplicate_of {id,...}, duplicates [...]; квитанция и публичная карточка —
   handling_status, handling_label (без номера исходного сообщения и без заметок).
5. POST /feedback: 409 request_id_conflict теперь содержит previous_receipt (квитанция уже сохранённой
   версии, без текста) — только для того же отправителя и того же client_request_id.
   422 для текста без слов (<5 букв или <3 разных) и для >3 ссылок.
6. SQLite: схема civic-feedback-v2. Существующая БД мигрирует автоматически (ALTER TABLE ADD COLUMN),
   старым строкам статус выводится из модерации: pending->new, решение с ответом->answered, иначе closed.
