# K10, раунд 5 (REVIEW): QA координат и состава выборки в BUILD

Проверяется готовая сборка `prototypes/city-evidence` из `claude/beautiful-clarke-sbzomj` @ `0bf27deb8549b325b34a9610402613d745544edb` (baseline). Сборка извлечена побайтно (`tools/extract_build.py`, 57 файлов, id git-объектов сверены) и проверена как `file://`, так и через её `serve.py`.

**Политика:**
- совпадение координат — флаг для проверки, а не автоматическое удаление;
- категории не переименовываются;
- полнота города не оценивается.

Статус: **ничего не исправлено**. Ниже только находки и предложения. Слово FIXED не используется.

## 3. Влияние на выбор квадрата 2×2 км (раунд 3)

`tools/selection_impact.py`: сначала граничная проверка без сырых данных, затем точный пересчёт всех ячеек сетки по сырым выгрузкам раунда 2. SHA этих выгрузок совпали с закоммиченным `raw_extracts.sha256`.

| Вариант счёта | Шымкент: выбранный / второй | Тот же квадрат? | Астана: выбранный / второй | Тот же квадрат? |
|---|---|---|---|---|
| V0 все записи (правило раунда 3) | 55 / 34 | да | 65 / 60 | да |
| V1 одна запись на точку | 39 / 34 | да | 62 / 52 | да |
| V2 одна на кластер ≤ 2 м | 38 / 32 | да | 62 / 52 | да |
| V3 без групп ≥ 3 записей | 41 / 34 | да | 65 / 53 | да |
| V4 без всех совпадающих | 33 / **34** | **нет** (соседняя ячейка `row 11, col 11`) | 59 / 49 | да |

**Вывод.** Совпадающие записи завысили счёт выбранного квадрата Шымкента: 55 записей, но только 39 разных точек. Выбор устойчив к схлопыванию совпадений (V1–V3). При полном исключении совпадающих записей (V4) он меняется с перевесом в 1 запись. Для Астаны выбор устойчив во всех вариантах. Варианты — анализ чувствительности, а не предложение удалять записи.

## 5. Предложения для BUILD (не реализованы, проверяются тестами SHOULD)

1. В `tools/build_data.py` добавлять к записи поле `qa_flags` или `coord_group` (id группы, размер, правило) из `qa_flags.json`. Проверка: `run_qa.py`, `SHOULD_data_exposes_coord_group_flag`.
2. На карте показывать значок группы («N записей в одной точке — координата требует проверки»). По клику — список записей с атрибутом `data-coord-group-item="<id>"`. Проверки: `ui_coord_group.cjs`, оба SHOULD.
3. В карточке показывать причину флага. Поле адреса с e-mail выводить как «адрес не указан (в поле источника не адрес)», не копируя значение.
4. Записи не удалять и не сдвигать. Проверки MUST в обоих тестах требуют, чтобы все ID и координаты сохранились.
