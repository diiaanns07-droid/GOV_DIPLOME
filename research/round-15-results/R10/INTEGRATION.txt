§1. R01 · ui/web_server.py · raw-маршруты сотрудника (B-102) — до B1
=====================================================================================================
В CivicV2.handle ветка kind == "raw" возвращает ответ до проверки handler.staff. В раунде 14 все raw-маршруты (R07 heat,
R08 akim/summary, R12 geo) были открыты всем, и это было верно. В раунде 15 по CONTRACT §7 «сотрудник» у raw-маршрутов:
GET works-calendar, GET works-conflicts (R12, engine.civic_geo.api.handle, strip_prefix) и GET akim/board, GET akim/week
(R08, ui.civic_akim.api.handle_get). Если R01 поставит V2Handler(..., kind="raw", staff=True), флаг staff будет проигнорирован.

Минимальная правка (перед вызовом self._raw):

         if handler.kind == "raw":
    +        if handler.staff:  # раунд 15: works-calendar, works-conflicts (R12), akim/board, akim/week (R08)
    +            _principal, denied = self._staff(context)
    +            if denied:
    +                return denied
             staff = self._is_staff(context) if handler.staff_view else None

Замечание: _staff() требует CSRF и для GET (unsafe=True). Клиент оболочки шлёт X-CSRF-Token только в изменяющих запросах —
либо экраны R08/R12 шлют токен и в GET (как модули R06), либо для GET сотрудника проверять сессию без CSRF
(store.require_staff(context, unsafe=False)) — решение R01 + R15. Тест R10 шлёт токен в GET сотрудника и принимает оба варианта.

§2. Всем ролям с маршрутами §7 — как R10 принимает API (tests/civic/R10/api_v2.py)
=====================================================================================================
- Модуля нет → шлюз 503 {"error": "module_not_ready", "message": по-русски, "role": роль из §7} — это PASS («ждёт модуль»).
- Модуль есть: сотрудник без входа → 401/403; изменяющий запрос сотрудника без CSRF → 403; житель без X-Birge-Device → 4xx
  с понятным текстом; открытые GET → 200. Ни одного 500 на примерах тел из интерфейса и на пустом теле {}.
- Ошибка = {"error": код, "message": текст по-русски} (шлюз) или {"ok": false, "error": {"code", "message"}} (сервис),
  без следов Python (Traceback, File "…", KeyError…).
- Записи §5 проверяются по полям и перечислениям: инициатива (kind, status, joined — целое, target по §4, point в Астане,
  starts_at с поясом, demo: true у синтетики), двор (yard-…, members — целое, captain null или {display_name, since}),
  профиль службы (id из §3, kind, color #rrggbb, sla_* целые), кризис (kind, zone.kind, tasks[].service из §3, в публичном
  ответе нет обновлений public: false), встреча (registered — целое, orders[].service из §3), событие ленты (link «#…»),
  работа v2 (service, kind, segments, starts_on/ends_on ГГГГ-ММ-ДД, source), конфликт (kind, ≥ 2 работ, severity, advice_ru/kk).
- Приватность §10 в ответах жителю: нет ключей *device*, нет телефонов, ИИН, e-mail в текстах; members/joined/registered —
  числа, а не списки. «Я приду» / «Я живу здесь» дважды с одного устройства — +1, «выйти» — обратно.
- Передача жалобы (R09): причина сохраняется в handoffs, поля срока (*due*, *deadline*) не меняются.
- Пример тел запросов — функция bodies() в api_v2.py (по CONTRACT §5); если ваш модуль ждёт другие имена полей — напишите
  в своём INTEGRATION, R10 поправит пример (это не подгонка: пример — «как в интерфейсе»).
