# R04 · раунд 15 · результаты и журнал оценок

Среда: облачная сессия Claude Code (Linux, Python 3, без сети, без GPU). Модель категорий — цепочка classify раунда 14
(v1 + словарь R03; v2 ONNX нет в облаке). Время — на одном ядре облака.

## Коротко для диплома (R14): метод, числа, ограничения

**Задача.** По тексту обращения (ru / kk / вперемешку / латиница) и, если есть, категории жителя и точке — назвать
службы, которым нужно обращение, и объяснить одной строкой; отдельно выявлять случаи, где нужны две службы
(«яма после раскопок водоканала» -> Водоканал + Дорожная служба).

**Метод (без нейросетей, объяснимый).** 1) Категория и уточнение — от жителя или из текста: ~45 упорядоченных
«сигналов» (регулярные выражения по сведённому тексту: қ -> к, латиница -> кириллица) и запасная категория модели
classify раунда 14. 2) Служба — по таблице акимата «категория/уточнение -> служба» (R08, с правками акимата).
3) Восемь правил совместных случаев (раскоп сетей, течь + провал/наледь, упавший столб, дерево на проводах, снег с
крыши на тротуаре, светофор без питания, два отключения, две проблемы). 4) Если дана точка — календарь работ R06:
чья раскопка была рядом. Ответ — службы, роль (ведущая / участвует), объяснение ru/kk, источник (rules / model).

**Протокол оценки.** Набор 208 фраз с ожидаемыми службами (92 совместных) разделён на dev / test; test зафиксирован
коммитом до написания правил, каждый прогон test записан в журнал. Так как фразы и правила — одного автора, отдельно
считается независимая проверка на синтетических корпусах R02, которые R04 не писал (первый прогон — до настройки).

**Ограничения (писать в диплом как есть).** Правила написаны вручную под соглашения разметки автора; живых
размеченных обращений нет (LOCAL-задача — форма LOCAL-6 и разметка по route_cases.json). Опечатки ловятся слабо.
Кто копал, если в тексте не сказано и в календаре работ рядом ничего нет, — по умолчанию Водоканал (с пометкой
«уточните»). Числа test = 1.0 нельзя приводить без оговорки об авторстве; главное честное число — независимая проверка.

### Независимая проверка: R02 v1_in_v2 (2 725 текстов), первый прогон @ 54b93e07
- срабатываний «2 службы»: 38 (1.4 %); все 38 проверены вручную — настоящие раскопы («после раскопок не восстановили
  асфальт», «после ремонта теплотрассы не восстановили газон»): **ложных 0 из 2 725**;
- полнота внутри семейств раскопов (asphalt 48 + lawn 32): **38 из 80 = 0.475** — пропуски: казахское «қазудан кейін»,
  «асфальт төселмеді», «после работ не положили асфальт» без слова «сети»;
- служба совпала с категорией разметки (служба ∈ службы этой категории по таблице R08): **0.868**.
После этого прогона правила дополнены (_RESTORE_FAIL, «қазу», вежливое «Рақмет» в конце жалобы — не благодарность);
повторно (уже виденный): раскопы 79 из 80, вне раскопов «2 службы» 0, согласие 0.869.

### Демо-мир R02 (world_v1.json @ 0c0a8636, 743 синтетические жалобы) — согласованность с экранами
- сцена 8 (c-w1500010 «Раскопали дорогу и так и бросили…»): route() -> Водоканал + Дорожная служба — совпадает с
  route_hint, который R02 записал в мир;
- ведущая служба route() = служба записи R02 (таблица R08): **719 из 743 (0.968)**; расхождения — 17 жалоб «разбита
  плитка тротуара», которым генератор R02 назначил совместное heating + road без раскопок в тексте, и 7 «лифт» (до
  правки CP8 R04 отправлял лифт в УК; теперь — по таблице, как R02);
- «2 службы»: в мире 40 совместных, route() видит 19, общих 6 — у R02 пары выбраны генератором случайно
  (плитка -> теплосеть, строительный мусор -> мусор + аппарат акима, спилили деревья -> озеленение + благоустройство).
  Предложение R02 — INTEGRATION.txt п. 8: совместные — из текстов, где route() видит 2 службы.

### Скорость
route(): p50 0.1 мс, p95 0.3–0.6 мс, максимум < 2 мс после прогрева (цель < 30 мс). Первая загрузка модели classify
(~80 мс) — при старте сервера (warmup()).
«Злые» входы 5 000 знаков (одна буква без пробелов, «кв. 1 » ×800, «@aaaa » ×830): route ≤ 12 мс, moderate ≤ 13 мс после
прогрева. Было 357 мс: обезличивание модели v1 (ml/civic_classifier/text.py, шаблон e-mail) квадратично на длинном
слове — теперь моделям подаются первые 1 000 знаков (это защищает и старый /classify), правилам — 2 000; шаблон «… жоқ»
ограничен 40 буквами слова. Тест test_long_adversarial_input_stays_fast.

«дома 7 9 11 13 15 17», «маршруты 8 10 12 14 16 18» (кодов 791, 101 нет) — по-прежнему перечни. 65 143 строки —
ложных 0; 12 600 синтетических номеров + 3 000 номеров КЗ парами — пропусков 0. Остаток: зарубежный номер
растущими парами без «+» и подписи («8 91 92 93 94 95») — проверка человеком.

## 3. reply_draft() — черновик ответа

Проверки (tests/civic/R04/round15/test_r04_replies.py): все 5 статусов × ru/kk — без канцелярита, без «{…}», числа
в тексте — только из записи (номер, день срока, рабочие дни); без паспортного срока устранения — «сообщим срок»,
и предупреждение сотруднику; совместное исполнение — «Водоканал — сделано, Дорожная служба — в работе»; передача —
«срок ответа не меняется» без внутренней причины; отказ без причины — место «[причина — допишите]» и needs_input;
дубль — номер общего обращения. Охрана языковой модели отбрасывает новые числа, числительные, месяцы и службы.
Стенд (шлюз + patch R01, демо-база R09): черновик по номеру B-0001 за 4.7 мс.
Стенд сборки R01 B0.12 с миром (16 окт 03:30): черновик просроченной жалобы B-0642 писал «Срок ответа — 14 октября»
(уже прошёл). Исправлено (ed24c452): «Срок ответа (14 октября) уже прошёл — извините за задержку.» + предупреждение
сотруднику; после передачи служба не повторяется. Мир R02 через хранилище R09 (743 × ru/kk): было 7 черновиков с
повтором службы и 5 с прошедшей датой как сроком — стало 0 и 0; длина ≤ 271 знака; HTTP-проверка на стенде 14/14.
