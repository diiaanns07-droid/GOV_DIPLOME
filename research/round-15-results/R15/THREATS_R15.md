## 2. Кто нападает (нарушители)

N1 — любопытный сосед (хочет узнать, кто из соседей в Birge и кто написал); N2 — скрипт накрутки с одного адреса и новыми
`device_id`; N3 — чужой сайт в браузере сотрудника (CSRF); N4 — автор текста с HTML-нагрузкой или с «инструкциями» для ИИ;
N5 — сотрудник, который ошибся или превысил свою службу; N6 — зритель на защите в той же сети Wi-Fi (все — «один адрес»);
N7 — внешний ИИ-провайдер (тексты уходят за рубеж).

## 3. Уровни

- **высокий** — раскрывает, где живёт конкретный житель, или публикует его личные данные; аноним действует от имени
  акимата; чужой код выполняется у жителя или сотрудника (XSS); внутренние данные штаба видны всем; тексты жителей
  уходят во внешний API; ИИ выдаёт выдуманные числа как данные платформы.
- **средний** — накрутка счётчиков больше чем вдвое с одного адреса; обход модерации, который ловит только человек;
  служебные данные без личных (логины, причины передач) в публичной части; один адрес кладёт очередь или сервер.
- **низкий** — защита в глубину (модуль не проверяет сам то, что уже проверяет шлюз), мелкие метаданные, неудобства.

Цель раунда (R15.txt «Готово, когда»): на FINAL-5 нет открытых находок уровня «высокий».

## 4. Общие правила для всех новых модулей (P1–P10)

Это ожидаемое поведение «по умолчанию»; угрозы ниже ссылаются на эти правила.

| # | Правило | Как проверяет R15 |
|---|---|---|
| P1 | Публичный ответ — **белый список полей** (как `public_view` R09), а не «вся запись минус секреты». Нет: id устройства и его хэша, времени вступления/регистрации, логина сотрудника, `request_id`, текста «на проверке», точки автора точнее 3–4 знаков | поиск сырых id устройств, их sha256 и маркеров во всех ответах |
| P2 | Любой текст жителя — модерация R04 **до** публикации; флаг или нет функции — «на проверке»; автор видит своё «на проверке», другие — 404 | создание с ПДн → публичный список/карточка |
| P3 | Все тексты и названия — `textContent`/`esc()`; ссылки ленты и действий — только внутренние `#раздел/id` | браузерная проба с HTML-нагрузкой; формат ссылок в API |
| P4 | Сотрудник = сессия R02 + `X-CSRF-Token` + свой Origin; проверяют **и шлюз** (`staff=True`), **и модуль** | без cookie → 401/403; без/с чужим CSRF → 403; чужой Origin → 403 |
| P5 | Запись жителя — лимит шлюза по адресу (`V2_RATE_LIMITS`) + лимит модуля по устройству; «один раз с устройства» — плюс суточный предел на одну цель с адреса (S08) | 25–30 запросов с новыми `device_id` → 429 и счётчик в пределе |
| P6 | id устройства — секрет: `crypto.getRandomValues` (≥ 96 бит, S16); в базе — только солёный хэш (как `device_hash` R09); никогда в ответах, журналах, ленте | сырой id не встречается в файле SQLite и в ответах |
| P7 | Ошибки — 400/401/403/404/409/422/429 с понятным текстом; без трассировок, SQL, путей; «нет» и «скрыто» — одинаковый 404 | неизвестный/скрытый id → 404 одного вида |
| P8 | Демо: синтетика `demo: true` и «Пример»; id демо-устройств засева **нельзя прислать через API** (S20) — иначе зритель в той же сети ломает сцену «Я приду 14 → 15» | засеянное «Я приду» нельзя снять запросом `leave` |
| P9 | Каждый список — с пределом (≤ 100), период — с пределом (≤ 92–400 дней), геометрия — ≤ N вершин и в границах города (S19) | огромный период/полигон → 400/422 быстро |
| P10 | Новые страницы (Ситуационный центр, Календарь работ — если отдельный HTML) — CSP шлюза: `script-src 'self'` + хэши, без внешних скриптов, без inline-обработчиков `on…=` | заголовок CSP страницы; браузер без нарушений CSP |

## 13. Что сознательно не закрываем (остаточный риск — честно для диплома)

- Житель без учётной записи: id устройства можно сбросить, лимиты держатся на адресе. В общей сети Wi-Fi (защита, школа)
  все — «один адрес»: лимиты могут задеть честных людей; перед показом — перезапуск `run-city.bat` (как в раунде 14).
- Права сотрудника не разделены по службам: любой «редактор» действует за любую службу; журнал пишет роль. Для пилота —
  учётные записи служб и права по службе (в отчёт R14 как «до пилота»).
- Регулярные выражения обходятся словами («восемь семьсот один…»); последняя защита — проверка человеком «на проверке».
- Локальный показ — HTTP на 127.0.0.1; для пилота — HTTPS, HSTS, cookie `Secure`, адрес за доверенным прокси.
- Хранение ПДн на территории РК и согласие на обработку (Закон РК «О персональных данных и их защите» [ПРОВЕРИТЬ
  ИСТОЧНИК]) — вопрос пилота; в раунде 15 тексты жителей не уходят во внешние API (T-R03-04, S14).

## 14. Как это проверяется (тесты R15 раунда 15)

`tests/civic/R15/round15/` — каждый тест помечен ID угрозы. Нет модуля роли в проверяемой сборке → **skip с
причиной «NOT_RUN: нет модуля …»**; модуль есть, но маршрута ещё нет в шлюзе → проверка сервиса напрямую
(`make_service(db).handle(...)`), а через HTTP — NOT_RUN. Проверить ветку роли без сборки:
`R15_ROOT=<рабочая копия ветки> python3 -m pytest tests/civic/R15/round15 -q`.
Найденное → ID `S42…` в `tests/civic/R15/r15_common.py` (xfail strict, пока не исправлено) и patch в `INTEGRATION.txt`.
