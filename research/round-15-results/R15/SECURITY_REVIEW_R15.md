## Что сделано хорошо (проверено тестами)

- **Двор и «Я приду» — только числа.** Ни id устройства, ни его хэша, ни времени вступления в ответах; в файле SQLite —
  только солёный хэш (R16, R13). «Моё» видит только своё устройство. Старший по двору — сосед, имя на проверке.
- **Сотрудник — сессия + CSRF + свой сайт, в модуле и в шлюзе.** 6–7 видов отказа на каждое действие штаба, встреч,
  инициатив и передач (аноним, житель, автор, без CSRF, чужой CSRF, чужой Origin, роль «житель»).
- **Публичное — белым списком полей.** Кризис жителю — без задач служб, внутренних обновлений и журнала; жалоба —
  без причины передачи и логина; инициатива — без автора; «на проверке» — 404 всем, кроме автора и сотрудника.
- **Тексты жителей — через модерацию R04 до публикации**; R06 вообще не принимает HTML в работах; на экранах — только
  textContent (браузерная проба: нагрузка видна как текст, ни одного вставленного элемента, нарушений CSP нет).
- **ИИ-аналитик:** вопрос — данные, а не инструкция; числа модели вычёркиваются; модели уходят только вопрос сотрудника
  и заголовки блоков без цифр; ключ — только из окружения (нет в ответе даже из текста ошибки провайдера).
- **Тяжёлые публичные запросы ограничены:** хроника — не длиннее квартала и не старше года (400 сразу), фильтр ПДн —
  1–6 мс на враждебных 5000 символах.

## Остаточный риск (честно)

- Житель без учётной записи: id устройства сбрасывается, лимиты держатся на адресе; в общей сети Wi-Fi все — один адрес.
- Права сотрудника не разделены по службам: любой редактор действует за любую службу; журнал пишет роль, не имя.
- Регулярные выражения обходятся словами («восемь семьсот один…») — последний барьер — проверка человеком.
- Голосовой ввод (если R09 включит): распознаёт браузер (в Chrome — серверы Google) — нужна подсказка у кнопки.
- Хранение ПДн в РК и согласие на обработку — вопрос пилота [ПРОВЕРИТЬ ИСТОЧНИК: Закон РК «О персональных данных и их
  защите»].

## Что сделать до пилота

HTTPS + HSTS + cookie Secure; учётные записи служб с правами по службе; адрес клиента за доверенным прокси для лимитов;
журнал действий штаба с хранением и выгрузкой для проверки; проверка фото «после» человеком до публикации.
