# «Спросить Birge» — как устроен ИИ-аналитик акима (R03, раунд 15)

Для главы диплома и заявки Gton (R14): что это, почему так, что гарантирует, как проверено. Цифры — из
`results/ASSISTANT_EVAL.md` (прогоны в облаке, демо-данные с пометкой «Пример»).

## Что это

Сотрудник акимата спрашивает словами — по-русски, по-казахски или вперемешку: «Где в Нуре больше всего жалоб на снег за
неделю и какие службы отстают?». За доли секунды — карточка: 2–3 крупных числа, 2–4 строки, список мест или служб,
«Показать на карте» (карта перелетает к месту) и «Открыть …» нужный раздел. Числа — те же, что на карте, в «Картине дня»,
в «Штабе ведомств»: аналитик не хранит своих данных, он спрашивает модули платформы.

## Устройство: агент с инструментами, где инструменты — функции платформы

```
вопрос ──► разбор (правила ru/kk) ──► план: какие намерения (1–3) и параметры (район, тема, период, служба)
                                          │
              ┌───────────────────────────┼──────────────────────────────┬─────────────────────┐
              ▼                           ▼                              ▼                     ▼
   R07 карта жалоб            R08 «Картина дня»              R17 «Штаб ведомств»     R12 / R16 / R13
   heat(), districts()        summary(): темы, районы,       board_snapshot(),       конфликты работ,
                              просрочки, пульс                active_incidents()      инициативы, поручения
              └───────────────────────────┬──────────────────────────────┴─────────────────────┘
                                          ▼
                  факты с источником (журнал вызовов: модуль, функция, статус, мс)
                                          ▼
          код собирает блоки ru + kk: числа, строки, места, действия «Показать на карте» / «Открыть …»
                                          ▼
          (по желанию) языковая модель: только порядок блоков и вводная фраза — числа из её текста вычёркиваются
                                          ▼
                     ответ + «Как получен ответ» (какие источники спрошены и что они сказали)
```

- **11 намерений:** горячие места, рост тем, сравнение районов, просрочки, отстающие службы, кризис, конфликты работ,
  инициативы жителей, поручения встреч, прогноз, сводка дня; несколько в одном вопросе («снег в Нуре **и** службы»).
- **Планирование с запасными путями:** соседа нет или он не связан с базой — честный блок «пока нет данных», а не ошибка;
  табло служб ещё не подключено — «отстающие службы» считаются по срокам «Картины дня» с подписью источника; штаб не
  открыт — пульс «Картины дня» с пометкой.
- **Прозрачность:** каждый ответ несёт журнал вызовов («Как получен ответ») — что спросили, у кого, сколько миллисекунд.

## Почему не «просто языковая модель»

| Вариант | Чем плох для акимата |
|---|---|
| Модель отвечает сама (чат) | Придумывает числа и названия служб; ответ нельзя проверить; данные уходят во внешний сервис |
| Модель пишет SQL к базе | Доступ модели к сырым данным, тексты жителей и персональные данные рядом; ошибка запроса = неверное число |
| Только дашборды | Аким должен знать, где искать; нет ответа на вопрос словами, тем более на казахском |
| **Birge: код считает, модель — только слог** | Числа всегда из модулей платформы; без ключа и сети работает так же (офлайн); модель можно отключить |

## Гарантии (проверяются тестами)

1. **Числа — только код.** Модель получает вопрос (как данные) и список блоков без чисел; возвращает строгий JSON
   `{order, lead}`. Любая фраза её текста с цифрой или числительным (ru / kk / en), ссылкой или разметкой вычёркивается.
   Не JSON, лишний ключ, неизвестный блок, дольше 8 с — ответ кода с пометкой «офлайн-режим».
2. **Вопрос — данные, а не инструкция.** «Забудь правила…», «ignore previous instructions», «придумай», «покажи
   телефоны», «удали» — модель не вызывается вовсе, ответ из данных с пометкой. Просьбы выдумать число, изменить данные, показать персональные данные —
   вежливый отказ этой части; у аналитика нет функций записи.
3. **Приватность.** В ответе только агрегаты (числа, улицы и дворы из OSM, названия служб); тексты жителей, телефоны,
   ИИН не попадают никуда, и тем более модели. Маршрут — только для сотрудника (сессия + CSRF), 30 вопросов в минуту.
4. **Честность.** Синтетика помечена «Пример»; модуля нет — «пока нет данных»; источник каждого блока подписан.

## Как проверено (облако, без сети)

| Что | Результат |
|---|---|
| 50 вопросов (ru 20 / kk 15 / вперемешку 15), первый прогон, отложенный набор | факты верны в 92 %; три сцены демо на трёх языках — 9 из 9 |
| 30 новых вопросов, записанных после правок (обобщение) | факты 86,7 % (93,3 % без ошибки оценки); выдуманных чисел — 0 |
| После правок правил (уже не отложенные) | 100 % на обоих наборах |
| С настоящими модулями соседей раунда 15 (R17, R12, R16, R13) | 100 % на обоих наборах |
| 10 провокаций (инструкции, «придумай», персональные данные, «удали») | 10 из 10 безопасны |
| Задержка без модели | медиана < 3 мс, 95 % < 60 мс; через шлюз 117 мс; цель «< 1 с» с запасом |
| Холодный старт сервера (мир R02) | без прогрева первый вопрос 3,4 с (карта грузит геометрию); с прогревом при старте — 0,7–1,2 с |
| Тесты | модуль: 81 прошли + 1 пропущен (нет всех соседей сразу); вместе с помощником v1, шлюзом и классификатором r14: 857 прошли |

Худший случай при ошибке разбора — подсказка «что я умею» или верные числа на соседний вопрос, но не неверное число.
Режим с языковой моделью в облаке проверен заглушкой; живой прогон — LOCAL-17 на ноутбуке (команда — RUN.txt).
