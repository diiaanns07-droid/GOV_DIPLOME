3. ЧТО ГАРАНТИРУЕТ ENDPOINT
   POST /assistant тело ровно {question, object_id|null, scenario_id|null}; facts/context/role/... -> 400.
   question: строка 1..500 символов (иначе 422/413). Нужен object_id или scenario_id (422).
   Черновик/архив/несуществующий объект неразличимы: 200 + source="unavailable".
   429 при >20 вопросов/мин с одного client_ip (in-memory). Ответ: {ok:true,data:answer}, Cache-Control no-store.
   answer: {schema, source: llm|template|unavailable, mode, model, intent, language, text,
            statements:[{text,kind,fact_ids,source_ids,required?}], fact_ids, warnings,
            object_id, scenario_id, context_digest, facts_version}
   Поля source/text/fact_ids/warnings — по CONTRACT; остальные — аддитивные (contract_delta.txt).

4. ФРОНТЕНД (web/index.html + ASSETS, R01)
   ASSETS: "/civic/assistant/assistant.js" и "/civic/assistant/assistant.css" (явные файлы, без каталога).
   Подключить <link rel="stylesheet" href="/civic/assistant/assistant.css"> и
   <script src="/civic/assistant/assistant.js" defer></script> после shell.js.
   shell.js R01 уже вызывает mount("assistant", root, {objectId}) -> CivicAssistant.mount({root, api, objectId}).
   Компонент вызывает только api.request("POST", "/assistant", {...}, {signal, timeoutMs}).
   Для сценариев: CivicAssistant.mount({root, api, objectId: null, scenarioId: "<case_id>"}).
   Редактор (R04): CivicAssistant.mountDraftReview({root, api, onApplyField(field, value, evidence)})
   field ∈ title|kind|schedule.planned_start|schedule.current_planned_end|budget.amount_kzt|
           budget.basis|responsible.organization|location_text (location_text — только подсказка, не geometry).
   onApplyField лишь заполняет форму R04; сохранение/публикация — обычными действиями редактора.
   По умолчанию помощник не нужен для чтения карты/карточки: его отсутствие ничего не ломает.
