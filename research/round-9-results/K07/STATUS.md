### Дефекты, найденные на `d18847f`

**D1 (средний): клик человека по «Найти точные оптимумы» / «Сравнить» сразу после ввода теряется.**
- Шаги: v2 → «Демо-набор» → в «Бюджет» ввести 660 (без Tab и Enter) → нажать мышью «Найти точные оптимумы», удерживая кнопку ~100 мс.
- Ожидалось: поиск с бюджетом 660.
- Наблюдалось: поиск не запущен (`opt.status` = `stale`/`idle`), бюджет 660 применён, нужен второй клик. То же с названием случая и «Сравнить».
- Причина: mousedown снимает фокус с поля → `change` → отложенное применение (`setTimeout 0`) срабатывает до mouseup → перерисовка заменяет кнопку → `click` уходит общему предку.
- Почему тесты BUILD этого не видят: Playwright `click()` шлёт mousedown и mouseup подряд, а `flush()` из `e82214e` спасает только этот случай.
- На `d865dd4` клик терялся при любой скорости; мой патч r8/r9 (тот же `setTimeout`) это не исправлял — тест BUILD `plan_keyboard` из `d18847f` на копии `d865dd4` + мой патч: FAIL «typed budget + immediate «Найти»». Касание (BRT1) на `d18847f` проходит.

**D2 (малый): после ввода и быстрой смены города сообщение относится к старому городу.**
- Шаги: 390 px с касанием, v2 → демо → стоимость K1 = 0 → коснуться «Астана».
- Наблюдалось: «Стоимость K1: нужно целое 1..1000000; значение не применено.» вместо «Город изменён — сценарий v2 сброшен…».
