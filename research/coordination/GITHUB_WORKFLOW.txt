Рабочая схема для 12 доступных Claude Code, 14 исследовательских ролей и локального координатора.

Актуальные остатки лимита и распределение по слотам: CLAUDE_CAPACITY_12.txt. Слоты аккаунтов не равны номерам исследовательских ролей.

Репозиторий, указанный текущим origin: https://github.com/diiaanns07-droid/GOV_DIPLOME.git
Дополнительный репозиторий для каждой модели не требуется. Существующий GOV_DIPLOME может хранить код, исследования и handoff обоих городов. Старую конкурсную публикацию менять для этого не нужно.

При первоначальной проверке 5 октября 2026 папка research была untracked. Последующая проверка git ls-remote и git fetch подтвердила существование main и 12 веток Claude. Однако во всех 12 ветках только записи состояния новых сессий, без исследовательских результатов; подробности в REMOTE_AUDIT.txt. Для передачи реальных материалов подготовлена отдельная ветка codex/research-import-2026-10-05. До успешного push наличие файлов на компьютере не означает доступности облачным агентам.

Порядок:
1. Один координатор делает начальный импорт подготовленных файлов в отдельной ветке: CLAUDE.md, актуальный PROJECT_CONTEXT.md, нужные распакованные исследования и research/coordination. Сначала просматривает состав; архивы, .env и локальные настройки исключены. Не включать автоматически всё рабочее дерево.
2. Commit + push этой ветки, проверка diff и содержимого. После согласованного объединения агенты стартуют от нового main; до объединения они могут читать назначенную отправленную ветку импорта.
3. У каждого Claude Code отдельная ветка сессии и точные собственные пути. Не заставлять все облачные среды писать в одну общую ветку. Если среда ограничивает имена веток, использовать назначенное ей имя.
4. Каждая небольшая законченная часть: файлы → handoff → commit → push. Первый checkpoint сделать сразу из уже готовых результатов. Не рассчитывать только на автоматический push в конце длинной задачи.
5. Готовая работа идёт на проверку через PR. Незавершённую можно сохранить в ветке/draft PR. Один координатор проверяет и объединяет; агенты не мержат друг друга автоматически.
6. При лимите/смене исполнителя другой Claude или Codex получает ветку, SHA и путь к STATUS.md, продолжает от этого состояния. Это сохранение работы, не способ снять или обойти лимит.

Срочное сообщение каждому Claude: AGENT_SAVE_NOW.txt.
Шаблон передачи: CHECKPOINT_TEMPLATE.txt. Поручение преемнику: RESUME_AGENT.txt.
Если агент уже исчерпал лимит, использовать скачанные файлы/последний успешный push. Не предполагать, что он сможет выполнить ещё один запрос.

Уже импортированные результаты:

- extracted_* — распакованные файлы; исходные ZIP сохранены.

Первый текущий приоритет:
Получить недостающий AST_A10_evidence.json; передать реальные материалы агенту 14/координатору для анализа обоих городов. У многих исследователей были сетевые ограничения. Перед повторным поиском проверить доступ к 2–3 нужным первоисточникам. Не тратить оставшийся лимит на повтор того же заблокированного обзора.

Claude Code поддерживает cloud-ветки GitHub; настройки сети задаются окружением. Официальные источники, просмотрено 5 октября 2026:
https://code.claude.com/docs/en/claude-code-on-the-web
https://code.claude.com/docs/en/cloud-environments

Для разрешения доступа к нужным источникам пользователь может настроить соответствующее облачное окружение и конкретные домены. Добавление домена не гарантирует, что сайт откроется: возможны robots, аутентификация и ограничения самого сайта. Агент записывает фактический результат, а не обходит запрет.
