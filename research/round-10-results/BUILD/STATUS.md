## Этап 3 — AI-шов и записка (сделан на стороне BUILD)

Пакетов K02 (AI) и K08 (записка) раунда 10 нет ни в одной ветке origin на момент чтения (полный перебор веток ~07:40 UTC). Поэтому шов и записка сделаны BUILD по CONTRACT; при появлении пакетов их нужно сверить/подменить.

- **AI-шов** `agent/school_ai.py` + `POST /api/school-ai`: запрос `school-ai-request-v1` {request_id, case_digest, question, facts[], views, origin_ids}; модель получает ID/метрики фактов (без значений) и может вернуть только {intent, fact_ids, tool_calls, needs_clarification}; строгая проверка (лишние ключи, неизвестные факты/точки/виды, недопустимые действия, числа в уточнении → отказ). Свободный текст модели не возвращается. Ответ `school-ai-response-v1` с `source = model | fallback`, `reason_code`. Ключи только на сервере (тот же `read_settings`, что у советника учебного режима), текст исключений провайдера не отдаётся. Ограничение CONTRACT: сервер не удостоверяет числа из браузера (локальное однопользовательское приложение).
- В браузере блок «Спросить о результате»: текст и числа собираются кодом из текущих `facts` по выбранным ID; кнопки действий только меняют вид (Сейчас/A/B, точка, ограничения) — места A/B меняет только пользователь. Ответ принимается, только если `request_id` и `case_digest` совпадают с текущими; иначе «Ответ устарел» (проверено задержкой ответа и изменением порога).
- **Живой AI: NOT_RUN.** В этой среде сервер сообщает `missing_key` (провайдер не настроен); `.env` не читался. Тесты шва — с поддельным клиентом (`tests/test_school_ai.py`, 17 PASS: валидный выбор, 7 видов отказа, отсутствие ключа, утечка текста ошибки, плохие запросы).
- **Записка** `web/govtech/school/note.js`: один статический HTML (вопрос, вывод по правилу, таблица Сейчас/A/B, метод, источники со статусами, ограничения, case_digest) + встроенный кейс `application/json`. «Скачать записку (HTML)» → реальный файл (40 969 байт); «Загрузить кейс…» принимает и записку: читается только встроенный кейс → тот же digest. Внедрение разметки через название кейса закрыто (тест). Пример: `screens/stage3/example_note_shymkent.html`.

Проверки этапа 3: pytest (вкл. `test_school_ai.py`) PASS; `school_case.cjs` 3402 PASS (вкл. записку); браузер `runs/stage3_ai_note_browser.json` — fallback-ответ с меткой источника, отброс устаревшего ответа, записка → диск → импорт (digest совпал), без ошибок страницы.
