# K03 r10 — пешеходные расстояния pedestrian-v1 для школьного кейса

Небольшой детерминированный модуль расстояний по сети для `school-access-case-v1` (CONTRACT r10), обоих городов. Не симулятор пробок, не дорожный редактор, не планировщик. Внешних и платных API нет.

## Что это даёт пользователю

Для каждой пары «точка анализа → школа/кандидат» модуль выдаёт одно из трёх:
- расстояние по пешеходной сети в целых мм с маршрутом на карте;
- честный отказ с причиной;
- прямую — только отдельным явным режимом «По прямой».

Прямая **никогда** не подставляется вместо отсутствующего пути.

| Режим (policy_id) | Что используется | Как подписывать |
|---|---|---|
| `geodesic` (policy_id = null) | прямая haversine-mm-v1 | «прямая, не маршрут» |
| `pedestrian-v1-strict` | рёбра с пешеходным доступом из данных: явное правило `foot` или класс пешеходной инфраструктуры OSM (footway, pedestrian, steps, path, living_street) | «маршрут по пешеходным рёбрам OSM/Overture (не проверено на месте)» |
| `pedestrian-v1-exploratory` | все рёбра без запрета, включая дороги без тега `foot`, условные правила, велодорожки — с явными допущениями | «маршрут по неполным данным (не гарантированно доступный пешеходный путь)» |

## Статусы

`distance_mm = null`, `geometry = null` при любом статусе, кроме `ok`.

| Статус | Когда | Текст для UI |
|---|---|---|
| `ok` | путь найден; допущения перечислены | «путь найден» + допущения |
| `access_unknown` | strict: рядом с точкой нет проверенного ребра, либо путь есть только через рёбра с неизвестным доступом | «пешеходный доступ на пути не подтверждён данными» |
| `disconnected` | пути нет, и компонента точки целиком внутри среза | «в модельной сети среза пути нет (не доказательство физической недоступности)» |
| `outside_coverage` | точка вне квадрата, либо пути нет, но обе стороны выходят к краю среза | «путь вне среза не проверен» |
| `unsnappable` | ни одного ребра без запрета ближе 100 м | «точка дальше 100 м от сети» |

Допущения в `ok`:
- `foot_access_unknown`, `cycleway_foot_unknown`, `conditional_foot_rule`;
- `vehicle_oneway_not_applied_to_foot`;
- `snap_model_connection` — отрезок от точки до сети по прямой, входит в длину;
- `route_partly_outside_slice`;
- `boundary_unverified` — более короткий путь за краем среза не исключён.

Русские тексты — `school-access-routing.js` (`STATUS_RU`, `ASSUMPTION_RU`).

## Как устроено

1. **Данные (`COVERAGE.md`, `audit_network.py`).** Сырой K10-пакет Overture `2026-09-23.1` (OSM, ODbL) из донора `d18847f`; sha256 = `data.js.files` базы `d2ff344`. В `data.js` у сегментов нет ID соединителей, поэтому граф строится из сырого пакета.
2. **Граф (`build_graph.py` → `graph/<city>.graph.json`).**
   - Узлы — `connector_id`. Пересечение линий без общего соединителя (мост, тоннель) — не узел.
   - Рёбра — куски сегмента между соседними соединителями (по вершине). Проверено на всех строках: соединитель всегда на вершине.
   - Допуск по направлениям для strict и exploratory, допущения, мост/тоннель/уровень, OSM `record_id`.
   - Hash: `graph_sha256` (входы + политика + граф), `policy_sha256`.
   - Лицензия: ODbL-1.0 с атрибуцией.
3. **Политика (`policy/pedestrian-v1.json`).** Привязка — к ближайшему ребру своей политики не дальше 100 м. Правила доступа и направления — в файле.
4. **Маршрут (`routing.js`, независимый оракул `routing_ref.py`).**
   - Дейкстра в целых мм, ничья — по ID узла.
   - Геометрия GeoJSON от точки до точки.
   - `parts`: привязка / сеть / привязка.
   - `route_edge_ids`.
   - Проверка края среза.
5. **Адаптер (`school-access-routing.js`).**
   - `distanceMatrix(case, G)` → строки матрицы CONTRACT.
   - `routeLayers(matrix, filter)` → GeoJSON для MapLibre: сеть, привязки и прямая — отдельно.
   - `explainRow(row)` — текст только из полей строки.

## Качество покрытия (кратко; подробно — `COVERAGE.md`, `fixtures/city_pairs_summary.json`)

| | Шымкент | Астана |
|---|---|---|
| Сеть в квадрате / подтверждено для strict | 125,5 / 29,1 км | 156,2 / 45,9 км |
| Пары фиксированного набора: strict ok / access_unknown | 32 / 121 из 153 | 54 / 36 из 90 |
| Exploratory ok | 153 из 153, но у 152 есть `foot_access_unknown` | 90 из 90, у 88 есть `foot_access_unknown` |
| Длина по сети / прямая (exploratory), медиана [мин–макс] | 1,38 [1,04–2,42] | 1,39 [1,09–2,03] |

**Вывод.** На текущих данных проверяемый пешеходный маршрут (strict) получается лишь для части пар. Остальные честно `access_unknown`. Exploratory даёт расстояние почти везде, но это «маршрут по неполным данным», не доказанный путь. Это ограничение данных OSM/Overture среза; модуль не может его исправить.

Важное следствие правила привязки (`R-snap-rule-effect`, INFO): в 26 из 98 пар, где strict найден, exploratory **длиннее**. Точка привязывается к ближайшему ребру своей политики — к дороге, а не к тротуару в 30 м. Сравнивать варианты A/B можно только в одной политике; смешивать режимы нельзя.

## Чего нет / ограничения

- Не проверено на месте: светофоры, ширина, бордюры, освещение, зима, заборы школ, вход на территорию.
- Привязка ищет ближайшее ребро и **не видит физических препятствий** между точкой и ребром (ручной граф `h11-between`, запрос `A-to-P150`). Отрезок привязки подписан как модельное соединение.
- Буфер вокруг квадрата в данных 0 м. Новая выгрузка Overture с буфером — NOT_FETCHED. Маршруты у края помечаются `boundary_unverified`.
- Нет времени в пути: только метры по прямой/сети. Нет пробок, транспорта, населения.
- Интеграция в основной сайт — задача BUILD (`INTEGRATION.md`); общий сайт здесь не менялся.
