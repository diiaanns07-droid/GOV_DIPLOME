# K10 → BUILD: как подключить пакет Астаны (school-access-case-v1)

Пакет поставляется как данные, не как код сайта. Общие файлы меняет только BUILD (K04).

## Что брать

| Файл | Назначение в продукте |
|---|---|
| `package/astana.case.json` | кейс по CONTRACT. Только входы: результатов, digest и сумм внутри нет; строгий импорт пересчитывает всё сам |
| `package/schools.json` | расширенная карточка школы для боковой панели: имена kk/ru/POI, здания OSM, привязанные POI, конфликты, `verification_status` записи |
| `package/match-review.json` | почему запись школой считается или не считается. Решения по всем 8 «школам» текущего среза приложения |
| `package/sources.json` | источники; 6 `not_fetched` показывать как «не открыто/не проверено», а не скрывать |
| `package/MANIFEST.json` | sha256 файлов, буфер, `case_digest_k10` (предложение; канонический `case_digest` вычисляет BUILD) |

Текущий `web/govtech/core/data.js` не заменять: CONTRACT требует миграции provenance. Пакет — отдельный вход нового режима «Доступность школ».

## Что показать пользователю (обязательно)

- **Город и вид данных:** «Астана — открытые вторичные данные OSM/Overture, не официальный реестр. 0 школ сверено с официальным источником». Это не учебная модель 52.56 и не synthetic demo.
- **Доступность школы** (`access_eligibility`):
  - `known_public` — вывод K10 по номерному названию и геометрии OSM (QA `eligibility_inferred_from_name`);
  - `known_restricted` — специальная школа, школа для одарённых, частная/международная или вечерняя;
  - `unknown` показывать как возможную неполноту базы, а не как отсутствие школы.
- **Конфликты** (`qa.location_conflict`, `identity_conflict`, `possible_same_site`) — на карточке и в легенде. У школы №8 местоположение спорно, её доступность `unknown`.
- **Точки анализа** — «центры жилых зданий OSM (не жители)». **Гипотезы A/B/C** — «точка для сравнения, не участок». Стоимость и статус земли — «неизвестно»; выдуманный бюджет не нужен.
- **Порог 800 м** — параметр пользователя, не норматив.
- **Буфер 2100 м:** школы за рамкой участка нужны для расчёта ближайшей школы у границы. Показывать их полупрозрачными или с подписью «вне участка». Расширять сам участок нельзя: для этого нужен новый snapshot.

## Импорт (недоверенный)

- Лимит размера проверяется до разбора; схема строгая; любая ошибка — атомарный отказ без частичного применения.
- Эталон отказов — `scripts/k10case.py`: 33 мутации в `tests/test_k10_package.py`, коды `unknown_field`, `derived_field`, `outside_bbox`, `bad_cost`, `bad_land_status`, `bad_capacity` и др. Коды BUILD могут отличаться; отказ обязателен.
- Смена кейса или города сбрасывает результаты, объяснения и AI предыдущего кейса. Эталон — `transfer_check()` и `tests/k10_city_switch.cjs`.

## Проверка нового BUILD (UI-import smoke)

`tests/ui_import_smoke.cjs` проверяет на настоящей странице:
- импорт пакета: город, `case_id`, все ID;
- видимость пометок «вторичные/гипотеза»;
- наличие digest без результата;
- 8 отказов без изменения состояния;
- переход Шымкент → Астана импортом: digest меняется, записей Шымкента не остаётся, результата и AI тоже.

Скрипту нужен шов страницы. По умолчанию:

```js
window.SCHOOL_ACCESS_UI = {
  importText(text) /* → {ok, code?} */,
  state() /* → {city_id, case_id, case_digest, school_ids[], origin_ids[], candidate_ids[], result_digest|null, ai_digest|null, labels_text} */
}
```

Другие имена — через `--adapter adapter.json` с ключами `open`, `import` (или `fileInput`), `state`. Пример — `tests/fixtures/mock_*.adapter.json`; эти моки нужны только для проверки самого smoke.

```bash
NODE_PATH="$(npm root -g)" node research/round-10-results/K10/tests/ui_import_smoke.cjs --url http://127.0.0.1:8501/ --sha <BUILD_SHA> \
  [--adapter adapter.json] --other-case <пакет Шымкента K01>
```

На `d2ff344` шва нет → `TEST_INCOMPATIBLE`, интеграция `NOT_RUN`.

## Независимая сверка чисел

`scripts/reference_compare.py` — справочный «Сейчас / A / B / C» по прямой, только для сверки с `compareCase` BUILD/K06. Расчёт сферический, разница в несколько метров с эллипсоидом допустима. Это не движок продукта.

## Проверено на BUILD `c0b276e8a2d8d97a369252470f60e97bf1858f1d` (school-access, этап 1 BUILD)

Головной расчёт сверялся headless (`tests/crosscheck_build_school_case.cjs`, `results/build_school_case_c0b276e/`):
- `SCHOOL_CASE.compareCase` BUILD на пакете K10 после адаптера совпадает со справочным расчётом K10;
- проверено для «Сейчас» и каждой гипотезы: строки ±1 мм, ближайшая школа, метрики, автовыбор — **7 PASS**.

Отличия шва BUILD от CONTRACT, из-за которых пакет «как есть» не принимается:

| № | BUILD c0b276e | CONTRACT / пакет K10 | Что сделать |
|---|---|---|---|
| 1 | обязательное поле `variants {A,B}` | есть только `selected_candidate_ids` | при отсутствии принимать `{A: null, B: null}` |
| 2 | обязательное поле `parameters.target_policy`; допустимость школы — по категории Overture, `access_eligibility` игнорируется | «ближайшая допустимая существующая школа»; в пакете `access_eligibility` с источником вывода | целями брать `known_public`, `unknown` показывать как неполноту. В адаптере K10 — `include_ids` = known_public |
| 3 | `model_assumptions` — только строки | в пакете `{id, text}`: на них ссылаются факты | принимать `{id, text}` или превращать в `"id: text"` |
| 4 | `snapshot_id` должен совпадать с загруженным срезом `overture-<release>-<city>` | snapshot пакета K10 шире среза: OSM-слои и буфер 2100 м | загрузить пакет K10 как отдельный снимок; другой срез не подставлять (как и сейчас) |
| 5 | ограничение `schools_outside_slice_not_loaded` всегда | в пакете 33 школы буфера | выводить ограничения из содержимого кейса |
| 6 | `qa` — строки-коды | `qa` — `{code, text}` | при чтении брать `code` |

**Данные Астаны по умолчанию в `c0b276e`** (`overture-school-category-v1`):
- целями считаются «Школа-гимназия 3», «ГУ СШ № 8» и «Школа "Почемучка"»;
- 2 из 3 спорны: у СШ №8 конфликт местоположения (≈620 м от участка OSM «№8 мектеп-лицей»), «Почемучка» по OSM — детский сад / центр развития;
- «Гимназия №6», подтверждённая двумя слоями, исключена;
- школ №4, №7 и №31 из рамки и всех школ буфера нет.

Пакет K10 (`match-review.json`) это исправляет; использовать его вместо правила категорий.
