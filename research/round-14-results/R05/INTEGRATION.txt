2. R06 (предложения): API /api/civic/v2/proposals
────────────────────────────────────────────────────────────────────────────
2.1 Что модуль отправляет (POST /proposals, JSON) — поля CONTRACT §7 + поля 3D:
      kind            "square" | "playground" | "sports" | "stop" | "lighting"
      geometry        Point [lon,lat] (центр пятна) | LineString (освещение — ось участка улицы по OSM)
      status          "proposal"
      rotation_deg    0–359, по часовой от севера (для освещения 0)          ← хранить и отдавать обратно
      year            2027 (табличка «Проект · 2027»)
      district        "nura" и т. п. (по границам районов OSM) или null
      near_street     ближайшая улица OSM («улица Сыганак») или null
      target          освещение: {kind:"segment", id:"osm-w<way>-<n>", ids:[…рёбра участка], label_ru, label_kk};
                      объект во дворе: {kind:"area", id:"yard-<osm id>", label_ru, label_kk} (CONTRACT §4);
                      иначе null. Это связывает предложение с жалобами на ту же цель (R07/R09).
      demo            false (примеры из фикстуры — true)
    Ответ: созданное предложение целиком (с выданным id, votes_up:0, votes_down:0), код 201.
2.2 GET /proposals?bbox=w,s,e,n → {items:[…]} (или просто массив). Модуль отбрасывает неверные записи.
2.3 POST /proposals/{id}/vote {value: 1|-1, device_id} → предложение (или {proposal:…}); полезно поле my_vote.
    Один голос с устройства: повтор того же значения ничего не меняет, другое значение переносит голос.
    НУЖНО ДОБАВИТЬ (нет в CONTRACT §7): DELETE /proposals/{id} → 204 — кнопка «Удалить» и «Отменить» после
    «Поставить». Ошибки — в форме civic_error {error:{code, message}}; при лимите — code "limit".
2.4 Пока R06 не подключён: GET /proposals отвечает 404/405/501/503 → модуль честно работает на заглушке этого
    устройства (localStorage + 2 примера demo:true из data/proposals.fixture.json) и пишет в панели
    «Сохраняется только на этом устройстве…». 500 и обрыв запроса после подключения — ошибка с «Повторить».
    Клиент проверен на макете API по контракту: api_store_contract_roundtrip (GET, POST, vote, DELETE, GET).
2.5 Своя карточка R06 (одобрить/отклонить): mount({renderCard:false, onSelect(p){…}}) — модуль не рисует
    карточку, а отдаёт копию выбранного предложения. Без этого — встроенная карточка с «За/Против» и «Удалить».

4. R12 (точность карты)
────────────────────────────────────────────────────────────────────────────
4.1 Освещение строится по участку улицы между двумя щелчками: рёбра ОДНОЙ улицы графа
    osm-astana-walking-20260506 (id osm-w<way>-<n>, как у /targets), кратчайший путь, форма OSM без «руки».
    Сейчас источник — web/civic/build3d/data/nura-streets.json (фокус-область Нуры 71.375–71.420 × 51.115–51.140).
    Вне неё — сообщение «Освещение пока можно предложить только в районе Нура». Когда у R12 будет участок между
    двумя точками, передайте в mount свой источник: streets = { nearest(lngLat, maxM, name?) → {edge:{id,name},
    dist, lngLat, bearing} | null, section(a, b) → {ok, name, coords, length_m, edge_ids} | {ok:false, reason},
    bbox? } — интерфейс как у CivicBuild3DCore.StreetIndex.
4.2 Модуль карты: прошу слушать document "civic-build3d:tool" {active} так же, как "civic-editor:tool"
    (одна строка) — тогда R01 не нужен onToolChange.
4.3 Формат двора: модуль пишет target.id = "yard-<osm id>" (CONTRACT §4). Если R12 выберет другой вид
    (например, yard-way-<id>), сообщите — это одна строка в tests/civic/R05/build3d/make_fixtures.py.
4.4 Проверено: вершины и точки через 5 м участка освещения — не дальше 0.5 м от рёбер графа (допуск 5 м);
    пример-остановка — в 3–60 м от улицы; все координаты внутри Астаны; объект стоит в своих lon/lat при
    наклоне 0°/45°/60° и повороте −35°/120°/250° с ошибкой 0.000 px (anchor_precision_pitch_0_60_rotation).
