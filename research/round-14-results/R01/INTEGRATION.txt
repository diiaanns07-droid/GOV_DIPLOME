1. API v2: какие функции ищет шлюз ui/web_server.py
=====================================================================================================
Все маршруты /api/civic/v2/* (CONTRACT §7) уже есть в шлюзе. Для каждого шлюз ищет функцию по таблице ниже
(первый найденный модуль). Нет модуля или функции — ответ 503:
    {"error": "module_not_ready", "message": "...", "module": "ui.civic_ml_api", "role": "R04"}
Приложение при этом работает. Состояние всех маршрутов: GET /api/civic/v2/modules.

| Маршрут                          | Роль | Модуль (по порядку)                       | Функция и аргументы |
|----------------------------------|------|-------------------------------------------|---------------------|
| POST /classify {text}            | R04  | ui.civic_ml_api                           | classify(text) — ПОДКЛЮЧЕНО в B2 |
| POST /similar {text,point?,days?,target?} | R04 | ui.civic_ml_api                    | similar(text, point=None, days=None, target=None) — B2 |
| GET /targets?lon&lat&category    | R12  | engine.civic_geo                          | targets(lon, lat, category=None) — B2 |
| GET /street-segment, /street-snap, /objects-near, /yard, /geo/status
|                                  | R12  | engine.civic_geo.api                      | handle(path, query) — B2 (путь без /api/civic/v2) |
| /categories, /complaints, /complaints/mine|events|summary|place|{id}, /complaints/{id}/metoo|status|duplicate
|                                  | R09  | ui.civic_feedback.v2.integration          | make_service(db) -> handle(...) — ПОДКЛЮЧЕНО в B1 |
| GET /heat, /heat/meta, /heat/target | R07 | ui.civic_heat.api                       | handle_get(path, query) — ПОДКЛЮЧЕНО в B1 |
| GET /akim/summary?date&district  | R08  | ui.civic_akim.api                         | handle_get(path, query) — ПОДКЛЮЧЕНО в B1 |
| GET /proposals?bbox&district&status&device_id | R06 | ui.civic_store.v2               | list_proposals(...) — B2 |
| POST /proposals               [С]| R06  | то же                                     | create_proposal(body) — B2 |
| GET /proposals/summary?since     | R06  | то же                                     | proposals_summary(since) — B2 |
| GET /proposals/{id}?device_id    | R06  | то же                                     | get_proposal(proposal_id, device_id) — B2 |
| POST /proposals/{id}/vote        | R06  | то же                                     | vote_proposal(proposal_id, value, device_id) — B2 |
| POST /proposals/{id}/approve|reject|withdraw [С] | R06 | то же                           | decide_proposal(proposal_id, action, body) — B2 |
| GET /objects?bbox&district, /objects/lagging, /objects/{id} | R06 | то же               | list_objects, lagging_objects, get_object — B2 |
| PUT /objects/{id}/stage       [С]| R06  | то же                                     | set_object_stage(object_id, body) — B2 |
| GET /staff/objects/{id}/stage [С]| R06  | то же                                     | get_object_stage(object_id) — B2 |
| GET /forecast?month&district&k   | R13  | ui.civic_forecast                         | forecast_response(month, district, k) — B2 (синтетика) |

[С] — только сотрудник: шлюз сам проверяет сессию редактора R02 (cookie + заголовок X-CSRF-Token, как staff-маршруты
v1) и не вызывает функцию без неё (401/403).
Три вида подключения (класс V2Handler): «функция» по таблице (шлюз проверяет параметры), «handle_get» роли (R07, R08 —
роль сама разбирает запрос и отвечает (status, body)), «сервис» роли (R09 — отвечает целиком в конверте ok/data и сам
проверяет сотрудника по principal R02). Связку модулей делает CivicV2Gateway.wire() — см. §8.

Если у вас функция называется иначе или лежит в другом модуле — напишите в своём INTEGRATION.txt строку
«R01: маршрут → модуль.функция», R01 поправит одну строку таблицы V2_HANDLERS. Не нужно подстраивать имена под меня.

Что шлюз уже проверил ДО вызова функции (ответ 400 {"error":"bad_request","field":...,"message":...}):
- text: непустая строка ≤ 5000 символов (classify, similar, complaints).
- point: [lon, lat] внутри Астаны (70.9–71.9, 50.9–51.4); lon/lat — так же; bbox — 4 числа, min < max, пересекается с Астаной.
  bbox приходит в функцию кортежем (minLon, minLat, maxLon, maxLat).
- category: id из research/round-14/categories_v2.json.
- days: целое 1..365; zoom: 0..24; date: ГГГГ-ММ-ДД; district: латиница [a-z0-9_-] (id района, напр. "nura").
- vote: value ∈ {1, -1}, device_id — строка 8–128 символов [A-Za-z0-9._:-].
- {id} в пути: правило v1 ^[A-Za-z0-9][A-Za-z0-9._:-]{0,95}$.
- Тело — JSON-объект ≤ 64 КБ; Host — этот сервер; POST/PUT с чужим Origin отклоняются.
Остальные поля body (статус, этап, вид предложения…) проверяет сама функция.

Что функция возвращает:
    return {...}                 -> 200, этот объект уходит как есть (без обёртки ok/data)
    return (201, {...})          -> свой код
    raise ValueError("текст")    -> 400 bad_request (текст пишите по-русски, он может попасть пользователю)
    raise KeyError / LookupError -> 404 not_found
    raise PermissionError        -> 403 forbidden
    исключение с атрибутами status (400..599) и code (str), message (необязательно) -> этот код
    любое другое исключение      -> 500 internal; подробности только в журнале сервера
Необязательные именованные параметры: если функция объявляет context=None — получит заголовки/cookies/адрес клиента;
principal=None — {"username", "role"} сотрудника (для [С]) или None. Не объявили — не передаются.

Функции вызываются из потоков сервера одновременно: ленивую загрузку модели/данных защищайте блокировкой.
Без сети. Модель > 50 МБ — не в Git (см. LOCAL-задачи).

Проверка без браузера:
    python -m pytest -q tests/civic/R01/test_r01_api_v2.py
    python -c "from ui.web_server import CivicV2Gateway; import json; print(json.dumps(CivicV2Gateway().modules(), ensure_ascii=False, indent=1))"

2. Фронтенд: как модуль экрана подключается к оболочке
=====================================================================================================
Оболочка (web/civic/shell/) — шапка Birge, ҚАЗ/РУС, «Акимат / Житель», разделы «Карта» и «Картина дня».
Модули экранов (R05 3D, R06 предложения, R07 тепловая карта, R08 картина дня, R09 жалоба) — свои файлы в своих
папках. Шлюз раздаёт ТОЛЬКО файлы из белого списка CIVIC_ASSETS в ui/web_server.py: напишите в INTEGRATION.txt
точный список своих .js/.css/.json, которые должен отдавать сервер, и порядок <script> в web/index.html.
Точку монтирования опишите в духе раунда 13: window.<Имя>.mount({root, api, lang, mode, map}) -> {update, destroy}.
- api — клиент оболочки: api.v2(method, path, body) -> Promise<JSON>; ошибки — объект с полями status, error, message.
- Язык: модуль сам подписывается на BirgeI18n.onChange (R11) и перерисовывается; весь текст — через ключи R11.
- mode: "akimat" | "resident" (переключатель в шапке); событие document "birge:mode" {detail:{mode}}.
- map: экземпляр MapLibre (может быть null, пока карта грузится: передаётся функцией map(), как у R04 в раунде 13).
