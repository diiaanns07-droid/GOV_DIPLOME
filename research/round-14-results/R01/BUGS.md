## I-01 · R07 · подписи объектов OSM в сборке

Где: `ui/civic_heat/targets.py` @ 306074b, `TargetResolver._resolve`. Порядок: реестр (в т. ч. `data/civic/astana/geo/objects.json`
и `yards.json` R12) → `engine.civic_geo.target_geometry` → свои объекты OSM (LOCAL-1). В ветке R07 файлов R12 нет, поэтому
работает третий шаг с хорошими подписями. В сборке R12 есть — срабатывает первый шаг: `label_ru` = голое `name_ru`,
`label_kk` = `name_kk` (у R12 почти всегда `null`) → общее слово вида «Нысан» / «Объект» / «Двор или квартал».

Воспроизвести (сборка R01):
    python3 -m pytest -q tests/civic/R07/test_r07_heat.py::test_resolver_finds_any_real_osm_object_by_contract_id
    # AssertionError: 'Хан Шатыр' == 'Остановка «Хан Шатыр»'
Масштаб в демо (CIVIC_DEMO=1, 30 дней): 13 из 53 целей с общим казахским словом; на скриншоте B1 горячее место
«Двор или квартал» без имени. Свой слой R07 даёт правильно: «Остановка «Республиканский диагностический центр»» /
«…аялдамасы», «Детская площадка у пр. Туран» / «Тұран даңғылы маңындағы балалар алаңы».

Предложение (одна проверка в начале `_resolve`, до реестра): для id `osm-*` и дворов `yard-*` сначала свой слой OSM,
реестр — только если там нет объекта:

    if self._use_osm_objects and (tid.startswith("osm-") or tid.startswith("yard-")):
        real = self._osm_object(tid)
        if real:
            return real

(Если в демо-фикстуре `targets_demo.json` есть выверенные подписи для `osm-*` — оставить их главнее: проверять
`tid in self._registry and self._registry[tid].get("source") != "r12"` или грузить файлы R12 с пометкой источника.)
Тест R07 `test_resolver_finds_any_real_osm_object_by_contract_id` уже ловит это в сборке — после правки он зелёный.

## I-03 · R07 · тест «примерного места» R09 по старой сетке

Тест считает id ячейки формулой R09 с углом 70.9/50.8. В сборке R09 @ fa49fc9 перешёл на общую сетку (71.0/50.8,
`ui/civic_feedback/v2/record.py`), и `r09_cell_polygon` R07 честно берёт функцию R09 — поэтому id «старой» формулы
рисуется в 7 км. Поведение приложения верное: настоящая ячейка R09 для точки в Нуре (`record.cell_id(71.4045, 51.1285)`
= `cell-188-242`) содержит точку, `approximate: true`, якорь в 59 м (проверка R01, и в браузере r14_b1 «map accuracy» PASS).
Предложение: в тесте брать id из `ui.civic_feedback.v2.record.cell_id`, если модуль есть (как уже делает
`r09_cell_polygon`), а формулу 70.9 оставить только для ветки без R09.
