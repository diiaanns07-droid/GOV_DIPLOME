3. R01 + R07 · переход «горячее место → цель на карте»
-----------------------------------------------------
  Клик по строке «Горячие места» сначала отправляет отменяемое событие на document:
      "birge:open-target"  detail = {target: {kind, id, label_ru, label_kk}, days: 7, from: "akim"}
  Если оболочка открыла цель у себя — event.preventDefault(), перехода не будет.
  Иначе браузер идёт по ссылке mapHref, по умолчанию "/#target=<kind>:<id>&days=7"
  (по образцу существующего "#object=<id>" в shell.js). Нужно, чтобы карта R07/оболочка R01 понимали
  этот адрес: открыть карточку цели, период 7 дней (тогда число в карточке = числу в списке).
  Готовый ответ для карточки уже есть у R07: GET /api/civic/v2/heat/target?kind=…&id=…&days=7.

4. R07 · ui/civic_heat — просьба (минимальный patch)
---------------------------------------------------
  «Картина дня» берёт записи жалоб у того же HeatService, что отвечает карте, — поэтому числа совпадают.
  Сейчас для этого используются внутренние _records и _generation. Прошу публичный метод:

    --- a/ui/civic_heat/service.py
    +++ b/ui/civic_heat/service.py
    @@ class HeatService:
    +    def records(self, since=None):
    +        """Записи жалоб v2 — те же, по которым считается карта (для «Картины дня» R08)."""
    +        return self._records(since)
    +
    +    @property
    +    def generation(self) -> int:
    +        """Растёт при каждом invalidate(): по нему R08 сбрасывает свой кэш."""
    +        return self._generation

  Код R08 уже сначала ищет публичный records(), а _records — запасной путь (ui/civic_akim/sources.py).
  Если R07 поменяет порядок/фильтры в heat() — тест tests/civic/R08/test_r08_heat_match.py это поймает.
