R06 · раунд 14 · команды и что теперь можно сделать
Проверено: Linux (облачный контейнер), Python 3.13, SQLite 3.45, Node 22, Chromium (Playwright). SHA — в DELIVERY.json.
Все базы — временные, вне репозитория. Пользовательская .runtime/*.sqlite3 не открывалась.

1. Тесты (Python)
   python3 -m pip install pytest
   python3 -m pytest -q tests/civic/R06            # всё R06: старые тесты жалоб v1 + store (раунд 13) + round14
   python3 -m pytest -q tests/civic/R06/round14    # этапы, миграция, предложения, голоса, демо
   Через настоящий шлюз v2 R01 (его ветка claude/sharp-dijkstra-0t87gl):
   git show origin/claude/sharp-dijkstra-0t87gl:ui/web_server.py > /tmp/r01_web_server.py
   R06_R01_WEB_SERVER=/tmp/r01_web_server.py python3 -m pytest -q tests/civic/R06/round14/test_r06r14_gateway_r01.py
   (без переменной и без шлюза в рабочем дереве — SKIP, а не PASS).

2. Демо-данные в базе (synthetic/demo: «Пример» в интерфейсе)
   T=$(mktemp -d)
   python3 -m ui.civic_store --db $T/c.sqlite3 init
   python3 -m ui.civic_store --db $T/c.sqlite3 seed-r14-demo     # seed-demo R02 (если пусто) + этапы + 5 проектов в Нуре
   python3 -m ui.civic_store --db $T/c.sqlite3 seed-r14-demo     # повтор: всё "kept", ничего не дублируется
   Освещение в демо идёт по настоящим рёбрам OSM улицы Ильяса Омарова (osm-w1482578141-0…8), не «от руки».

3. Стенд карточек на настоящем HTTP + браузерная проверка (375/1366, ru/kk, голос, акимат, этап, нет связи)
   python3 tests/civic/R06/round14/serve_r14.py --port 8616 --age-days 16 > /tmp/stand.json &
   #   --age-days 16: демо засеяно «16 дней назад» → видно «Не обновлялось 16 дней»;
   #   --kit-dir <корень другой ветки>: взять ui-kit/i18n R11 из выгрузки его ветки (git archive), иначе из этого дерева.
   NODE_PATH="$(npm root -g)" node tests/civic/R06/round14/browser_r14.cjs /tmp/stand.json <папка-скриншотов>
   # Каждый прогон одобряет один проект и меняет этап — для повторного прогона запускайте СВЕЖИЙ стенд.
   Открыть руками: http://127.0.0.1:8616/civic/proposals/demo.html  (?lang=kk, ?role=akimat — после входа сотрудника;
   логин/пароль сотрудника стенд печатает первой строкой stdout; пароль случайный при каждом запуске).

4. Python-функции для соседей (без HTTP)
   from ui.civic_store import CivicService, CivicV2
   v2 = CivicV2(CivicService("<путь к базе>"))
   v2.lagging_objects("nura")           # R08: отстающие и устаревшие объекты района
   v2.proposals_summary(since="2026-10-11")
   v2.handle(method, "/api/civic/v2/…", query, body, context)    # конверт {ok, data} как у v1
   Для шлюза R01 — функции уровня модуля ui.civic_store.v2 (после bind(service)), см. INTEGRATION.txt §1.

Что теперь может пользователь
- Житель: открыть карточку проекта акимата («Проект · 2027»), нажать «За» или «Против». Повторное нажатие не
  удваивает счёт, другая кнопка меняет голос, после перезагрузки страницы голос на месте («Вы проголосовали «против»»).
- Акимат: «Одобрить» / «Отклонить» проект — голосование закрывается, статус меняется словом и цветом.
- Все: в карточке объекта — полоса из 6 этапов с текущим, «Отстаёт на 23 дня» (цвет + слова), «Не обновлялось 16 дней»,
  плановый срок и прогноз; в обеих локалях, на 375 и 1366 px.
- Сотрудник (после patch R12): в редакторе объекта — блок «Этап работ»: этап, срок, прогноз, «Сохранить этап»;
  при чужой правке — понятное сообщение и свежая версия, ничего не теряется молча.
- Аким (через R08): список отстающих и давно не обновлявшихся объектов по району.
