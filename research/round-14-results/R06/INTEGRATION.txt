tests/civic/R06/round14/r05_client_r14.cjs запускает ВАШ createApiStore против настоящего API R06 (стенд serve_r14.py),
в двух видах ответа: конверт R06 и «голый» JSON шлюза R01. PASS: list(bbox), create без входа → 401, create сотрудником
(CSRF клиент берёт сам из /api/civic/v1/session), vote → my_vote, list с device_id → «мой голос», remove через
withdraw, restore, remove с запасным DELETE (когда withdraw отвечает 404).
POST /api/civic/v2/proposals принимает:
    {kind, geometry, title_ru?, title_kk?, rotation_deg?, planned_year? | year?, demo?}            — как раньше
    + status?: "proposal" (другое → 422), near_street?: строка ≤ 200, target?: {kind: segment|area|object,
      id, ids?, label_ru?, label_kk?} — хранятся и отдаются обратно (миграция 7)
    + near_street_kk?: строка ≤ 200 (миграция 8, UX_REVIEW R11 ночь п. 5) — казахское название улицы рядом; храним
      и отдаём. В ҚАЗ показывайте «Жанында: {near_street_kk}», а если его нет — без улицы, не русское название.
      Демо-предложения R06 приходят с near_street и near_street_kk (ближайшая улица по графу OSM, ≤ 100 м).
    + id?: если это id СНЯТОГО предложения того же вида — оно возвращается с теми же голосами (restored: true)
    district считает сервер по полигонам OSM (district из тела игнорируется). Служебные поля (votes_up, my_vote,
    created_at, …) игнорируются и перечислены в ignored_fields — копию предложения целиком можно слать как есть.
    Ответ 201 {item, proposal, restored, ignored_fields}; vote → {item, proposal, changed, previous}.
    Лимит: 20 открытых предложений на район → 409 {code: "limit"}.
Предложение (необязательно): в restore() добавить id: p.id в тело — тогда «Отменить» вернёт ТО ЖЕ предложение с голосами,
а не новое без голосов. Только когда R01 возьмёт R06 ≥ code_sha этой поставки (7031afa отвечает 422 на поле id).
