R10 · раунд 14 · приёмка — как запустить проверки и что они дают

Ветка R10: claude/r14-R10. Свои пути: tests/e2e/, tests/civic/R10/, research/round-14-results/R10/.
Нужно: Python 3.11+ (с pytest), Node 20+, Playwright + Chromium (глобально: NODE_PATH="$(npm root -g)";
или npm i playwright в папке тестов). На Windows задайте PYTHON=путь к .venv\Scripts\python.exe сборки.

=====================================================================================================
1. Всё сразу на сборке R01 (B1 / B2 / FINAL) — одна команда, 10–15 минут
=====================================================================================================
    node tests/e2e/run_acceptance.cjs --root <папка сборки> --out <папка отчёта> --label B1
  Сервер сборки поднимается как run-city.bat (CIVIC_DEMO=1 — синтетический набор тепловой карты R07; флаг --no-demo —
  без него). Сам поднимает сервер сборки на свободном порту с временной базой (init → seed-demo → seed-r14-demo, если есть →
  сотрудник r10-operator), прогоняет точность карты, сценарий демо и UX по экранам, гасит сервер, удаляет базу.
  Итог: <папка отчёта>/SUMMARY.md (+ e2e/RESULT.md, ux/UX_RESULT.md, accuracy.json, кадры .jpg, логи).
  Сборку удобно держать отдельным worktree:  git worktree add --detach ../b1 <SHA сборки из STATUS.md R01>

=====================================================================================================
2. По частям
=====================================================================================================
Точность карты (CONTRACT §8), без браузера, ~5 с:
    python3 tests/civic/R10/accuracy.py --root <сборка> [--json out.json]
    R10_ROOT=<сборка> python3 -m pytest -q tests/civic/R10          # то же как тесты + самопроверка геометрии
  Проверяет: участки = рёбра графа OSM (≤ 5 м в обе стороны, с уплотнением точек), остановки ≤ 60 м от улицы и не ж/д
  платформы, объекты = точки OSM LOCAL-1 (≤ 1 м), id целей по §4, всё внутри полигонов районов Астаны, демо-линии
  либо на графе, либо «примерное место». Наборы, которых нет в сборке, — NOT_RUN.

Сценарий демо (CONTRACT §0, 6 шагов), API + интерфейс, 1366/375 × ru/kk. Интерфейс — как ведущий демо: жалоба с выбором
остановки и «Я тоже»; тепловая карта у акимата; «Картина дня»; вход «Для сотрудников» → «Сквер» → «Поставить» →
житель «За» → «Удалить»; карточка остановки «Взять в работу» → «Отметить исправленным» → «Мои обращения» жителя:
    NODE_PATH="$(npm root -g)" node tests/e2e/demo_flow.cjs --root <сборка> --out <папка>
    # уже запущенный сервер:  --url http://127.0.0.1:8611/ --user <сотрудник> --pass <пароль>
    # другая остановка:       --stop "71.4225746,51.1097974,osm-node-10677613224,Ботанический сад"
    # часть экранов:          --sizes 1366x768 --langs kk

UX-чек-лист по экранам (UX_BRIEF «Проверка каждого экрана»):
    NODE_PATH="$(npm root -g)" node tests/e2e/ux_screens.cjs --screens tests/e2e/screens_build.json --base http://127.0.0.1:8611/ --out <папка>
  Для стендов ролей — свой screens.json (пример: research/round-14-results/R10/ux/pre-b1/screens.json).
  В screens.json можно задать "storage": {"birge.mode": "resident"} — что записать в localStorage до загрузки (вид экрана).

Новые пункты волн (POLISH_WAVE.md, POLISH_WAVE_2.md) — написаны до поставок; пункт без кода роли — ЖДЁТ, не FAIL:
    NODE_PATH="$(npm root -g)" node tests/e2e/wave_checks.cjs --root <сборка> --out <папка> [--only W2-1] [--force]
  Подробно — research/round-14-results/R10/wave/README.md.

Регресс «карта и сценарий не стали хуже» (POLISH_WAVE_2 правило 7) — эталон research/round-14-results/R10/baseline_8e67c65/:
    NODE_PATH="$(npm root -g)" node tests/e2e/demo_flow.cjs    --root <сборка> --out <папка>/e2e
    NODE_PATH="$(npm root -g)" node tests/e2e/map_baseline.cjs --root <сборка> --out <папка>/map --repeat 3
    NODE_PATH="$(npm root -g)" node tests/e2e/compare_baseline.cjs --base research/round-14-results/R10/baseline_8e67c65 \
         --new <папка> [--control <те же два прогона на 8e67c65 на этой машине>]
  Или всё сразу: run_acceptance.cjs ... --baseline research/round-14-results/R10/baseline_8e67c65 [--control <папка>].
  Время сравнимо только на одной машине: без --control время из другой среды — «СМОТРЕТЬ», не FAIL. Порядок — README эталона.

FINAL-3 против эталона (владелец, 12 окт): «сценарий не сломан, все тексты на месте, ничего не стало меньше 13 px,
кнопки ≥ 44 px, контраст в норме» — demo_flow с --audit (замер интерфейса на каждом кадре; время замера вычтено):
    NODE_PATH="$(npm root -g)" node tests/e2e/demo_flow.cjs --root <FINAL-3> --audit --out <папка>/e2e
  затем map_baseline и compare_baseline, как выше. В начале COMPARE.md — таблица пяти критериев (да / НЕТ / смотреть);
  эталон интерфейса — baseline_8e67c65/audit/RESULT.json (тот же 8e67c65, тесты 552a388). run_acceptance с --baseline
  добавляет --audit сам. Пропавшие строки текста — «СМОТРЕТЬ» со списком по кадру (часть — намеренные изменения волны 2).

Стекло «Liquid Glass» (R11 GLASS.md; пока стекла нет в сборке — ЖДЁТ):
    NODE_PATH="$(npm root -g)" node tests/e2e/glass_check.cjs --root <сборка> --out <папка> [--sizes 1366x768,1024x768,375x812]
         [--langs ru,kk] [--control <сборка до стекла>] [--fps-only | --no-fps]
  G-1 где стекло (не на значках, не в формах) · G-2 запасной вид (CSS, «уменьшить прозрачность», html.bk-glass-off) ·
  G-3 контраст текста на стекле по пикселям над фонами карты · G-4 плавность (к/с): стекло против bk-glass-off на той же
  сборке. Плавность — на ноутбуке (в облаке программный WebGL, 3–7 к/с — только ИНФО). Подробно — research/round-14-results/R10/glass/README.md.

=====================================================================================================
3. Что можно сделать с результатами
=====================================================================================================
- R01 и роли: открыть research/round-14-results/R10/BUGS.md — у каждого дефекта владелец, шаги, ожидалось/получилось.
- Перед B1/B2/FINAL: прогнать п.1 на SHA сборки → ACCEPTANCE_<B1|B2|FINAL>.md по образцу ACCEPTANCE_B2.md.
- После 15 октября: Codex повторяет приёмку FINAL по research/round-14-results/R10/CODEX_ACCEPTANCE_PROMPT.txt.

Ограничения облачной проверки: нет интернета (подложка OpenFreeMap не грузится — упрощённый фон), программный WebGL
(плавность 3D не измерить), казахский проверяется на полноту, а не на качество (это делает владелец по KK_REVIEW R11).
