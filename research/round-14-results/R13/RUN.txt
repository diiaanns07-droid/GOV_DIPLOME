R13 · раунд 14 · команды и что теперь можно сделать
Проверено: Linux (облачный контейнер), Python 3.13.16, scikit-learn 1.9.1, numpy 2.5.3. Сети не нужно.
Без scikit-learn всё работает на запасной модели (fallback) — так же отвечает API и строится backtest.

1. Зависимости (только для бустинга)
   python3 -m pip install scikit-learn pytest      # на ноутбуке владельца уже есть (LOCAL-3, venv birge-ml)

2. Тесты
   python3 -m pytest -q tests/civic/R13
   Через шлюз R01 (его ветка claude/sharp-dijkstra-0t87gl), patch накладывается в тесте сам:
   git show origin/claude/sharp-dijkstra-0t87gl:ui/web_server.py > /tmp/r01_web_server.py
   R13_R01_WEB_SERVER=/tmp/r01_web_server.py python3 -m pytest -q tests/civic/R13/test_r13_gateway_r01.py

3. Конвейер
   python3 -m ml.civic_forecast history                       # сводка синтетической истории (JSON)
   python3 -m ml.civic_forecast backtest --seeds 2026,2027,2028   # ~2–4 мин → ml/civic_forecast/RESULTS.md, results.json
   python3 -m ml.civic_forecast report                        # перестроить RESULTS.md из results.json
   python3 -m ml.civic_forecast build-cache                   # ~6 с на месяц → ui/civic_forecast/data/forecast_cache.json
   python3 -m ml.civic_forecast build-targets --geo-dir data/civic/astana/geo   # после обновления данных R12
   python3 -m ml.civic_forecast weather-fixture               # пересоздать синтетическую погоду (если нет LOCAL-9)

4. Прогноз из Python (для R01 и R08)
   python3 -c "from ui.civic_forecast import forecast; import json; print(json.dumps(forecast('2026-11','nura',5), ensure_ascii=False, indent=1))"
   python3 -c "from ui.civic_forecast import attention_next_month; from datetime import date; print(attention_next_month(None, 5, date(2026,10,11)))"

5. «Вопрос акиму» (волна 2 п. 9) — в сборке R01 с patch (INTEGRATION §8.1)
   python3 -m pytest -q tests/civic/R13/qa                       # 43 (в ветке R13 без шлюза R01 — 41 + 2 SKIP)
   BIRGE_REPO=<сборка R01> node tests/civic/R13/qa/qa_browser.cjs <папка>   # 81 проверка, снимки 375/1366 × ru/kk
   QA_GLASS=1 BIRGE_REPO=<сборка R01> node tests/civic/R13/qa/qa_browser.cjs <папка>  # + стекло листа и контраст (91)
   Демо: run-city.bat (CIVIC_DEMO=1) — 12 вопросов «Пример» появятся сами; вход сотрудника — как для «Обращений»
   (python -m ui.civic_store create-editor <логин>). Отдельная страница без оболочки: /civic/qa/ (?role=akimat).

6. «Пульс района» — проверка метода R08 (волна 2 п. 8), ~50 с, нужен модуль R08 (сборка R01):
   python3 -m ml.civic_forecast.pulse_check --trials 200 [--p 0.01]   # → ml/civic_forecast/results_pulse.json
   Итог и выводы — research/round-14-results/R13/PULSE_METHOD.md; правка для R08 — patches/r08_pulse_not_by_chance.patch.

Что теперь может пользователь (после подключения R01/R08)
- Житель: «Ещё → Вопрос акиму» — задать вопрос (после проверки его увидят все), поддержать чужие вопросы
  (одно устройство — один голос), прочитать ответы акима. Правило «раз в неделю аким отвечает на 5 самых поддержанных»
  видно всегда.
- Акимат: «Ещё → Вопросы жителей» — проверить новые (опубликовать или отклонить с причиной; подсказка, если в тексте
  телефон или ИИН), «Топ-5 недели» с формой ответа на ru и/или kk, «На этой неделе отвечено: N из 5».
- Аким в «Картине дня» (R08, с patch R13): «Пульс» без шума обычной недели — тревога, только если такой всплеск
  не бывает «просто так».
- (прогноз, если R08 выведет блок) Аким в «Картине дня» видит 5–30 мест, где в следующем месяце вероятны жалобы, с причинами простыми словами:
  «Снег и гололёд: 6 жалоб в ноябре прошлого года», «Проблема держится 5 месяцев подряд», «В ноябре обычно снег: 24 см».
  Фильтр по району; клик — то же место на карте. Всё с пометкой «прототип на синтетике».
- Для прошлого месяца видно, подтвердился ли прогноз (на синтетике): например, 2026-10 — 4 из 10.
- Для диплома и Gton: методика проверки «как будто в прошлом» с честной таблицей precision@10/20/30 против простых прогнозов.
