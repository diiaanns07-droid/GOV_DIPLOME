R01 (интегратор)
=====================================================================================================
1. Перенести пути R04 (path-scoped, без merge):
     git fetch origin claude/r14-R04
     git checkout <code_sha из DELIVERY.json> -- ml/civic_dedup ui/civic_ml_api tests/civic/R04/round14
   Зависимости в сборке (у R01 уже есть или придут от ролей): ml/civic_classifier/ (v1), ml/civic_classifier_v2/ (R03),
   research/round-14/categories_v2.json. ml/datasets/ (R02) нужен только для tune/evaluate, не для сервера.

2. Шлюз API v2: имена уже совпадают с V2_HANDLERS — ничего менять не нужно:
     POST /classify -> ui.civic_ml_api.classify(text)
     POST /similar  -> ui.civic_ml_api.similar(text, point=None, days=None)
   Ошибки — по договору R01 §1: ValueError -> 400; MLServiceUnavailable (status=503, code, message) -> 503.
   Функции потокобезопасны (ленивая загрузка под блокировкой; проверено 32 потоками с холодного старта).

3. Patch (3 строки, проверен на ui/web_server.py @ 2eaeacb): передать в similar необязательную цель жалобы,
   иначе условие «та же цель» работает только через точку (≤ 200 м), а участок улицы бывает длиннее.
   Файл: research/round-14-results/R04/r01_similar_target.patch
     в CivicV2Gateway.arguments, ветка key == "similar", перед return args:
         if body.get("target") is not None:
             # R04: «та же цель» ({kind, id} или id) — проверяет сама ui.civic_ml_api.similar (ValueError -> 400)
             args["target"] = body["target"]
   Проверка после патча: target чужого вида -> 400 «target: нужен объект {kind, id} или id цели.»

4. Подключение хранилища жалоб при старте сервера — там, где создаётся ComplaintStore R09
   (ui.civic_feedback.v2.integration.make_service(db_path) -> сервис с атрибутом .store):
         import ui.civic_ml_api as civic_ml
         civic_ml.connect_store(complaints_service)   # можно передать и сам ComplaintStore
         civic_ml.warmup()                            # фоновый поток: загрузка моделей + прогрев кэша
   connect_store подписывается на события R09 (store.subscribe): каждая новая жалоба заранее считается в фоне.
   Без connect_store /similar отвечает 503 source_not_connected — форма R09 работает без «Я тоже» (так задумано).
   Повторный connect_store (перезапуск сервиса) снимает старую подписку.

5. Диагностика (для GET /api/civic/v2/modules или журнала старта, по желанию):
         civic_ml.status() -> {"classify": {"model_version", "models": {v2, v1, kw, v1_heuristic}},
                               "similar": {"method", "version", "threshold", "text_only_threshold", "radius_m",
                                           "notes", "source"}}
   Пути в причинах — относительно репозитория (абсолютные пути сервера наружу не уходят).

6. Тесты: python -m pytest -q tests/civic/R04/round14   (97 тестов; без torch; e5-тесты на крошечной ONNX-модели
   пропускаются, если нет onnx/tokenizers).
   ВАЖНО для общей сборки: в tests/civic/R04/round14 НАРОЧНО нет conftest.py. Тесты R03 делают
   `from conftest import needs_ml`; все conftest.py без пакета импортируются под одним именем «conftest», и любой
   другой conftest.py, собранный в том же прогоне раньше, подменит модуль R03 (ImportError при сборе тестов).
   Совместный прогон tests/civic/R03/round14 + tests/civic/R04/round14: 137 passed, 6 skipped.

7. Зависимости рантайма: запасные пути (v1 + словарь, поиск n-грамм) — только стандартная библиотека.
   Модель v2 R03 и e5 — numpy + onnxruntime + tokenizers в Python сервера; нет их — тихий переход на запасной путь
   (status() покажет причину). .gitignore: ml/civic_dedup/.gitignore уже исключает artifacts/ (веса e5).

=====================================================================================================
R09 (жалоба жителя) — как пользоваться ответами
=====================================================================================================
POST /classify {text} ->
  {category, score, needs_review, model_version, top3:[{category, score}],     <- контракт §7
   suggest, source, score_kind}                                                <- сверх контракта
  - suggest = true: можно сразу выделить чип «Похоже на: …» (житель подтверждает или меняет).
    Точность при suggest на синтетике: 0.94 (val) / 0.83 (test).
  - needs_review — для сотрудника (подсказка не проверена на людях): сейчас всегда true. Для чипа жителя смотрите
    suggest, а не needs_review: иначе подсказка не покажется никогда.
  - Пустой/бессодержательный текст -> category "other", top3 [], suggest false.
POST /similar {text, point, days: 14, target?} ->
  {matches:[{complaint_id, score, target, metoo, people, category, created_at, status, distance_m, same_target}],
   people_total, method, model_version, threshold, days, radius_m}
  - ВСЕ matches уже прошли порог R04. Не фильтруйте повторно по score ≥ 0.6: шкала зависит от режима
    (в режиме «понятия» дубль начинается с 0.18). Берите matches[0] — список уже упорядочен:
    самое похожее, при равенстве та же цель, ближе, больше людей.
  - people = 1 + metoo (автор + «Я тоже»); people_total — сумма по matches. Для «Об этом уже сообщили N человек»
    берите people у matches[0] (или GET /complaints/{id}, как сейчас).
  - Закрытые (fixed, rejected) и помеченные дублем жалобы не возвращаются. Текстов чужих жалоб в ответе нет.
  - Без point и target -> matches [] и note "no_location". Хранилище не подключено -> 503 source_not_connected.
  - target передавайте ту, что житель выбрал на шаге ② (после патча R01 п. 3 она дойдёт до R04).

=====================================================================================================
R03 (модель v2)
=====================================================================================================
- R04 вызывает ml.civic_classifier_v2.predict.get_default() (artifacts/onnx, затем artifacts/final) и берёт
  атрибуты model_version и threshold (threshold — для suggest). Модель с метками не из categories_v2.json R04
  не примет (ответ с неизвестной категорией -> запасной путь). Три сбоя подряд при запросах — v2 выключается
  до перезапуска сервера (не тормозить каждый запрос).
- Ваши тесты используют `from conftest import needs_ml` — см. R01 п. 6: в общем прогоне это ломается от любого
  чужого conftest.py. Надёжнее — модуль с уникальным именем (как tests/civic/R04/round14/r04_helpers.py).

Что будет: если e5 на dev даёт точность ≥ 0.90 и полноту выше n-грамм, tune поставит e5 первым в prefer, и сервер
(после перезапуска) сам возьмёт e5; иначе e5 будет выключен (threshold null) — это нормальный честный исход.
Если export_e5 пишет FAIL (не совпали токены или косинус < порога) — e5 не включать, прислать вывод.
Сервер с e5 должен запускаться тем Python, где есть numpy/onnxruntime/tokenizers; иначе — запасной путь.
