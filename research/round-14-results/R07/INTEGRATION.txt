1б) Маршрут GET в do_GET, ПЕРЕД строкой «if path == CIVIC_PREFIX or path.startswith(CIVIC_PREFIX + "/"):»
    (или внутри вашего общего шлюза v2, если он уже есть — функция та же):

+        if path == "/api/civic/v2/heat" or path.startswith("/api/civic/v2/heat/"):
+            from ui.civic_heat.api import handle_get as civic_heat_get   # R07: ответ строго по CONTRACT §7

    handle_get никогда не бросает исключение: неверные параметры → 400 {"error":"bad_request","field":…},
    сбой источника жалоб → 500 {"error":"heat_failed"}; сервер не падает.
    Если шлюз заворачивает ответ в {"ok": true, "data": …}, интерфейс это понимает.
    Маршруты:  GET /api/civic/v2/heat?bbox&days&category&district&zoom
               GET /api/civic/v2/heat/meta            (категории, легенда, районы — из categories_v2.json и geofence.json)
               GET /api/civic/v2/heat/target?kind&id&days

1в) Источник жалоб. Без подключения модуль показывает ДЕМО-набор (synthetic, demo: true) и пишет об этом в ответе ("demo": true).
    Когда у R09 есть функция списка записей v2, при старте сервера:

        civic_heat.configure(source=lambda since: <модуль R09>.list(bbox=None, since=since, category=None))
    Автоматически подхватываются ui.civic_feedback.list_complaints_v2 или ui.civic_feedback.list_v2 (если R09 так назовёт).

1г) Оболочка (web/civic/shell/ или web/interface.js):
    <link rel="stylesheet" href="/civic/heat/heat.css">  <script src="/civic/heat/heat.js"></script>
    const heat = window.CivicHeat.mount({
      root: <элемент правой панели / шторки>,   // модуль рисует внутрь фильтры, легенду, «Горячие места», карточку
      map,                                     // экземпляр MapLibre (window.map у web/map.js)
      role: "akimat" | "resident",             // переключатель «Акимат / Житель»

    Модуль сам НЕ двигает карту, пока пользователь не нажал строку в списке (UX_BRIEF, правило 8).
    Выбор цели генерирует событие "birge:heat-select" {detail:{target}} (всплывает от root) — для соседних модулей.
    Демо-страница модуля (web/civic/heat/demo.html) и fixtures/basemap-*.geojson в общую сборку не нужны.

2. R09 · жалобы v2 — сброс кэша и событие для пульса
======================================================================
2а) Сервер: после create / metoo / set_status вызвать   import ui.civic_heat; ui.civic_heat.invalidate()
    (иначе новая жалоба появится на карте через ≤ 60 с — кэш живёт минуту).
2б) Браузер: после отправки жалобы или «Я тоже»
        window.dispatchEvent(new CustomEvent("birge:complaint", { detail: { type: "created" | "metoo" | "status", complaint_id, target: { kind, id } } }));
    Тепловая карта перезагрузит данные, плавно перекрасит цель (~0.8 с) и покажет пульс-кольцо (для status — без пульса).
2в) Кнопки карточки цели вызывают ваш API (CONTRACT §7):
        «Взять в работу»          → POST /api/civic/v2/complaints/{id}/status {"status":"in_progress"} для каждого id из item.open_ids
        «Отметить исправленным»   → то же с {"status":"fixed"}
        «Я тоже» (житель)         → POST /api/civic/v2/complaints/{open_ids[0]}/metoo {"device_id": localStorage["birge.device_id"]}
    Ключ устройства "birge.device_id" — предлагаю этот же в форме жалобы (одно «Я тоже» с устройства).
    Доступ сотрудника (сессия/CSRF) — на стороне шлюза R01; модуль отправляет обычный JSON с того же origin.
2г) Правила веса, которые зависят от ваших полей: человек = жалоба + каждое «Я тоже» (metoo); статусы fixed и rejected
    в вес не идут; всё, что пришло ДО последнего статуса fixed у цели, считается закрытым. duplicate_of на вес не влияет
    (дубль — это отдельный человек; «Я тоже» дублей не создаёт — так в CONTRACT).

4. R12 · цели и геометрия
======================================================================
    Модуль берёт форму цели по id (ui/civic_heat/targets.py), по порядку:
      а) реестр: ui/civic_heat/fixtures/targets_demo.json и ваши data/civic/astana/geo/objects.json | yards.json | targets.json
         (форматы {"targets": {id: {geometry, label_ru, label_kk}}} или {"items": [{id, geometry | coordinates | lon/lat, name_ru, name_kk}]});
      б) если в engine.civic_geo есть функция target_geometry({"kind","id"}) → {"geometry","label_ru","label_kk","approximate"?} — берётся она;
      в) участок osm-w<way>-<n> — ребро пешеходного графа как есть; г) cell-<ix>-<iy> — квадрат по формуле ui/civic_heat/geo.py
         (CELL_M=150, начало 71.0/50.8, широта 51.15). Просьба: ваши ячейки — по той же формуле, или отдавайте их через target_geometry.
      д) иначе — «примерное место»: круг 60 м у точки жалобы, пунктирный контур и надпись в карточке.
    Порядок слоёв относительно 3D-зданий решаете вы: передайте нужный id в mount({ beforeId }).

5. Координатор · research/round-14/categories_v2.json (предложение, сам файл не менял)
======================================================================
    а) У уровня 1 min_weight = 1, а вес одной жалобы через час уже < 1 (0.5 ** (возраст/14)) — одиночная жалоба пропала бы.
       В коде: вес > 0 всегда даёт уровень ≥ 1, а с порогами сравнивается вес, округлённый до целого человека
       (10 свежих жалоб = «10+», а не «6–9»). Предложение: в JSON у уровня 1 поставить min_weight 0.01 и записать правило округления.
    б) fixed_state.kk = «түзетілді». Для ремонта (яма, фонарь) естественнее «жөнделді». Модуль везде пишет как в JSON —
       если владелец выберет «жөнделді», поменять в JSON и в словаре heat.js (5 строк с «Түзетілді»).
