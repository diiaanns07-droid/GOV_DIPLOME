1е) Ночь, круг 1 (R10 B-019/B-023/B-025, R11 B1 п.3, LOCAL_B2 P1) — в оболочке ничего менять не нужно:
    - Выбор места жалобой: пока на body класс birge-picking (его уже ставит shell.js B3 в adapter.setPickMode),
      нажатие на значок R07 = щелчок по карте ТОЧНО в цель (map.fire("click", {lngLat: точка объекта})), карточка не
      открывается; щелчок по линии/двору в этом режиме тоже карточку не открывает. Правило birge.css
      «body.birge-picking .r07-badge { pointer-events: none }» можно оставить: heat.css перебивает его для значков
      (специфичнее) — иначе нажатие уходило бы в точку значка, а не в саму остановку. Без класса — heat.setPickMode(on).
    - Клавиатура: значки — одна остановка Tab (самый горячий), между значками — стрелки, Home/End; Enter открывает карточку.
      Ссылка «К главному действию» в начале страницы — у оболочки (B-025, R01).
    - Тосты: если есть window.BirgeUI.toast (ui-kit R11) — модуль показывает свои сообщения через него (body, z 60:
      над каталогом R05 и шторками); без ui-kit — свой запасной тост. Ошибка обновления карты и ошибка «Взять в работу» /
      «Отметить исправленным» / «Я тоже» — тост с действием «Повторить» (BirgeUI.toast(text, {type: "error", action})).
    - Пока данных нет (первая загрузка, нет связи) панель показывает только заголовок и скелетон / «Нет связи · Повторить» —
      на телефоне это видно в шторке сразу, без прокрутки за фильтры.
    - Значки ставятся только целиком внутри карты; своя панель/шторка (root), кнопки MapLibre (.maplibregl-ctrl-group,
      .maplibregl-ctrl-attrib) и легенда — препятствия. Свои кнопки поверх карты (⌖ + − 3D ↻, «Что построить?») передайте
      в avoidRects: () => [...document.querySelectorAll("<ваши кнопки>")].map((el) => el.getBoundingClientRect()).
    - heat.badges() — видимые значки {key, mode, spot, cx, cy}: для проверок точности (R10) без доступа к внутренностям.
    - Id устройства: "birge.device" создаётся только из crypto; старый ключ "birge.device_id" (им же пользуется R05)
      НЕ переносится (R15 S16).
    - Ошибки действий (R15 U1): 429 → «Слишком много действий подряд. Повторите позже.», 401/403 → «Войдите как сотрудник
      акимата и повторите.» — без «Повторить»; остальное — «Проверьте связь…» с «Повторить».
    - Телефон (≤ 760 px): легенда на карте — одна строка ~33 px (как .bk-legend ui-kit R11); подсказка «Приблизьте карту…»
      в режиме районов — один раз тостом.

2. R09 · жалобы v2 — сброс кэша, пульс, вес
======================================================================
2а) Сервер: после create / metoo / set_status — ui.civic_heat.invalidate() (в B1 делает шлюз через store.subscribe).
2б) Браузер: window "birge:complaint" {type, complaint_id, target} — карта перекрашивает цель (~0.8 с) и даёт пульс (не для status).
2в) Кнопки карточки вызывают ваш API: «Взять в работу» / «Отметить исправленным» → POST /complaints/{id}/status для item.open_ids;
    «Я тоже» → POST /complaints/{open_ids[0]}/metoo, заголовок X-Birge-Device и тело {device_id} — id из localStorage "birge.device"
    (тот же ключ и формат, что у формы R09; старый ключ R07 "birge.device_id" переносится сам).
2г) Ячейки: с R09 fa49fc9 сетка общая (угол 71.0/50.8). Ячейка с approximate: true — «Примерное место» /
    «Шамамен көрсетілген орын» (слово словаря R11), пунктир; без флага — «Квартал». Адаптер R01 R09CellResolver
    (ради подписи «примерное место») больше не нужен — модуль подписывает сам. Старые записи R09 с id по углу 70.9/50.8
    тоже рисуются там, где нажал житель (выбор по точке жалобы). Подпись «Шамамен орны …» от R09/R12 приводится к слову R11.
2д) Вес: человек = жалоба + каждое «Я тоже»; «Я тоже» остывает от своего времени (metoo_times); fixed / rejected не в счёт;
    всё, что пришло до последнего fixed у цели, закрыто; записи с duplicate_of НЕ считаются (их люди уже в «Я тоже» исходной).

4. R12 · цели и геометрия
======================================================================
    Модуль берёт форму цели по id (ui/civic_heat/targets.py), по порядку:
      а) реестр: ui/civic_heat/fixtures/targets_demo.json и ваши data/civic/astana/geo/objects.json | yards.json | targets.json
         (форматы {"targets": {id: {geometry, label_ru, label_kk}}} или {"items": [{id, geometry | point | polygon | coordinates | lon/lat,
         label_ru | name_ru, label_kk | name_kk}]}) — поля point / polygon R12 теперь читаются;
         для id osm-…/yard-… свой слой OSM (в) главнее ваших файлов (R01 I-01: у вас голое имя «Хан Шатыр» и name_kk = null →
         в ҚАЗ было «Нысан»); объект только у вас — подпись по вашему kind и имени на двух языках («Остановка «…»» /
         ««…» аялдамасы»), без имени — по ближайшей улице. Подпись из ЗАПИСИ жалобы — только у ячеек (R15 S11).
         11 ваших id нет в слое R07 (yard-r19917639-0 и т. п. — части мультиполигона; «Мерей» — платформа без bus=yes) —
         берутся из ваших файлов как есть.
      б) если в engine.civic_geo есть функция target_geometry({"kind","id"}) → {"geometry","label_ru","label_kk","approximate"?} — берётся она;
      в) РЕАЛЬНЫЕ объекты LOCAL-1 (data/civic/astana/osm-objects/, только чтение) — ui/civic_heat/osm_objects.py:
         osm-node-<id> / osm-way-<id> / osm-relation-<id> — остановки, платформы, детские и спортплощадки, парки, скверы,
         контейнерные площадки, вторсырьё, фонари, школы, детсады (всего с дворами 3463 цели, из них остановок 974; читаются за ~0,2 с);
         остановка — только highway=bus_stop или платформа с bus/trolleybus/share_taxi=yes (ж/д платформы исключены, R10 B-007);
         двор = landuse=residential: yard-<id пути>, для отношения yard-r<id>. Просьба: те же id в ваших /targets.
         Подписи безымянных объектов по ближайшей улице посчитаны заранее: ui/civic_heat/fixtures/osm_street_labels.json.
      г) участок osm-w<way>-<n> — ребро пешеходного графа как есть; д) cell-<ix>-<iy> — квадрат по формуле ui/civic_heat/geo.py
         (CELL_M=150, начало 71.0/50.8, широта 51.15) — только там, где двора нет;
      е) иначе — «примерное место»: круг 60 м у точки жалобы, пунктирный контур и надпись в карточке.
    Значок с числом ставится ВНУТРИ контура (geo.inside_point; найден и исправлен сдвиг центра у мелких площадок на 60–100 м).
    Порядок слоёв относительно 3D-зданий решаете вы: передайте нужный id в mount({ beforeId }).

5. Координатор · research/round-14/categories_v2.json (предложение, сам файл не менял)
======================================================================
    а) У уровня 1 min_weight = 1, а вес одной жалобы через час уже < 1 (0.5 ** (возраст/14)) — одиночная жалоба пропала бы.
       В коде: вес > 0 всегда даёт уровень ≥ 1, а с порогами сравнивается вес, округлённый до целого человека
       (10 свежих жалоб = «10+», а не «6–9»). Предложение: в JSON у уровня 1 поставить min_weight 0.01 и записать правило округления.
    б) fixed_state.kk = «түзетілді». Для ремонта (яма, фонарь) естественнее «жөнделді». Модуль везде пишет как в JSON —
       если владелец выберет «жөнделді», поменять в JSON и в словаре heat.js (5 строк с «Түзетілді»).
