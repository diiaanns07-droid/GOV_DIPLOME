1) Бэкенд /api/civic/v2 (жалобы):
     from ui.civic_feedback.v2.integration import make_service, ROUTES
     complaints = make_service(<тот же civic.sqlite3, что у v1>)
     reply = complaints.handle(method, "/api/civic/v2" + rel_path, raw_query, body_bytes, principal, context)

   - principal = store.resolve_principal(context) (R02) или None; status/duplicate требуют principal.is_staff

   - context: {"headers": заголовки запроса, "host_allowed": bool, "is_same_origin": bool|None} — как у v1.
     Заголовок X-Birge-Device должен доходить до сервиса (идентификатор устройства для «Я тоже» и «Мои обращения»).
   - Ответ — тот же конверт {"status","headers","body":{"ok","data"|"error"}}; handle() -> None для чужих путей.
   - Миграция при развёртывании: python -m ui.civic_feedback.v2 migrate --v1 <civic.sqlite3> (demo=true по умолчанию).

=== R07 (тепловая карта) — события для пульса и данные для веса ===
- В браузере: window "birge:complaint" (CustomEvent) сразу после успешной отправки или «Я тоже»:
    detail = {type: "created"|"metoo", complaint_id, target: {kind, id, label_ru?, label_kk?}, category,
              reporters (автор + «Я тоже»), status, demo}
  -> показать .bk-pulse на detail.target.id и плавно пересчитать цвет (~0.8 с).
- На сервере: GET /api/civic/v2/complaints/events?after=<seq> -> {events:[{seq, type, at, complaint_id, target,
  category, status, reporters, demo}], last}; type: created | metoo | status | duplicate. Без текстов.
  В Python: ComplaintStore.subscribe(callback) (вызывается после COMMIT) и events_since(after).
- Для веса (CONTRACT §6): ComplaintStore.list(bbox, since, category) — записи без дублей по умолчанию;
  вес = 0.5^(возраст жалобы/14) + Σ 0.5^(возраст каждого «Я тоже»/14); даты «Я тоже» —
  ComplaintStore.metoo_times([complaint_id, ...]) -> {id: [ISO, ...]}.
  status_history: момент fixed -> 7 дней зелёный «исправлено». Дубли (duplicate_of != null) НЕ считать:
  их люди уже перенесены в «Я тоже» исходной записи.
- Цель «примерное место»: target {kind: "area", id: "cell-<col>-<row>", approximate: true}; контур ячейки —
  GET /api/civic/v2/complaints/place?lon&lat или ui.civic_feedback.v2.record.cell_polygon(id) (сетка 150 м от
  угла ASTANA_BBOX 70.9, 50.8). Рисовать мягкой областью с подписью «примерное место».

=== R12 (точность карты) — что ожидает путь жителя от GET /api/civic/v2/targets?lon&lat[&category] ===
- {candidates: [{target: {kind, id, label_ru, label_kk}, distance_m, geometry}]}, 1–3 штуки, ближайший первым.
  Подпись показывается как есть в кнопке («Остановка «Нура»», «Участок: ул. Туран»), поэтому — человеческим
  языком, с заглавной буквы, без id. geometry — GeoJSON (LineString по форме улицы / Point / Polygon двора).
- Вызывается без category (житель выбирает место до текста). Таймаут на клиенте 2.5 с; при ошибке/пустом списке —
  «примерное место» (ячейка R09), жалоба всё равно имеет цель.
- Стенд R09 уже работает на реальных объектах LOCAL-1 (tests/civic/R09/stand/osm_objects.py — можно взять как
  черновик правил: точки ≤ 60 м, площади — внутри или ≤ 30 м, двор/парк уступает остановке и улице; id
  osm-node/way/relation-<id>, дворы yard-<wayid> / yard-r<relid>; отношения сшиваются из outer-путей).
- Одинаковые подписи у кандидатов (две безымянные «Участок улицы», две остановки с одним именем) житель не различит:
  R09 тогда всегда показывает расстояние, но лучше давать различимые подписи (улица + «у дома …», направление).
- НАХОДКА стенда: соседние рёбра одной улицы (osm-w503812669-26 и -27) — разные цели. Если два жителя ткнули
  в 20 м друг от друга по разные стороны узла, «Я тоже» по цели не сработает и тепло разделится. Предложение:
  участок = несколько рёбер одной улицы между перекрёстками (или ≥ 100 м), один id на участок.

=== R04 (ML-API) ===
- POST /classify {text} -> {category, score, needs_review, model_version, top3}. Клиент: дебаунс 0.7 с, от 8 символов,
  таймаут 2.5 с. needs_review=true -> категория не подставляется, открыта сетка 12 категорий.
- POST /similar {text, point, days:14} -> {matches:[{complaint_id, score, target, metoo}]}. Клиент берёт первое
  совпадение с той же целью или score ≥ 0.6, затем GET /complaints/{id} (публичная проекция без текста).
  Источник данных для /similar: ComplaintStore.list(since=...) (поле text есть только на сервере).
- Без R04 работает: категория вручную, «Я тоже» — по той же цели и категории (GET /complaints/summary).
