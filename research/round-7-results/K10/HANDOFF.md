## Устройство фикстуры

- **`steps[].scenario`** — вход по контракту `city-whatif-v1`: `schema_version`, `city_id`, `source_snapshot`, `category`, `control_points`, `proposed_object`. Вымышлены только `control_points` и `proposed_object`.
- **`source_copy.category_records`** — исходные записи категории: ID, lon/lat как в `web/data.js`, `group`, QA-флаги. Это копия только для чтения.
- **`steps[].expected.rows`** — выводимые значения для каждой точки:
  - `before_m`, `nearest_before_id`, `distance_to_proposed_m`, `after_m`, `nearest_after_id`, `delta_m`, `label`;
  - `tied_at_before_ids`;
  - `nearest_*_source`: имя, категория, `sources` с лицензией, `qa_flags` или `hypothetical`.

  Значения не округлены.
- **`source`** — коммит сборки, sha256 `data.js` и `evidence.js`, файл и sha256 `places_social.geojson`, компоненты отпечатка среза.
- **`rules`** — правила размещения точек, заданные до расчёта:
  - контрольные точки — доли bbox (0.25, 0.25), (0.5, 0.5), (0.75, 0.75);
  - проект — (0.5, 0.5), затем перенос в (0.05, 0.95);
  - QA-точка — координата самой большой группы `colocated` с записями нужной категории.

  Точки ничего не говорят о жителях.

## Мои прочтения спецификации (решите, совпадают ли с вашими)

1. **Ничья:** выбирается наименьший ID в порядке строк.
2. **Проект на том же расстоянии**, что и исходная запись, не заменяет её в `nearest_after` (`after` от этого не зависит).
3. **`source_snapshot`:** `"k10s1-"` + первые 32 hex-символа sha256 от канонического JSON (`sort_keys`, разделители `,` и `:`). В JSON входят:
   - `schema`, `city`, `release`, `bbox`;
   - `places_social_sha256` (исходный файл K10);
   - `ui_places_digest` — sha256 от отсортированного `[id, lon, lat, group]` из `web/data.js`;
   - `formula`.

   Если у сборки свой формат отпечатка, подставьте его в `scenario.source_snapshot`. Расстояния от этого не меняются. `FOREIGN_SNAPSHOT` должен по-прежнему отклоняться.
4. **Коды ошибок** (`OUT_OF_BBOX` и др.) — названия K10. Реализация может использовать свои; обязательно только отклонить ввод до расчёта.

## Как применить к реализации

```bash
python3 research/round-7-results/K10/tests/check_fixtures.py --app-root <новая сборка>   # данные не изменились?
```

Для каждого шага подайте `scenario` в свою функцию расчёта и сравните `before_m`, `after_m`, `delta_m` с допуском 1e-6 м. `nearest_before_id` и `nearest_after_id` должны совпасть точно. Для `null` — точное совпадение.

Мой порт на JS (`tools/whatif_ref.cjs`) отличается от Python максимум на ~1e-9 м.

## Чего фикстуры не утверждают

- Ближайшая запись в срезе не обязательно ближайшее учреждение города: Overture неполон.
- `delta > 0` означает только более короткое расстояние по прямой. Это не время пешком и не улучшение образования или здоровья.
- QA-флаг — повод проверить запись, а не доказанная ошибка.
