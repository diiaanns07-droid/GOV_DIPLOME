## Контрольные значения и допуски
| Случай | Ожидание (получено независимо) | Допуск |
|---|---|---|
| одна и та же точка | 0 точно | 0 |
| 1° по меридиану, 0,5° по экватору, 1e-5° у Астаны | R·Δφ, R·Δλ (замкнутая форма) | 1e-6 м |

Реализация сборщика считается совпадающей, если |её значение − fixture| ≤ 1e-6 м до округления для вывода.

## Метаморфные проверки (на реальных записях обоих городов, обеих категорий, 25 случайных сценариев на пару)
after ≤ before и delta ≥ 0; удаление проекта восстанавливает baseline; проект дальше ближайшей записи ничего не меняет
(ни after, ни ближайший источник); перемещение = расчёт заново; порядок записей не влияет; оракул = хорда на реальных записях.

## Как проверить сборку
Для каждого `cases[]` и `synthetic_edge_cases.cases[]` подать `scenario` (и `records` / записи среза города) в реализацию,
сравнить `before_m`, `after_m`, `delta_m`, `nearest_record_id` (null там, где null); все `must_reject` должны отклоняться.
`nearest_record_qa` показывает, у каких ближайших записей есть QA-флаги (6 строк из 120) — их нельзя молча убирать.
Опорный `source_snapshot` (`k06ref-sha256:…`) вычислен из записей, bbox, выпуска и параметров формулы; сборщик может
задать свой отпечаток, но не по имени файла.
