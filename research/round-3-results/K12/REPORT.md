## Контракт строки `k12-energy-monthly-v1`

Одна строка — это одно здание за один расчётный период. Поля перечислены в `REQUEST_FIELDS.txt`.
Названия `value_status` (reported / reported_zero / missing) и `kind` совпадают с контрактом K05
`k05-obs-v1` (`claude/optimistic-davinci-1oiqs9` @ `6d39cc5`, прочитан только
`observation.schema.json`). Код K05 не импортируется.

**Правила строки.** Каждая отклонённая строка сохраняется с кодом причины в `rows_validation.csv`.

- Обязательные поля.
- `city_id`: для KZ допустимы только `kz.shymkent` и `kz.astana`; префикс должен совпадать
  с `country`.
- Даты: только ISO, и `period_end ≥ period_start`.
- Единицы: kWh принимается. MWh и тыс. кВт·ч переводятся ×1000 с пометкой. кВт, Гкал и м³
  отклоняются, остальное — «неизвестная единица».
- Отрицательные значения отклоняются.
- **missing ≠ 0**: ноль принимается только с `value_status = reported_zero`, пустое значение —
  только со статусом `missing`.
- `reading_type`: `norm` — не измерение; `estimated` и `unknown` снижают доверие.
- `coverage_share` должен быть в [0, 1].
- `kind = hypothesis` для показаний запрещён.
- Неоднозначные числа вида `1,234.5` отклоняются.

**Правила между строками:**

- точный дубликат: первая строка остаётся, остальные отклоняются;
- конфликтующий дубликат: отклоняются все строки;
- пересечение периодов одного здания: отклоняются все пересекающиеся строки, в том числе длинный
  период поверх нескольких коротких.

**Правила здания:**

- EUI считается только по **одному общему окну** для всех зданий и только при полном покрытии
  окна днями со значением.
- «Годовым» EUI называется только при окне в 365 или 366 дней.
- Период, выходящий за границу окна, не делится пропорционально и не входит в итог.
- Не ранжируются здания, у которых:
  - разные города или типы объекта;
  - смешаны synthetic и реальные строки;
  - площадь неизвестна, равна 0 или различается между строками;
  - в окне есть начисление по нормативу;
  - взвешенное покрытие учётом < 0,9.
- Рейтинг строится только внутри группы «город × тип объекта × класс данных». Шымкент, Астана и
  synthetic не смешиваются.

## Пример на BDG1: что показал отчёт

Данные **реальные, иностранные**: Великобритания, Dec 2014 – Nov 2015, имена школ из BDG1
сохранены (`bdg1:PrimClass_*`), `city_id = gb.unknown` (в метаданных BDG1 города нет). Значения —
суммы наблюдённых часов без заполнения пропусков (`kind = derived`). Единицы kWh — допущение:
источник их не указывает. Условия использования измерений — `unknown`: LICENSE репозитория — MIT, то
есть лицензия ПО, а условия исходных измерений не перечислены. Отчёт:
`examples/bdg1_gb_2014_2015/report/report.md`.

- 888 строк, принято 888. Ранжировано 74 школы, топ-15. Доверие у всех `medium`: площадь из
  метаданных набора, а не из техпаспорта.
- **Ошибка площади.** Среднее совпадение топ-15: 0,851 / 0,708 / 0,607 при σ_log 0,1 / 0,2 / 0,3.
  При σ_log 0,2 устойчиво в топе только 2 школы, на границе 29, вне топа 43.
- **Неполный учёт меняет границу списка.** 15-е место занимают разные школы в зависимости от того,
  как учтены пропуски:
  - значения как есть (по умолчанию) — `Juanita`;
  - досчёт «значение / покрытие» — `Jacquelyn`;
  - профильная подстановка раунда 2 — `Josue`.

  В остальном топ-15 совпадает (14 из 15).
- **Строгое правило учёта опасно при общем пробеле.** Если не принимать месяцы с покрытием < 0,8,
  в рейтинге остаётся **12 из 74** школ. Причина — июнь 2015: медианное покрытие 0,70 у всех
  британских школ, то есть общий пробел набора, а не проблема отдельных зданий. Порог по строке
  надо применять с учётом того, общий пробел или индивидуальный.

## Синтетические проверочные случаи

Входы выдуманы. Коды городов казахстанские только для проверки формата оператора. Отчёт:
`examples/synthetic_cases/report/report.md`.

- 333 строки, отклонено 16 с 11 разными кодами причин.
- 32 здания, 15 ранжированы в двух группах (Шымкент и Астана отдельно).
- Каждый случай дал ожидаемый исход:
  - пропущенный месяц, неподтверждённый ноль, отрицательное значение, кВт, Гкал, конфликтующий
    дубликат и пересечение периодов делают окно неполным;
  - подтверждённый ноль, точный дубликат, MWh и расчётные показания допускаются с пометкой;
  - норматив, нулевая или неизвестная площадь и два города у одного здания не ранжируются;
  - счёт с 15-го по 14-е не покрывает календарный год, но покрыл бы окно, выровненное по счетам
    (проверено тестом).

## Ограничения

- Местных входов нет. Импортёр проверен на иностранных данных и синтетике.
- Модель ошибки площади (лог-нормальная, σ_log 0,1–0,3) — допущение для чувствительности.
- Досчёт по покрытию — оценка в предположении равномерного потребления. В BDG1 пропуски сгущаются
  в учебные часы (раунд 2), поэтому эта оценка смещена. По умолчанию она не используется.
- Окно анализа задаёт пользователь, одно для всех зданий. Выравнивание по датам счетов оператора
  пока ручное.
- Десятичная запятая принимается с пометкой. Строки вида `1,234.5` отклоняются как неоднозначные.
- Высокий EUI — кандидат на энергообследование, не доказанная экономия и не неисправность.
  Электрический EUI ничего не говорит о тепле.
