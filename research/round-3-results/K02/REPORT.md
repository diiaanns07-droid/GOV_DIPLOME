# K02, раунд 3. Объяснение по ID проверенных фактов

Дата: 2026-10-05. Изолированный прототип. Код `agent/` и интерфейс продукта не менялись.

## Итог

Модель (в прототипе — детерминированная заглушка) больше не пишет числа. Она выбирает только:
- **типы секций** из закрытого списка `summary | weakest | risks | data_gaps`;
- **ID фактов** из каталога, который код строит по ответу движка.

Значения, единицы, подписи ru/kk и пометку вида данных («учебная модель», «нет данных») выдаёт код. Свободный комментарий по умолчанию отбрасывается. Если его показывать, он идёт отдельным блоком «не проверяется» после проверяемой части, а сама проверяемая часть от него не зависит; это покрыто тестом.

## 1. Что сделано

| Файл | Назначение |
|---|---|
| `verified_explainer.py` | адаптер: `build_catalog` (ответ `simulate`), `catalog_from_observations` (реальные наблюдения), `PLAN_SCHEMA`, `validate_plan`, `render`, `StubSelector`, `explain` |
| `demo.py` | команда: лучший план учебной модели, ru и kk, опционально `--event E2` |

| `kk_letters_anchor.patch` | отдельная правка ошибки с казахскими буквами в `agent/evidence.py` (не применена) |

**Формат ID:** `<город>/<сценарий или период>/<путь>`, например `astana_hackathon/base/plan.score`. Город и сценарий входят в ID, поэтому факт другого города или устаревшего сценария видно до рендеринга.

Каталог учебной модели содержит 9 фактов: Score плана и без мер, изменение Score, стоимость, бюджет, число критических значений после мер и без них, самый слабый район и его индекс. Все помечены `kind = model`. Если поле отсутствует или равно `null`, факт получает `kind = unknown`.

## 3. Сравнение с текущим фильтром (`compare_result.json`)

- **A** — текущий `qualitative_comment`.
- **B** — словарь K02 r2.
- **C** — объяснение по ID.

Для A и B: «одна» — фраза подана отдельно; «+ ru» — фраза подана вместе с нейтральным русским предложением.

| Фраза | Есть число | A одна / + ru | B одна / + ru | C, если подать как ID |
|---|---|---|---|---|
| «Бұл бір маңызды қадам.» | нет | сохранена / сохранена | **EvidenceError / удалена** (ложно) | `not_an_id` |
| «Іс әлі ұзақ.» | нет | **EvidenceError** / сохранена | сохранена | `not_an_id` |
| «Үш аудан ғана жақсарады.» | да | **сохранена (утечка)** | удалена | `not_an_id` |
| «Есіл ауданы үшінші орынға түседі.» | да | **утечка** | **утечка** | `not_an_id` |
| «Bul josparda bes mektep bar.» | да | **утечка** | **утечка** | `not_an_id` |
| «Score вырос на 99 баллов.» | да | удалена | удалена | `not_an_id` |

Проверяемая часть C на ru и kk содержит числа `57,24 / 4,68 / 98 / 54,09 / 0`. Все они — запись значений каталога (`all_from_catalog: true`). Текущий фильтр, применённый к этой части, удалил бы строки с числами. Значит, для проверяемой части он не подходит: там числа легитимны.

Важное уточнение к заданию. Ложное удаление на «бір» даёт **не текущий фильтр**, а словарь K02 r2 (B). Текущий фильтр ошибается на казахских буквах: отказ `[А-Яа-яA-Za-z]{3}`. Patch `kk_letters_anchor.patch` (замена на `[^\W\d_]{3}`) проверен на копии файла:
- «Іс әлі ұзақ.» принимается;
- «12 34.», «...» и «Стоимость 56.54 у.е. Score 95.» по-прежнему дают EvidenceError.

Patch в `agent/` не применён.

## 4. Граница гарантий

**Гарантируется кодом при принятом плане:**
- каждое число и каждая подпись в проверяемой части — запись значения из каталога текущего ответа движка для указанного города и сценария;
- `null` не превращается в 0;
- факт другого города или сценария не попадает в текст;
- комментарий модели не меняет проверяемую часть.

**НЕ гарантируется:**
- **уместность выбора.** Модель может выбрать верные, но не относящиеся к вопросу факты или промолчать о важном. Это вопрос качества, а не достоверности. Измерить его можно только на наборе вопросов ru/kk с разметкой людей: Т1/Т4 у K09;
- **правильность каталога.** Если движок или адаптер неверно взял поле, ошибка будет напечатана «проверенной». Каталог проверяется тестами адаптера, а не моделью;
- **безопасность свободного комментария.** Словарь числительных её не обеспечивает: утечки «үшінші» и латиницы остаются даже после расширения. Поэтому по умолчанию комментарий отбрасывается. В режиме `separate` он помечен как непроверяемый, и это честная маркировка, а не фильтрация;
- **казахские формулировки.** Подписи — черновик K02, их должен проверить носитель;
- **живые ответы модели.** LLM не вызывалась: ключа нет. `StubSelector` помечен `deterministic_stub (not an LLM)`. Насколько хорошо реальная модель выбирает ID по `PLAN_SCHEMA`, не измерено;
- **реальные города.** Сейчас каталог строится только из учебной модели (`kind = model`). `catalog_from_observations` проверен лишь на тестовой строке с `null`. Контракт наблюдений — у K05.
