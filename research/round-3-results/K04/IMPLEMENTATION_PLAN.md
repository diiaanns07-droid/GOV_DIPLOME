# K04 · План трёх небольших этапов для MVP-1 (предложение)

MVP-1 — «Аудит данных и пешая доступность соцобъектов». Каждый этап — отдельная ветка и отдельное задание координатора. Код продукта этот план не меняет. Критерии каждого этапа — в `acceptance.json`.

## Этап 1 — «Честная карточка района» (без расчёта доступности)

- **Что:** для обоих городов собрать карточку района: полигон, число объектов по типам из Overture с confidence, источник, снимок и лицензия; статус `value | unknown | partial` по контракту K05 `k05-obs-v1`. Заменить способ, которым `fetch_real_context.py` пишет нули при сбое, — **патчем**, применять его будет координатор.
- **Входы:** скрипты и выгрузки K10 (`overture_extract.py`, `places_by_district.py`, `raw_extracts.sha256`), валидатор K05, границы продукта.
- **Результат:** `district_cards_{shymkent,astana}.json` и статическая страница-прототип вне основного сайта.
- **Готово, когда:** A1.1–A1.5 выполнены.
- **Зависит от:** K05 раунда 3 (адаптер), K03 (состав районов; две версии — выбирает координатор), K08 (проверка K10).
- **Объём:** ~1 день.

## Этап 2 — «Доступность по сети против радиуса» на одном районе каждого города

- **Что:** пешеходный граф из Overture-сегментов (классы из K10-E03) для одного района Шымкента и одного района Астаны; изохроны 500/800/1200 м от школ; сравнение с радиусом; доля дорожной сети в пределах порога. Пока нет зданий — по длине сети, а не по жителям. Явная пометка о разной полноте footway.
- **Входы:** K10-D04, точки школ из этапа 1, скрипты K07 (`03_access_vs_provision.py` как эталон логики).
- **Результат:** `access_{city}_{district}.json` и слой на прототипе.
- **Готово, когда:** A2.1–A2.4 выполнены. На A2.3 нужна ручная сверка 20 объектов на район по независимой карте.
- **Зависит от:** K07 раунда 3 (прототип карты); дублировать его нельзя, использовать результат.
- **Объём:** 1–2 дня.

## Этап 3 — «Проверяемое объяснение и сопоставление с реестром»

- **Что:** (a) AI-объяснение карточки ru/kk с числовым фильтром: все числа берутся только из карточки; (b) после доступа к реестру data.egov.kz — AI-предложения пар «объект Overture ↔ строка реестра», подтверждаемые человеком; (c) 1–2 think-aloud сеанса со специалистом.
- **Входы:** результат K02 (проверяемое объяснение), K09-E8 (топонимы), реестр (сейчас заблокирован: 403).
- **Результат:** отчёт с метриками A3.1–A3.3.
- **Готово, когда:** A3.1 = 0 новых чисел. A3.2 опубликовано с порогом, заданным заранее. A3.3 проведено; если сеансов не было, польза остаётся гипотезой.
- **Объём:** 1–2 дня без реестра; после реестра — дополнительно.

## Что не входит

Слой обеспеченности местами (нет вместимости и детей), межгородской рейтинг, прогнозы, изменения учебной модели STUPITS, слияние веток.
