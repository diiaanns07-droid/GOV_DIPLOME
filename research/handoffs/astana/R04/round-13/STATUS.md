## Checkpoint 1 — PARTIAL (гонки сессии, карты и навигации)

Сделано в `web/civic/editor/editor.js`:
- `openObject(id)` до ответа GET /session при mount больше не теряется: запрос ждёт проверки сессии; если вход есть —
  открывается сразу эта запись (без списка), если нет — форма входа «Войдите, чтобы открыть запись», после входа
  открывается запись. Промис openObject возвращает true/false (false — если пользователь ушёл в другое место).
- Перед запросом записи прежняя запись удаляется из памяти страницы; отказ (404/403) возвращает в список с ошибкой,
  поля закрытой записи не показываются.
- Поздний ответ не открывает старую запись поверх новой или поверх списка (счётчик навигации).
- Смена пользователя в этой вкладке (например, вход другим пользователем в соседней вкладке заменил cookie):
  форма первого не отправляется и не показывается второму; несохранённая копия первого хранится отдельно и
  возвращается ему, когда он снова войдёт в этой вкладке. Локальная копия в sessionStorage — по пользователям (v2),
  без паролей, токенов и CSRF.
- Ожидание поздней карты ограничено (повторы 1–30 с, всего около минуты на открытую запись), дальше — только по
  нажатию кнопки рисования или через `setMap()`. Без карты кнопки объясняют, что карта ещё загружается.
- Перед каждой записью (сохранить/опубликовать/архив) — проверка GET /session: если вкладка уже под другим
  пользователем, запись не отправляется. Причина: адаптер R01 после отказа CSRF обновляет сессию и повторяет POST,
  что иначе отправило бы форму первого пользователя от имени второго.
- Совместимость с P0-проверкой R01: кнопки «Точка/Линия/Площадь» видны и при «Место неизвестно» (выбор сменится на
  «приблизительно»); отмена инструмента возвращает прежний выбор.
- Рисование: синхронный признак для соседей — `window.CivicEditor.isDrawing()` / `activeTool()` и атрибут
  `<html data-civic-editor-tool>`; при завершении щелчком по карте `{active:false}` отправляется после обработки
  этого щелчка всеми слушателями (чтобы R03 не принял щелчок за выбор объекта).
- openObject при невходе возвращает false (контракт), но запись откроется сразу после входа.

## Checkpoint 2 — PARTIAL (изменённый источник, сравнение при 409, совместимость с R02)

Сделано:
- Изменённый источник (R02 import candidates): если `staff.pending_import_candidates > 0`, редактор загружает
  GET /staff/objects/{id}/import-candidates и показывает таблицу «Поле · Сейчас (ред. N) · По источнику · Что
  подтверждает» (источник, дата публикации, проверка, доступ — из source_refs[].fields кандидата); подсказка, что
  первоначальный срок зафиксирован. «Принять изменения источника…» (причина обязательна после первой публикации,
  остаётся в служебной истории) и «Отклонить…» (причина необязательна, сервер её не хранит). С несохранёнными
  правками принять нельзя. 409 при принятии — сравнение обновляется, ничего не применяется.
- Сервер без маршрута /import-candidates (шлюз R01 на 56538a3 его не подключает): честное сообщение «есть N
  изменений, но посмотреть их здесь нельзя», кнопок нет.
- Публичная причина переноса срока: при публикации (модель R02) или сохранении опубликованной записи (без модели)
  перенос срока, видимый жителям, требует понятной причины — голая категория («Уточнение по источнику») не
  принимается; в шаге публикации написано, что увидят жители (новый срок, прежний, причина).
- 409 при сохранении: таблица по полям «Было (ред. N) · На сервере (ред. M) · Ваша правка», поля, изменённые
  обеими сторонами, отмечены; ввод остаётся, ничего не перезаписывается до выбора; при «Перенести мои правки»
  учитывается и то, что набрано после появления конфликта. Восстановление локальной копии поверх новой редакции —
  сначала та же таблица сравнения.
- Совместимость с реальными данными R02/R05 (найдено тестом против R02 bd7a911): `retrieved_at` может быть
  датой-временем ISO (как принимает R02) — больше не блокирует сохранение; поля источника — весь список путей R02
  (title, schedule.current_planned_end, …), непоказываемые пути сохраняются и отображаются.
- По независимому обзору: ответ сохранения/публикации, пришедший после перехода к другой записи, не возвращает
  старую; смена экземпляра карты через геттер подхватывается; рисование завершается при повторном входе, конфликте,
  восстановлении; публикация/архив ждут завершения рисования; потерянный ответ публикации всё равно сообщает карте
  (onPublished); правка только внутренней заметки не дёргает публичную карту; настройка внутренних заметок не
  переходит к следующему пользователю.
