CP1 (ab1d2fc) — контракт пользовательского результата:
- `ScenarioResultCache.remember(payload, result)` принимает только проверенный ответ движка R07 на этот вход:
  result_digest (без `timing_ms` HTTP-адаптера), payload_digest, город/граф/режим/момент/точки, планы и
  согласованность итогов (пары = отправления × назначения, суммы статусов и изменений, a_vs_b при A и B).
  Отказ -> None + код (`stats()["rejections"]`). digest — контроль целостности, не подпись: подлинность
  обеспечивает то, что remember вызывает только шлюз после своего compare().
- Запись v2 (`civic-assistant-scenario-entry-v2`): без edge_ids/node_ids маршрутов, копия (deepcopy); город
  ~54 КБ -> несколько КБ; факты из записи совпадают с фактами полного результата на 3 реальных кейсах R07.
- Лимиты: число записей, TTL, размер записи (`entry_too_large`), общий объём (вытеснение старых).
- Нет записи: `scenario_result_expired` («больше не хранится») и `scenario_result_unknown` («не найден») —
  оба просят пересчитать; подготовленный кейс никогда не подставляется вместо `result:`.
- Факты `scenario.kind/result_ref/stored_at` и фраза «Это ваш расчёт… (идентификатор …)» / «Это
  подготовленный пример сценария, а не ваш расчёт»; подмена вида записи/ID -> `scenario_kind_mismatch`.

CP2 — объект и даты данных:
- `revision` в теле POST /assistant (целое ≥ 1, только с object_id). Опубликована другая редакция ->
  `object_revision_changed`: фактов нет, названа текущая редакция. Проверено на настоящем R02 (временная SQLite):
  публикация -> черновик переноса (жителю не виден) -> публикация переноса -> архив (недоступно).
- UI шлёт `revision`, на `object_revision_changed` не показывает ответ и вызывает `onStale({objectId, revision})`;
  destroy во время запроса: обработчики сняты, запоздавший ответ не появляется (проверено в Chromium).
- Интент `freshness`: дата изменения карточки (редакция) ≠ дата публикации источника ≠ дата получения системой;
  снимок OSM ≠ дата получения; «помощник не знает, что изменилось после». Источник теперь называет и дату получения.
- Доля неизвестного доступа всегда «по длине сети»; доля по числу рёбер движком не сообщается -> «нет данных»
  (факт `scenario.unknown_access_share_by_edges`, не пересчитывается).
- access_impact: обязательная фраза «помощник не делает вывода, что перекрытие действует сейчас»; интервалы
  перекрытий сценария — «по условию сценария в момент анализа».
