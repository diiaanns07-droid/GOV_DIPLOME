# K07 — доступность школ и социальной инфраструктуры: проверка идеи

Задание K07: свести A04/A05 (Шымкент) и AST-A04/AST-A05 (Астана) в одну узкую проверку. Найти реальный реестр и пешеходную сеть или зафиксировать блокировку. Сформулировать сценарий пользователя и baseline. Показать на воспроизводимом примере разницу между географической доступностью и обеспеченностью местами, не выдумывая население и вместимость.

Дата работы: 2026-10-05 (UTC). Транспорт (A06/AST-A06) не дублируется.

## Главное

1. **Реальных данных получить не удалось.** Overpass и data.egov.kz из этого окружения отвечают 403 на CONNECT: это политика сети, а не отсутствие данных (`access_check.json`). В репозитории нет ни строк реестра школ, ни OSM-точек школ, ни пешеходной сети. Для обоих городов есть только карточки наборов data.egov.kz из стороннего обхода каталога (вторичный источник).
2. **Эксперименты A04 и A05 воспроизводятся точно.** A04 совпал побайтно, у A05 отличаются только платформа и время работы. Из 32 чисел, процитированных в отчётах, совпали 31. Расхождение: у A05 участок C1 «шестой» по непокрытым местам, а по JSON он пятый.
3. **Baseline «радиус вместо сети» на игрушках A04 меряет в основном решётку, а не барьер.** При 500 м из разрыва 22,5 п.п. на барьер и промзону приходится 0,8 п.п. Числа «радиус завышает на X п.п.» с игрушек на город переносить нельзя.
4. **Проверка слоя продукта.** Подтверждены 25 нулей при `status = unavailable` в `data/real_context.json`. Новое:
   - сборщик знает 5 районов из 6, поэтому объекты Сарайшыка попадут в «вне районов»;
   - заглушка создана до сохранения OSM-границ;
   - безымянные объекты не дедуплицируются.
5. **Пример «доступность против обеспеченности».** Вместимость и спрос заданы только неизвестными долями, а не числами.
   - География одинакова при любых долях, а худшая по местам территория бывает любой. Из 9 сценариев она та же, что по географии, в 3, противоположная в 3 и не определена (территории равны) в 3.
   - Районный баланс скрывает, что у 40% спроса одной территории нет школы в пределах 800 м по сети.
   - Радиус вместо сети переворачивает вывод о местах в 3 сценариях. Например, острая нехватка 0,43 от среднего превращается в 1,01.

**Вывод для идеи.** Продукт должен показывать два раздельных слоя. Слой «географическая доступность по сети» вычислим сразу после доступа к OSM. Слой «обеспеченность местами» до появления источников мощности и численности детей честно показывает «не вычислимо». Радиус допустим только как подписанная грубая оценка, но не как основа выводов о местах.

## Что нужно для следующего шага

Разрешить в настройках окружения домены `overpass-api.de` (или `download.geofabrik.de`) и `data.egov.kz`. Затем:
1. выгрузить OSM-точки школ, жилые здания и пешеходную сеть для одного района каждого города, отдельно;
2. получить 5–10 строк реестра;
3. прогнать валидатор и пример на реальных входах.

Слой обеспеченности остаётся «не вычислимо», пока нет источника мощности и численности детей.
