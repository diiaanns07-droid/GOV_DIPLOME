## 1. Астана: независимая проверка утверждений AST-A12

Свой скрипт `k03_geometry.py` собирает кольца каждого из 11 отношений из сырого ответа Overpass (`data/geo_sources/astana_districts_overpass.json`). Он не использует слой продукта и не использует код AST-A12. Результат `geometry_result.json`.

| Утверждение AST-A12 | Результат K03 |
|---|---|
| Объединение 6 районов 789,3 км², 4 части: 770,41 / 9,021 / 5,033 / 4,794 | **подтверждено**: 789,257 км², те же части |
| Эксклав Байконура 9,021 км² лежит и в Целиноградском районе (relation 3403760), точка (71.66574, 51.33028) в обоих | **подтверждено**: площадь пересечения 9,021 км², точка покрыта обоими |
| Остальные эксклавы (Байконур 5,033; Алматы 4,794) | K03: ни в одну соседнюю единицу снимка не попадают |
| Косшы, Аршалы, Шортанды, Тайтобе касаются Астаны без площадного пересечения | **подтверждено** (плюс Целиноград касается и пересекается) |
| Тройная вершина (71.447389, 51.1311552): `contains` — никто, `covers` — Алматы, Есиль, Сарайшык | **подтверждено** |
| Сарайшык `admin_level=8`, relation v17 от 2026-09-21T13:44:01Z | **подтверждено** (`sara_osm.json`, changeset 189349743) |
| Пересечений между 6 районами нет | **подтверждено**: 0 пар с площадью > 0 |
| В реестре AST-A12 КАТО районов = `null` | **уточнение**: в OSM у Есиля `711210000`, Алматы `711110000`, Сарыарки `711310000`, Байконура `711410000` есть тег `kato` (его фиксировал AST-A04). Это теги сообщества, не классификатор. У Нуры и Сарайшыка тега нет |

Дополнительно:
- Слой продукта `data/astana_districts.geojson` совпадает с сырым OSM: IoU = 1,0 для всех 6 районов.
- Площади в слое продукта плоские приближённые. Например, Есиль 193,0 против геодезических 194,556 км², расхождение около 0,8 %. Для показателей на км² брать геодезические.
- `astana_districts_overpass.json` и `overpass.json` содержат одинаковые элементы. Файлы различаются только полем `_provenance`.
- Natural Earth (п. F015 AST-A12) не проверялся: файла в репозитории нет.

**Что это значит.** Геометрические конфликты AST-A12 — реальные свойства сохранённого снимка OSM, а не ошибки расчёта. Какая принадлежность эксклава юридически верна (город или Целиноградский район), из этих данных не следует. Нужен официальный акт.

## 2. Шымкент

- В репозитории нет ни одного полигона Шымкента. Единственный GeoJSON по Шымкенту — синтетический `govtech-results/03_logistics/extracted_files__22_/A03_synthetic_instance.geojson`, полигонов в нём нет.
- Единственное наблюдение — коды из выборки A10. Их получил A10 через WebFetch 2026-10-04, K03 их не перепроверял, потому что сеть закрыта:
  - `area_code = 1979`;
  - районы по полю `fd1r06p2`: `197910`–`197913` встречаются в 2018–2026, **`197914` — только в 2023–2026**.
- Состав «Абайский, Аль-Фарабийский, Енбекшинский, Каратауский, Туранский» — гипотеза A12-F016 по памяти модели. По A12 «Туранский создан около 2021 г.», а код `197914` в слое ДТП появляется с 2023. Это расхождение не разрешено. Могут быть разные причины: дата реформы, переход учёта, ошибка памяти. **Коды с названиями не сопоставлены.**
- ISO `KZ-79` — гипотеза A12-F018. `KZ-71` для Астаны взят из Nominatim (`sara_nominatim.json`), это тоже не официальный источник.

## 3. Реестр (`territory_registry.csv`)

Поля: город; тип; предлагаемый `stable_id`; `legacy_id`; названия; `osm_relation`; `admin_level`; КАТО и его происхождение; wikidata; код КПСиСУ; дата и её смысл; тип геометрии; геодезическая площадь; provenance с sha256; проверка геометрии; официальный статус; общий статус; примечания.

- Астана: город (производная геометрия), 6 районов (`observed_osm`).
- 5 соседей Акмолинской области помечены «в агрегаты Астаны не включать».
- Шымкент: город и 5 кодов районов. У них `geometry = none`, `status = observed_code_only`.

## 4. Ограничения

- Официальные источники (adilet.zan.kz, stat.gov.kz) и OSM (Overpass, API) недоступны: прокси вернул 403 (host_not_allowed). Свежесть снимка от 2026-09-22 не проверена. Сарайшык редактировался за день до снимка.
- OSM — общественный источник. Полигон не является юридической границей.
- Коды КПСиСУ взяты из чужой выборки. Справочника кодов нет, лицензия слоя не указана (A10).

## 5. Следующий шаг

Из среды с разрешённым доступом получить для обоих городов:
1. Действующий акт о составе и границах районов: adilet.zan.kz или сайт акимата.
2. Классификатор КАТО.

Затем заполнить в `territory_registry.csv` поля `official_status` и `kato` и сопоставить коды `1979xx` с районами. Для Шымкента выполнить Overpass-запрос из A12 §4.3 и сохранить ответ с `osm_base`.
