# K05. «Нет данных записано как ноль»: проверка и контракт наблюдения

Дата: 2026-10-05. Город проверенных файлов: Астана (`data/real_context*.json`). Контракт общий для Астаны и Шымкента. Код приложения, `data/city_data.json` и эталоны не менялись: хэши до и после совпадают (`experiment_output.json → data_unchanged: true`).

## 1. Вывод

**Проблема подтверждена.** Утверждения A12 (Шымкент, F006), AST-A12 и A13 о «25 ложных нулях» верны по факту. Её реальное влияние сейчас ограничено, но механизм ошибки остаётся в коде.

| Что проверено | Результат | Как |
|---|---|---|
| `data/real_context.json` | 25 ячеек (5 районов × 5 категорий), все `0`, ни одного `null` | E1 |
| `data/real_context_meta.json` | `status: "unavailable"`, `districts_source: "fallback_approx"`, ошибка `ReadTimeout` Overpass, `generated_at 2026-09-23T09:25:25Z` | E1 |
| Источник нулей | `fetch_real_context.py`, `handle_failure()`: при сбое пишет `{cat: 0}` для всех районов. Признак «нет данных» хранится только в отдельном meta-файле | чтение кода + E2 |
| Воспроизведение | Настоящая `handle_failure()` с путями во временном каталоге записала 25 нулей и 0 null | E2 |
| Потребители | Кроме самого `fetch_real_context.py`, ни один `.py/.js/.html` не упоминает `real_context` (`git grep`). В Score и UI файл сейчас не попадает | E1 |
| Наивная сумма школ по городу | `0`. По контракту — `null`, `missing`, покрытие `0/5` | E3 |

Вывод «приложение файл не использует» подтверждён для текущего кода. Опасность в формате: любой будущий потребитель, который прочитает только `real_context.json`, получит «0 школ в Есиле» как факт. Именно этот формат предлагали переносить на Шымкент.

### Дополнительно найдено (в отчётах A12/A13 не отмечено)

1. **Сбой обновления не фиксируется.** Если `real_context.json` уже существует, `handle_failure()` оставляет старые файл и meta без изменений. Новая попытка и её ошибка нигде не записываются (E2: `second_failure_meta_unchanged: true`). Устаревшие данные выглядят так же, как свежие, отличаясь только `generated_at`.
2. **Нули при успешной загрузке тоже неоднозначны.** `aggregate()` заранее заполняет счётчики нулями. При `status: ok` ноль означает «в снимке OSM нет размеченных объектов», а не «объектов в районе нет». Контракт отражает это через `kind`/`source`/`note`; официальным реестром OSM не является.
3. **Устаревшая геометрия.** Нули посчитаны 09:25 UTC по схематичным границам (`fallback_approx`), а реальные полигоны OSM получены в 11:28 того же дня (подтверждает AST-A12 F006). Кроме того, `DISTRICT_IDS` содержит 5 районов. Объекты Сарайшыка при новых полигонах попали бы в «вне районов», а не в отдельную строку.
4. **Ошибка в собственном первом прототипе (исправлена).** Принадлежность отношения OSM городу я сначала определял по центру вершин внешних путей. Это засчитало в Астану Целиноградский район, который окружает город кольцом: 6 районов admin_level=6 вместо 5. Теперь принадлежность определяется по `osm_id` из `data/astana_districts.geojson`. Это пример того, почему derived-значение обязано хранить `derivation`.

## 2. Минимальный контракт наблюдения `k05-obs-v1`

Одно число (или его отсутствие) — одна запись. Структура: `observation.schema.json`. Правила связи полей проверяет `k05_validator.py`.

| Поле | Обязательно | Смысл |
|---|---|---|
| `schema_version` | да | `k05-obs-v1` |
| `obs_id` | да | устойчивый ID |
| `city_id` | да | `kz.astana` или `kz.shymkent` |
| `geo_unit_id` | да | `city_id` или `city_id.<район>`; другой город запрещён |
| `indicator_id` | да | ID показателя (в дальнейшем — ссылка на IndicatorDefinition из AST-A13) |
| `period` | да | `YYYY`, `YYYY-MM`, `YYYY-Qn`, `YYYY-MM-DD` или интервал `A/B` |
| `value` | да | число или `null` |
| `unit` | да | единица; для счётчиков `count` |
| `value_status` | да | `reported`, `reported_zero`, `missing`, `suppressed`, `not_applicable` (набор A12) |
| `kind` | да | `observed`, `derived`, `hypothesis`, `synthetic` |
| `source` | да | `source_id`, `locator`; для измеренного числа также `retrieved_at`; по возможности `url/path`, `sha256`, `license` |
| `data_version` | да | версия набора; синтетика только в `synthetic:*` или `astana_hackathon*` |
| `boundary_version` | нет | версия границ (`osm@<osm_base>`, `fallback_approx`) |
| `max_age_days` | нет | политика давности; «устарело» вычисляется при проверке, не хранится |
| `derivation` | для derived | формула или метод |
| `note` | нет | пояснение |

### Правила валидатора

| Код | Тип | Правило |
|---|---|---|
| `FALSE_VALUE` | ошибка | `missing/suppressed/not_applicable` с числом, **включая 0** — текущая ошибка `real_context` |
| `NULL_REPORTED` | ошибка | `reported/reported_zero` без числа |
| `IMPLICIT_ZERO` | ошибка | `0` со статусом `reported`: настоящий ноль помечается явно `reported_zero` |
| `ZERO_STATUS` | ошибка | `reported_zero` при ненулевом значении |
| `CITY`, `CITY_MIX` | ошибка | неизвестный город; район чужого города |
| `PERIOD`, `UNIT` | ошибка | нет или неверный формат |
| `SOURCE` | ошибка | нет `source_id`/`locator`; у измеренного числа нет `retrieved_at` |
| `DERIVATION` | ошибка | derived без метода |
| `SYNTHETIC_NS` | ошибка | синтетика вне синтетической версии или измерение в синтетической версии |
| `NOT_MEASUREMENT` | предупреждение | число с `kind=synthetic/hypothesis` — не показывать как факт |
| `STALE` | предупреждение | возраст на дату `--as-of` больше `max_age_days` |
| `BOUNDARY_MISMATCH` | предупреждение | `boundary_version` не совпадает с текущей версией границ города |

`aggregate_sum()` не превращает `null` в 0: при неполном покрытии итог равен `null` с покрытием `k/n`. Агрегат отклоняется при смешении городов, единиц и при смешении синтетики/гипотез с измерениями.

## 3. Примеры (`examples/`)

| Файл | Случай | Происхождение | Результат |
|---|---|---|---|
| `real_zero_osm_admin_level9.json` | **настоящий ноль**: 0 отношений admin_level=9 | настоящий снимок Overpass в репозитории (`data/geo_sources/astana_districts_overpass.json`, osm_base 2026-09-22T08:45:51Z, ODbL, sha256 записан) | OK |
| `real_count_osm_admin_level6.json` | настоящее число: 5 районов admin_level=6 | тот же снимок + `osm_id` из `astana_districts.geojson` | OK |
| `missing_real_context_astana.json` | **отсутствие**: 25 ячеек текущего `real_context` → `null/missing` | перевод `legacy_real_context_to_observations()` | 25 приняты, предупреждение `BOUNDARY_MISMATCH` (fallback_approx) |
| `stale_osm_admin_level6.json` | **устаревшее**: то же настоящее число с `max_age_days=7` | политика 7 дней — демонстрационный параметр, не норматив | `STALE` (11 дней на 2026-10-05) |
| `synthetic_city_data_esil_T1.json` | **синтетика**: T1=45 для Есиля | `data/city_data.json` (учебный датасет ТЗ, шкала 0–100) | `NOT_MEASUREMENT`; смешение с измерением в агрегате отклонено |
| `invalid/invalid_cases.json` | 6 неверных записей, в т.ч. «0 при missing» | составлены вручную | отклонены все 6 |

Ноль admin_level=9 — настоящий ноль **в источнике OSM** и в границах запроса (рамка 50.90–51.5 / 71.0–72.0 целиком содержит город: долгота 71.218–71.785, широта 50.931–51.351). Это не юридическое утверждение об административном делении. Настоящий малый образец по объектам (школы, остановки) получить не удалось: Overpass заблокирован (раздел 5).

## 4. Рекомендация (код продукта не менялся)

Минимальное изменение для отдельной задачи с владельцем `fetch_real_context.py`:
1. В `handle_failure()` писать `null` вместо `0`, либо сразу писать записи k05-obs-v1 со статусом `missing`.
2. При сбое с существующим файлом обновлять meta: `last_attempt_at`, `last_error`, `last_success_at`.
3. Добавить `saraishyk` в `DISTRICT_IDS` для справочного слоя (в расчётный набор ТЗ не добавлять) и записывать `boundary_version` из `astana_districts.geojson`.
4. Любой будущий потребитель читает слой только через валидатор.

Учебный режим `astana_hackathon` под контракт не переводить: эталоны и `city_data.json` остаются как есть, синтетика лишь получает метку при экспорте.

## 5. Ограничения

- Сеть: по одному запросу к `https://overpass-api.de/api/status` и `https://stat.gov.kz/` получили `CONNECT tunnel failed, response 403`. Прокси записал `connect_rejected` (политика). Повторы не делались. Реальный образец объектов OSM и официальные показатели БНС не получены. Это отсутствие доступа, а не отсутствие данных.
- Шымкент: локальных реальных наблюдений нет, примеры только по Астане. Контракт и `CITY_MIX` проверяют разделение городов.
- Валидатор — изолированный прототип на stdlib. JSON Schema описывает структуру, но отдельной библиотекой `jsonschema` не прогонялась (её нет в окружении).
- Числа из отчётов A12/A13 я не принимал на веру. Проверены только утверждения о `real_context` и коде.
