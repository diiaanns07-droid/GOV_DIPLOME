ЗАЧЕМ
Задача Gton «Единая карта инфраструктурных объектов» требует реестр с жизненным циклом и флагами отставания: «90% объектов с актуальным статусом, сводка за минуты». А идея владельца — «сблизить народ и акимат»: акимат предлагает объект, жители голосуют.

ЗАДАЧИ ПО ПОРЯДКУ
1. Этапы объекта в ui/civic_store/: stage (planned → design → procurement → construction → acceptance → operating), planned_end, forecast_end, delay_days (считается сам), stale (не обновлялся > 14 дней). Миграция старых записей без потерь (история сохраняется), тесты миграции.
2. Предложения и голоса: таблицы proposals (id, kind из 5 объектов R05, geometry, title ru/kk, status proposal/approved/rejected, created_at) и votes (proposal_id, хэш device_id, value ±1; один голос с устройства, повторное нажатие меняет голос). Функции API по CONTRACT §7.
3. web/civic/proposals/: карточка предложения — название, «Проект», крупные кнопки «За» / «Против» со счётчиками, подпись «Один голос с устройства»; для акимата — «Одобрить» / «Отклонить». Карточка объекта: полоса из 6 этапов с текущим выделенным, значок «Отстаёт на 23 дня» (цвет + слова), «Давно не обновлялось».
4. Поля этапа в редакторе сотрудника: редактор принадлежит R12 — дай в INTEGRATION.txt точный patch для web/civic/editor/.
5. Функция для «Картины дня» (R08): список объектов с отставанием и устаревших, по району.

ГОТОВО, КОГДА
- Голос сохраняется, повтор с того же устройства не удваивает счёт, всё переживает перезапуск сервера.
- Этапы и отставание видны в карточке на 375 и 1366 px, в обеих локалях.

НЕ ДЕЛАЙ
- Не теряй историю объектов при миграции. Не меняй чужие пути (редактор — через INTEGRATION).
