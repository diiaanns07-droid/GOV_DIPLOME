# K06, раунд 4 (REVIEW): проверка геометрической длины в пакете K10 раунда 3

Вход: `claude/save-work-handoff-j7pc05` @ `ea703f1ddd3a411430a981164a78a7dda64ec909`, `research/round-3-results/K10/`,
выпуск Overture `2026-09-23.1`. Вид данных: `observed_secondary` (Overture/OSM), по одному квадрату 2×2 км на город.
**Это не реестр города.** Шымкент и Астана считаются отдельно.
Дополнительно прочитан потребитель пакета: K07 `claude/save-work-handoff-ku3ej3` @ `6778deda6d3f3a7f27698f651c1b0046d2a9aae9`,
`scripts/graph_check.py`.

Все длины здесь — геометрическая (топологическая) длина в метрах по линиям OSM. **Это не время пешком**:
скорость, переходы, ожидание, уклоны, зима и права прохода не моделируются.

## Оракул
`geo_oracle.py` (stdlib): формула Винсенти на эллипсоиде WGS84, независимая от гаверсинуса K10 (сфера R = 6 371 008,8 м).
Допуск: |Δ| ≤ max(0,5 %, 0,05 м). Сфера отличается от эллипсоида до −0,32 % с востока на запад и −0,05 % с севера на юг на 42–51° с. ш.
Явные гипотезы ошибок: `km_not_m`, `degrees_not_m` (евклид по сырым lon/lat), `latlon_swapped`, иначе `mismatch`.
8 тестов (`test_geo_oracle.py`):
- нулевая длина;
- 1° по экватору;
- 1° по меридиану;
- опубликованный пример Винсенти (54 972,271 м);
- аддитивность и разрез полилинии;
- обнаружение перестановки lat/lon;
- классификация ошибок единиц;
- сфера в пределах допуска.

Сверка с pyproj `Geod(WGS84)` на всех 2 410 сегментах: максимум 2,5·10⁻⁶ относительно.

## Выводы
1. **Длины K10 корректны.** Метры, `[lon, lat]`, сфера в пределах допуска. Систематическое занижение на 0,07–0,18 %
   вызвано моделью сферы. Для пешеходной доступности это несущественно; для точных сумм лучше считать по WGS84.
2. **Структура графа K10 корректна.** Компоненты воспроизведены независимо. Повторов сегментов нет. 20–21 параллельное
   ребро — законная мультиграфовость; сборщик должен хранить мультирёбра или брать минимум, а не терять их.
3. **Найдена ошибка у потребителя (K07 `graph_check.py`, строки ~150 и ~157).** `substring(..., normalized=True)` и
   `interpolate(..., normalized=True)` на lon/lat делят по плоской доле в градусах, а `at` в Overture — геодезическая доля.
   Сумма по сегменту не меняется, но длины рёбер и положения узлов смещаются (до 58 м и 61 м в Астане).
   Подтверждено на настоящем shapely 2.1.2: эмуляция совпадает с ним до 0,0 м (`out/crosscheck_shapely_k07.json`).
   Сейчас этот путь кода у K07 запускается только для будущего экспорта со связностью, поэтому прежние результаты K07
   по выборкам он не затронул. Для сборки по пакету K10 это важно. Предложение — `K07_edge_split.patch.txt`
   (не применено).
4. **Ловушка для сборки.** Нельзя присваивать `k10_length_m` каждому ребру сегмента: это даёт +357 / +432 км
   (почти в 3,8 раза больше длины сети). Ребро = (at_b − at_a)·L или геодезический разрез.
5. **Топологическую длину нельзя называть временем пешком.** Минуты появятся только с явной скоростью и пометкой «допущение».

## Ограничения
- Проверена геометрия, а не соответствие местности: пакет K10 — вторичные данные Overture/OSM в квадрате 2×2 км.
- Проходимость для пешеходов (`unknown` у большинства сегментов) не проверялась; это вне задачи.
- K07 целиком не запускался (нужен networkx); воспроизведены только две строки деления рёбер настоящим shapely.
- pyproj 3.7.2 вместо 3.8.0, закреплённого у K07: в окружении Python 3.11. `Geod` в обеих версиях использует алгоритм Karney.
