2. Стык R07 -> R09 (собственный расчёт пользователя)
   scenario_id = "result:" + result_digest ответа POST /scenarios/compare. Клиент метрик не передаёт.
   Шлюз после УСПЕШНОГО compare кладёт результат в общий ScenarioResultCache:
     a) R07 1.1.0 (ветка claude/brave-hopper-bkc58b @ f166100): http.handle(..., on_result=cache.remember);
     b) R07 базы 56538a3 (без on_result) или обвязка в шлюзе: после 200 —
        cache.remember(body, reply["body"]["data"])  или  api.remember_compare_response(cache, body, reply).
   remember() принимает только проверенный результат: result_digest (timing_ms вне digest), payload_digest,
   город/граф/режим/момент/точки, планы и согласованность итогов; иначе None + код в stats()["rejections"].
   Важно: digest — контроль целостности, не подпись. remember вызывает только сервер после своего compare();
   клиентского пути к remember нет и не должно быть.
   Лимиты по умолчанию: 64 записи, TTL 3600 с, 64 КиБ на запись, 2 МиБ всего; запись — компактная
   (без edge_ids/node_ids, сводки движка как есть; с записью MANIFEST графа: город 7,4 КБ вместо 55 КБ,
   k03 7,1 КБ вместо 148 КБ, tiny 5,1 КБ вместо 18 КБ).
   Кэш в памяти процесса: после перезапуска или при нескольких процессах -> scenario_result_unknown
   (честный «пересчитайте»); общий для процессов кэш не сделан.
   r07_case_loader(list_cases, load_graph, compare, manifest=None, *, result_cache=cache) — "result:..." ищется
   только в кэше; load.status(id) -> ok|expired|rejected|unknown.
   Поля R07 1.1.0, если пришли: a_vs_b.identical_active_closures -> «закрыты одни и те же участки»;
   closed_on_baseline_routes пуст -> «длины не меняются». Доля неизвестного доступа — только «по длине сети»
   (graph_coverage.known_access_share_by_length); доли по числу рёбер движок не даёт -> «нет данных»; если R07
   добавит graph_coverage.unknown_access_share_by_edges (0..1), помощник покажет её отдельной фразой.

4. UI R09 (web/civic/assistant/assistant.js)
   CivicAssistant.mount({root, api, objectId, scenarioId?, revision?, onStale?}) -> {ask, update, destroy}.
   Шлёт revision; на object_revision_changed ответ не показывает и вызывает onStale({objectId, revision}).
   update({objectId?, scenarioId?, revision?}) отменяет текущий запрос и убирает ответ по старой редакции;
   destroy во время запроса снимает обработчики, запоздавший ответ не появляется (проверено в Chromium).
