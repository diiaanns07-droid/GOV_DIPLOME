ТВОЁ КОНКРЕТНОЕ ЗАДАНИЕ
В учебном симуляторе AI уже есть, но новый GovTech-режим объясняет результаты шаблонами. Сделай пригодный для интеграции серверный адаптер к существующему провайдеру и тонкий клиентский адаптер действий. Не строй новый чат-продукт.
1. Прочитай agent/advisor.py, tools.py, evidence.py, offline.py и API в ui/web_server.py. Переиспользуй существующую конфигурацию, таймауты и обработку ошибок. Не читай и не печатай .env/ключи; программа может получать настроенные ключи обычным безопасным способом. Подготовь минимальный модуль и patch к API в своей папке.
2. Задача AI: понять запрос «сравни эти два места», «покажи, кому станет дальше», «каких данных не хватает», запросить необходимые инструменты и выбрать факты для объяснения. RU/KK поддержать на фиксированном наборе реальных по смыслу запросов. Инструменты ограничены case ID, допустимыми origin/candidate ID, сравнением и фактами источников. Свободный код, внешние URL и изменение плана без Apply недопустимы.
3. Контракт ответа: schema_version, request_id, case_digest, intent, допустимые tool calls, fact_ids, needs_clarification. Числа, название метода, подписи источников и итоговую рекомендацию формирует локальный движок/рендерер из текущего результата. Провайдер не является источником достоверности клиентских чисел. Любое действие проходит тот же валидатор и расчёт, что ручное; plan остаётся предложением до Apply. Неизвестные ID и устаревший digest отклоняются. Если метод — прямая, нельзя назвать результат пешим маршрутом. Не обещать увеличение школьной вместимости.
4. Онлайн/без ключа/таймаут/ошибка схемы/недоступность источника должны быть видимыми состояниями. Без ключа работает полезный шаблон с source=fallback; этот тест не считать живым AI. Число живых вызовов ограничить небольшим явно указанным лимитом; отсутствие разрешённого доступа к провайдеру = NOT_RUN без бесконечных попыток.
ACCEPTANCE: исполнимый модуль, минимальный patch, tests/expected для корректных и враждебных ответов, stale response, RU/KK и offline; live-eval.json только с реально вызванной моделью/датой/расходом либо NOT_RUN. Отдельно укажи, что проверено автономно, а что ещё не подключено к сайту.
Не создавать вторую реализацию оптимизатора. Вызовы расчёта делай через узкий adapter API CONTRACT; интеграцию endpoint и общих файлов выполняет BUILD.
