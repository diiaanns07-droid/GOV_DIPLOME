# Model card — классификатор обращений v2 (R03, раунд 14, Birge · Астана)

> **Статус на 10.10.2026: модель обучена на ноутбуке владельца (LOCAL-4, RTX 4060, коммит c19b889).**
> Итоговая модель `civic-clf-v2-xlm-roberta-base-synth_all-daaa6dae4-s20261011` обучена **только на синтетике**
> (шаблонная v3 + LLM llm_v1). Независимый тест вне шаблонов probe_v2: **macro-F1 0.828 [0.778–0.865]**.
> Качество на текстах жителей: **NOT_EVALUATED** — шаги с текстами людей по решению владельца не запускались.
> Поэтому `needs_review` всегда true. Полная таблица — `results/RESULTS.md` (генерируется, руками не правится).

## Назначение
Подсказка категории обращения жителя Астаны (русский, казахский, смешанный, транслит) — одна из 12 категорий
`research/round-14/categories_v2.json` (`roads, snow_ice, sidewalks, transport, lighting, yards, waste, utilities,
smell_air, noise_safety, parking, other`). Используется в `POST /api/civic/v2/classify` (R04) и в мастере жалобы (R09):
«Похоже на: …». Модель **не** публикует и не отклоняет обращение, не определяет срочность и исполнителя;
житель и сотрудник всегда могут сменить категорию. Нет модели или ошибка — интерфейс даёт выбрать вручную.

## Ответ (CONTRACT §7)
`{category, score, needs_review, model_version, top3:[{category, score}]}` — `predict.Classifier.classify(text)`.
- `score` — softmax top-1, **не калиброванная вероятность** (ECE считается в отчёте).
- `needs_review = True`, если score < порога (подобран на validation по цели точности 0.90), категория `other`,
  в тексте < 3 букв, **или** порогу нельзя доверять: в обучении не было текстов людей (`review_policy = always`)
  либо рецепт не проверен на людях (`human_eval != EVALUATED`). Модель только на синтетике ⇒ всегда True (как v1).

## Модель
- Основа: `FacebookAI/xlm-roberta-base` (278 млн параметров, из них 192 млн — словарь 250 тыс. токенов; 100 языков,
  включая казахский и русский). Голова классификации на 12 выходов, дообучение всей сети.
- Обучение (`transformer.py`, цикл PyTorch без Trainer): длина ≤ 128 токенов, fp16 (CUDA), batch 16 × накопление 2,
  AdamW lr 2e-5, weight decay 0.01, warmup 10 %, линейное затухание, ≤ 8 эпох, **ранняя остановка по macro-F1 на
  validation** (терпение 2), веса классов `sqrt(N / (K·n_c))`, seed 20261011, лог каждой эпохи в JSONL.
  Малые наборы (только люди): эпох добавляется до 300 шагов оптимизатора (не больше 30 эпох), и ранняя остановка
  не срабатывает раньше этих шагов — иначе обучение обрывалось бы на разгоне и режим «люди» был бы занижен.
- Продукт: ONNX (opset 17) + динамическое квантование int8 (`onnxruntime.quantization.quantize_dynamic`, веса QInt8),
  токенизатор `tokenizers` — без torch на сервере. Файлы > 50 МБ — в `artifacts/` (вне Git).
- Версия: `civic-clf-v2-<модель>-<режим>-d<sha данных>-s<seed>` в `birge_meta.json`.

## Протокол эксперимента (`experiments.py`)
- Режимы: `synth_v1`, `synth_template` (v3), `synth_llm`, `synth_all` (v3 + LLM), `human` (только люди),
  `mix` (v3 + LLM + люди). Модели: словарная эвристика, «v1-метод» (логрегрессия на символьных n-граммах + словарь,
  признаки как у v1), трансформер v2; без обучения — LLM zero-shot и v1 как есть (если доступен пакет v1).
- **Независимый тест вне шаблонов — probe_v2** (до появления людей — главный честный ориентир): оценивается во всех
  режимах; в обучение и выбор параметров не входит, совпадающие тексты удаляются из обучения; в режимах human/mix
  его предсказывает ансамбль моделей фолдов (среднее вероятностей). Это всё ещё текст агента, а не жителей.
- **Один оценочный набор — все тексты людей.** Режимы без людей предсказывают их целиком; режимы human/mix — 5-fold,
  стратифицировано по категории, прогноз каждого текста делает модель, которая его не видела (out-of-fold).
- Выбор эпохи, порога и гиперпараметров логрегрессии — только на validation: синтетической (режимы synth_*) или
  15 % обучающей части фолда (human/mix). Тексты людей / синтетический test для выбора не используются.
- Из обучения удаляются тексты, совпадающие с оценочными после нормализации.
- Метрики: macro-F1 (по классам с support > 0, как v1), accuracy, weighted-F1, P/R/F1 по классам, матрица ошибок,
  ECE; 95 % ДИ — бутстрэп 2000 повторов (по текстам у людей и в probe_v2, по шаблонам у синтетического test);
  парная Δ macro-F1.
- «Потеря на людях» = macro-F1 на синтетическом test − macro-F1 на людях (главная цифра диплома); рядом —
  «потеря вне шаблонов» = синтетический test − probe_v2.

### ONNX int8 (продукт для R04)
| Вариант | Совпадение top-1 с PyTorch (200 текстов v3) | Время на текст, CPU ноутбука (24 потока) |
|---|---|---|
| int8, одна шкала на матрицу, все потоки (штатный экспорт кода 477f97b) | 96.5 % — **FAIL** (< 97 %); по одному тексту 98 % | 102.9 мс — **FAIL** |
| то же, 4 потока (диагностика Codex, отдельный процесс) | 96.5 % | 21.2 мс, p95 31.6 мс |
| int8 per-channel, 4 потока (диагностика Codex) | **98 %** в пачках и по одному | **22.7 мс**, p95 32.9 мс |

- fp32 ONNX совпадает с PyTorch на 100 % (max |Δp| 9e-6). Размер int8 — 266 МБ.
- Причина медленной работы: onnxruntime по умолчанию берёт все 24 потока гибридного процессора (P- и E-ядра).
- С кода этого коммита по умолчанию: квантование per-channel и `min(4, ядер)` потоков в `predict.py`
  (`BIRGE_CLF_V2_THREADS` меняет число потоков).
- Проверка в облаке на модели того же размера со случайными весами: 266 МБ, 17.8 мс, три PASS.
- Артефакт на ноутбуке ещё штатный: нужно повторить шаг 8 RUN.txt. Пока не повторено — критерии 97 % и 50 мс по
  умолчанию не подтверждены.
- Качество int8 на probe не измерено: 2 % текстов могут сменить категорию. Шаг 8б RUN.txt.

## Ограничения (честно)
- Модель обучена только на синтетике; качество на жителях не измерено. Не переносить числа синтетики и probe_v2 на людей.
- Один seed: разброс трансформера по seed не оценён (`--seeds 3` в RUN.txt шаг 6); ДИ отражают только выборку текстов.
- Метки llm_v1 — запрошенная у LLM категория, людьми не проверены. Шум меток в обучении не оценён.
- Синтетику писали агенты (R02, R08), словарь эвристики — R03, по одним и тем же правилам спорных случаев: на
  синтетике словарь и n-граммы выглядят лучше, чем будут на людях. Словарь эксперимента (версия v1) написан до
  просмотра корпуса v3 (видели 3 строки формата) и заморожен: отпечаток `DICT_V1_SHA256` проверяет тест.
  Продуктовая версия словаря (запасной уровень R04) = v1 + добавки по ошибкам приёмки: B-004, парковка на газоне.
  На probe_v2 она меняет 1 текст из 300: 0.684 → 0.689; на test v3 — без изменений. В таблицах диплома не
  используется.
- Разметка людей — один разметчик (владелец); согласие разметчиков — отдельно (`ml/labeling/agreement.py`, R02).
- 200–400 текстов людей ⇒ широкие ДИ (±0.05–0.10 macro-F1); редкие категории (parking, smell_air) могут иметь
  единицы примеров — их F1 неустойчив. Парная разница с ДИ, содержащим 0, — «преимущество не доказано».
- Казахские шаблоны не проверены носителем; транслит латиницей — слабое место базовых моделей (см. срезы style).
- Определитель языка для срезов (если язык не указан) считает казахский без специфических букв русским — поэтому
  срезы берут язык из записи (форма/разметка).
- `score` не калиброван (ECE 0.14 на probe). int8 меняет категорию примерно у 2 % текстов относительно PyTorch
  (сверка в `export_onnx`).
- LLM zero-shot отправляет обезличенные тексты людей во внешний API — только с согласия владельца, ключ из
  переменной окружения.
