# ml/datasets — данные классификатора обращений Birge (R02, раунд 14)

Научный вопрос диплома: **можно ли обучить классификатор обращений на казахском и русском на синтетике
и сколько он теряет на текстах живых людей.** Поэтому здесь строго разделены три вида данных:

| Что | Где | Вид | Кто разметил | В Git |
|---|---|---|---|---|
| Шаблонная синтетика v3 | `synth_v3/data/corpus_v3.jsonl` | `evidence: synthetic` | агент (Claude, R02) по правилам v2 | да |
| Пары перефразов для поиска дублей | `synth_v3/data/paraphrase_pairs_v3.jsonl` | синтетика | генератор (тот же случай / другой) | да |
| Корпус v1, переведённый в 12 категорий | `v1_in_v2/corpus_v1_in_v2.jsonl` | синтетика R08 (раунд 12) | агент R08 → правила R02 | да |
| LLM-синтетика | `llm_v1/corpus_llm_v1.jsonl` (появится после запуска у владельца) | `evidence: synthetic_llm` | категория из запроса (не проверено человеком) | да, без кэша |
| Тексты людей (Google-форма) | `private/form_*.jsonl` | `evidence: real_human_text` | владелец (+ второй разметчик, + LLM) | **никогда** |

Категории — только `research/round-14/categories_v2.json` (12 штук). Что считается чем — `LABELING_GUIDE_v2.md`.

## Шаблонная синтетика v3 (`synth_v3/`)

- `templates.py` — 221 шаблон: 12 категорий × ru / kk / mixed; семейства (одна проблема разными словами),
  регистры (официальный, разговорный, сленг, короткий, вопрос, благодарность), 53 шаблона трудных случаев из правил
  (снег на тротуаре → `snow_ice`, яма во дворе → `roads`, нет света на остановке → `lighting`…).
- `slots.py` — улицы Астаны (настоящие топонимы, ru и kk написание), места, остановки (условные названия),
  время, рамки обращений, детали для длинного стиля, выдуманные контакты.
- `build.py` — сборка с `SEED = 20261011`: варианты «длинный», «с опечатками» (соседние клавиши ЙЦУКЕН),
  «транслит» (три схемы казахской латиницы, включая латиницу 2021 года), «сленг», «смешанный» (рамка на другом языке),
  иногда контакты → затем обезличивание `ml/labeling/anonymize.py` (в корпусе маркеры `[телефон]`, `[адрес]`, …).
- Удаление утечек: точные повторы до split; split **по шаблонам** внутри (категория × язык): val/test — только
  шаблоны, которых нет в train; короткие шаблоны — только train; val/test с Jaccard 3-грамм ≥ 0.8 к train
  помечаются `excluded_near_dup`.
- Итог (manifest_v3.json): 4260 сообщений — train 2659 / val 945 / test 656; ru 2060, kk 1542, mixed 658;
  все 12 категорий в каждом split.

Поля строки: `id, text, label, lang, split, template_id, family, register, variant, style, hard, anonymized,
evidence, corpus` (+ `max_train_jaccard` у val/test).

Пары `paraphrase_pairs_v3.jsonl` (для R04, поиск «Я тоже»): `a, b, same_incident, kind` —
`paraphrase` / `paraphrase_same_template` / `paraphrase_crosslingual` (тот же случай, в т. ч. ru ↔ kk) и
`same_place_other_problem` / `same_problem_other_place` (трудные отрицательные); `split: dev|test` по семейству.

Пересборка и проверка воспроизводимости:

    python -m ml.datasets.synth_v3.build
    python -m ml.datasets.synth_v3.build --check     # sha256 совпадает с manifest_v3.json

## v1 → v2 (`v1_in_v2/`)

Корпус R08 (раунд 12, 2725 строк, 6 меток) переведён в 12 категорий. Две метки:
`label_table` — строго по `v1_to_v2`; `label` — уточнённая по правилам v2 (снег/лёд → `snow_ice`; из v1-«other»
выделены мусор, ЖКХ, шум/собаки, парковки; вопросы и благодарности остаются `other`). Отличаются 393 строки —
это и есть цена механического перевода. Для обучения брать `label`. Источник читается из ветки v1 без изменений
(`ml/civic_classifier/` не трогаем); команда — в docstring `v1_in_v2/convert.py`.

## LLM-синтетика (`llm_synth.py` → `llm_v1/`)

Отдельный корпус для сравнения «шаблоны против LLM». Запуск только у владельца (облако без доступа к API).
Определения категорий в промпте берутся из `LABELING_GUIDE_v2.md`. После ответа — обезличивание, фильтр длины,
удаление повторов, почти-повторов (Jaccard ≥ 0.85) и совпадений с v3; split по запросам ≈ 70/15/15.
Кэш ответов — `private/llm_cache/synth/` (в Git не идёт). Команды и стоимость — `research/round-14-results/R02/RUN.txt`.

## Тексты людей и разметка (`ml/labeling/`, `web/labeling/`)

1. Google-форма (LOCAL-6) → CSV в `private/` → `python -m ml.labeling.import_form private/form.csv`
   (согласие, обезличивание, повторы, язык, дата без времени, стабильный id) → `private/form_<дата>.jsonl`
   и `.review.txt` — строки для ручной проверки персональных данных.
2. Разметка: `web/labeling/index.html` (двойной щелчок, без сервера и интернета) → экспорт JSONL `birge-labels-v1`.
3. Согласие: второй разметчик (режим «Второй разметчик», тот же поднабор по ключу) и/или
   `python -m ml.labeling.llm_label` → `python -m ml.labeling.agreement A.jsonl B.jsonl` (Cohen's kappa, матрица).

`private/` создаётся скриптами с собственным `.gitignore` (`*`), поэтому реальные тексты не попадут в Git даже до
того, как R01 добавит `private/` в корневой `.gitignore`.

## Лицензии и происхождение

- Шаблоны, правила, синтетика v3, пары, перевод v1: написаны агентами проекта (R08 раунд 12, R02 раунд 14);
  лицензия — лицензия репозитория GOV_DIPLOME (в репозитории пока не указана — решает владелец).
- Названия улиц и районов — публичные топонимы Астаны; данные OpenStreetMap здесь не используются.
- LLM-синтетика: условия использования выбранного провайдера и модели (OpenAI — ответы принадлежат пользователю;
  модели на NVIDIA API — по лицензии конкретной модели, например Llama Community License требует атрибуции).
  Провайдер, модель и версия промпта записываются в `manifest_llm_v1.json`.
- Тексты людей: собраны с согласием «текст будет использован анонимно для исследования и обучения ИИ»;
  хранятся только у владельца в `private/`. Отправка во внешний API (LLM-разметчик) — только с флагом
  `--confirm-external` и после повторного обезличивания.

## Честные ограничения

- Шаблоны, правила и пробные фразы писал один автор (агент) — на синтетическом test модель будет выглядеть лучше,
  чем на людях. Ровно это и измеряет диплом: главный test — тексты людей.
- Казахские шаблоны и примеры не проверены носителем языка (владелец проверяет: `LABELING_GUIDE_v2.md`, ⚠).
- Обезличивание — регулярные выражения: имена удаляются только по явным шаблонам («меня зовут…», подпись,
  «Иванов И.И.»), адрес без ключевых слов и без известной улицы может остаться → ручная проверка `.review.txt`.
- LLM-скрипты в облаке проверены только на подставном транспорте (NOT_RUN с настоящим API).
