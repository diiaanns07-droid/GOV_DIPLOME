# data/civic/astana/landmarks — ориентиры Астаны (R05, раунд 15, поправка П1 «Настоящий город»)

`landmarks.json` (схема `birge-landmarks-v2`) — шесть ориентиров: Байтерек, Хан Шатыр, Акорда, мечеть Хазрет Султан,
Дворец мира и согласия, «Нур Алем» (ЭКСПО). Это **один источник центров и названий ru/kk** для двух мест:

- подписи и выделение зданий-ориентиров на подложке — R01 `web/civic/shell/basemap-style.js` (патч R05:
  `research/round-15-results/R05/patches/R01_landmarks_search_basemap.patch`);
- поиск в шапке («Байтерек», «пирамида», «экспо») и перелёт камеры к зданию — `web/civic/build3d/landmarks.js`.

**Моделей нет.** Здания рисует подложка (3D-здания OSM по `render_height`); нарисованные копии зданий отменены
поправкой П1. Копия файла для браузера — `web/civic/build3d/data/landmarks.json` (файлы одинаковые, их пишет один
инструмент).

## Поля записи

| Поле | Что это |
|---|---|
| `id` | тот же id, что в `basemap-style.js` R01: `baiterek`, `khan-shatyr`, `akorda`, `hazrat-sultan`, `palace-peace`, `nur-alem` |
| `name.ru` / `name.kk` | название (подсказка поиска, заголовок «Сейчас на карте») |
| `label.ru` / `label.kk` | подпись на карте; у «Нур Алем» — «Нур Алем · ЭКСПО», у остальных = `name` |
| `kind.ru` / `kind.kk` | вид здания — вторая строка подсказки («монумент · район Есиль») |
| `aliases` | другие написания для поиска (латиница, «пирамида», «ЭКСПО») |
| `lat`, `lon`, `district` | центр здания и район (по `web/civic/build3d/data/astana-districts.json`) |
| `radius_m` | допуск «здание подложки — этот ориентир» (выражение `distance` MapLibre в `basemap-style.js`) |
| `camera` | камера перелёта из поиска: `zoom`, `pitch` 52° (как кнопка «3D» оболочки), `bearing` |
| `osm_object` | объект OSM с именем, если он есть в снимке (пирамида — node 5009488810), иначе `null` |
| `coords` | как выведен центр: способ, линии и узлы OSM, проверки; `check: "LOCAL-13"` |

## Откуда координаты

Только из данных OSM в репозитории. Контуров самих зданий в репозитории нет (выгрузка LOCAL-1 брала площадки,
остановки, парки, дворы), поэтому центр каждого здания выводится из снимка пешеходной сети
`data/civic/astana/osm-walking/overpass.json.gz` (OSM на 2026-05-06) — по дорожкам и проездам, которые обходят здание:

| Ориентир | Способ | Линии и узлы OSM | Проверка |
|---|---|---|---|
| Байтерек | центр круглой площади | way 258818019 (кольцо r = 42 м) | внешнее кольцо 258818051 — 0,6 м; входы 2389116250 / 2389116244 — 5,7 / 7,4 м |
| Хан Шатыр | центр эллипса кольцевого проезда | way 164938029 (43 точки) | вход в шатёр 13294095201 — 95 м от центра (≈ радиус основания) |
| «Нур Алем» | средний центр 5 колец ЭКСПО | ways 455013941/2/3, 1461824179/80 | разброс центров колец 1,1 м |
| Акорда | центр пустого места между дорожками | ось — сады 329669144 и 329669208 | центр в 2 м от оси садов |
| Мечеть Хазрет Султан | центр двора внутри кольца дорожек | way 1373014142 | пустое место 2,5 га, все 720 лучей упираются в дорожки (63–117 м) |
| Дворец мира и согласия | узел с именем здания | node 5009488810 | центр пустого квадрата дорожек — 4,6 м |

Подробности (радиусы, разброс, площади) — в поле `coords` каждой записи.

**Пометка `check: "LOCAL-13"`** у каждой записи: это вывод по соседним линиям, а не контур здания. На ноутбуке Codex
выгружает контуры зданий через Overpass (задача LOCAL-13 в `research/round-15-results/R05/INTEGRATION.txt`) и сверяет
центр; расхождение больше 10 м — поправить способ вывода и пересобрать.
