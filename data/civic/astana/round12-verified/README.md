## Как кандидат становится подтверждённой записью

1. Открыть URL кандидата (человек в браузере или сессия, где домены разрешены).
2. Сохранить текст страницы **вне репозитория** (полный текст статей в Git не хранится).
3. Заполнить `drafts/<id>.json` по `SCHEMA.md`: значение поля + дословная выдержка (≥ 3 слов, ≤ 300 символов);
   дата/сумма должны быть в самой выдержке, иначе — объяснение в `value_basis` (запись станет `derived`).
4. `python3 -I data/civic/astana/round12-verified/tools/r12.py verify drafts/<id>.json --text src-id=/путь/page.txt --published-on src-id=YYYY-MM-DD --retrieved-at 2026-10-07T12:00:00Z`
   — запись переходит в `verified/`, только если каждая выдержка найдена целыми словами; sha256 текста и
   отпечаток проверенных утверждений записываются (правка после проверки её аннулирует).
5. `python3 -I data/civic/astana/round12-verified/tools/r12.py build` — пакет; сборка применяет профиль `real`
   валидатора R05 (`data/civic/astana/tools/civic_v1.py`) и без него записи не пропускает.

Команды целиком — `research/round-12-results/R05/RUN.txt`; лист проверки — `research/round-12-results/R05/VERIFY_SHEET.md`.

## Геометрия

Только из открытого OSM-снимка проекта (2026-05-06, ODbL): пересечение двух названных улиц, участок между
двумя пересечениями или улица целиком, если она одна связная цепочка. Одноимённые несвязанные участки не
склеиваются; адрес не найден — `geometry: null`. Точность всегда `approximate`; центр района не подставляется,
геометрия закрытых карт не используется. Майский снимок — не наблюдение октября.
