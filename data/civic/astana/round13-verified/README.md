(`network_audit.json`), поэтому здесь подготовлен воспроизводимый путь проверки, а не загрузка данных.

| файл | что это |
|---|---|
| `analysis/queue_analysis.json` | разбор 19 текущих кандидатов раунда 12: дубли, противоречия, цели проверки |
| `VERIFY_QUEUE.json` | очередь целей с вычисленным состоянием и тем, что открыть и выписать (строит `r13.py queue`) |
| `evidence/<slug>/<source>.json` | прикреплённые доказательства (пишет только `r13.py attach`) — сейчас пусто |
| `reviews/<slug>.json` | проверки сотрудником (пишет только `r13.py review`) — сейчас пусто |
| `package.civic-v1.json` | черновики civic-v1 для импорта R02 (текущие/предстоящие) — сейчас 0 записей |
| `historical.civic-v1.json` | черновики прошедших работ — сейчас 0 записей |
| `summary.json` | счётчики: verified_current, verified_historical, candidates, rejected, fetched_sources, покрытие |
| `config.json` | срез `as_of`, порог устаревания статуса (45 дней), минимальная длина текста страницы |
| `network_audit.json` | журнал отказов сети раунда 13 (без секретов) |
| `tools/r13.py` | инструмент (stdlib); правила сверки выдержек и геокодер — из `../round12-verified/tools/r12.py` |
| `SCHEMA.md` | форматы и правила |

Путь записи: `candidate → evidence_attached → (review) → draft_ready → пакет черновиков → импорт R02 (draft)
→ публикация сотрудником в кабинете R04`. Ни один шаг не публикует автоматически. Пошаговые команды —
`research/round-13-results/R05/RUN.txt`.

Различимость данных: здесь только реальные записи (`evidence_type` observed/derived, `slice.demo=false`).
Синтетика — в `../demo_synthetic.json`; учебная модель Астаны и Шымкент — в своих каталогах.
Тесты работают на синтетике во временном каталоге и в этот пакет ничего не пишут.
