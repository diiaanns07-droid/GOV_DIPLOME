# Городское планирование в основном интерфейсе

Запуск — корневой `run.bat` или `.venv/Scripts/python.exe -B app.py --host 127.0.0.1 --port 8501`.
Открыть `http://127.0.0.1:8501/`, нажать **Городское планирование** в верхней панели.

Сохранены светлый интерфейс, одна MapLibre-карта, здания в 3D и исходный учебный симулятор (Score 52,56).
Новый режим — отдельная модель: его расстояния, места и порог не подставляются в учебный Score.

## Главный путь: «Доступность школ» (раунд 10)

Вопрос: какие точки участка дальше от известных школ и какое из двух мест, A или B, лучше меняет доступность.
Это анализ пространственной доступности, не расчёт дефицита мест и не решение о земле.

1. Сверху — город, вопрос и 3 показателя (среднее до школы, точек в пределах порога, самая дальняя точка; «неизвестно», если есть).
2. Снизу — действия: **Место A**, **Место B** (пунктирный ромб на карте, своё место щелчком внутри рамки или список в карточке), **Подобрать лучшее**, **Сравнить**; вид **Сейчас / A / B / Разница**.
3. Справа (на 390 px — снизу) одна карточка: вопрос и данные → выбранная школа/точка/место → результат сравнения.
4. Линии «точка → ближайшая школа» — слой MapLibre, пересобирается для Сейчас/A/B. «Разница» окрашивает точки: ближе / без изменений / неизвестно.
5. **Как считать расстояние**: по прямой (по умолчанию, подписано) или по улицам (граф K03 pedestrian-v1: «проверенные» / «неполные данные»). При отсутствии пути — «неизвестно», прямая не подставляется.
6. **Спросить о результате**: сервер `/api/school-ai`; модель (если провайдер настроен на сервере) выбирает только ID фактов и действия показа; текст и числа собираются из расчёта. Без провайдера — помеченный шаблонный ответ. Устаревший ответ отбрасывается.
7. **Скачать записку (HTML)**, **Сохранить кейс (JSON)**, **Загрузить кейс…** (принимает и JSON, и записку): строгая проверка, привязка к срезу, сверка `case_digest`; отказ ничего не меняет.

Данные кейсов:
- Шымкент — пакет K01 r10 (5 школ после ручного обзора 15 записей, 12 точек-сетки, 3 места-гипотезы).
- Астана — пакет K10 r10 (40 школ включая буфер 2,1 км, 23 точки — центры жилых зданий OSM, 3 места-гипотезы).
- Если пакет не прошёл проверку хэша/схемы/привязки, используется кейс, собранный из среза (`overture-school-category-v1`), с пометкой.
- Все школы — вторичные данные (Overture/OSM); официальный перечень, вместимость и правила приёма не сверялись. Точки — не жители. Места — не участки. Стоимости нет.

Прежний план v2 (бюджет в условных единицах, 16 кандидатов, Парето) и устойчивость — кнопка **Расширенный режим**; возврат — **← Доступность школ**.

## Устройство

- `shell.js` — адаптер существующей MapLibre-карты: режимы, города, камера, 3D; хуки `onMap/onActive/onMode` для школьного пути.
- `school/case.js` — school-access-case-v1: кейс, проверка, `normalizeCase` (пакеты коллег), `bindToSlice`, матрица по прямой, `compareCase`, факты, `case_digest` (канонизация `sac-canon-v1`), импорт/экспорт.
- `school/school-ui.js`, `school/school.css` — интерфейс пути; `school/note.js` — записка.
- `school/cases/` + `school/SCHOOL_MANIFEST.json` — пакеты K01/K10 байт-в-байт с sha256 (сверяются и в браузере перед использованием).
- `k03/` — модуль маршрутов и графы K03 (ODbL), `K03_MANIFEST.json`.
- `core/` — закреплённые модули BUILD `d18847f`; происхождение и хэши в `SOURCE_MANIFEST.json` (адаптации UI: plan-ui.js, resilience-ui.js).
- `agent/school_ai.py` — серверный AI-шов школьного кейса. `ui/web_server.py` раздаёт только явно перечисленные файлы.
