# Городские данные: Шымкент / Астана (демо BUILD, раунд 8)

Демо открытых вторичных данных (Overture Maps 2026-09-23.1) для **двух квадратов ~2×2 км** — по одному в Шымкенте и Астане. Это не целые города, не официальный реестр, не учебная модель STUPITS. Пешеходная проходимость не утверждается. Объяснение — шаблон, а не ответ LLM. Основной сайт (корневые `web/`, `agent/`, `engine/`, `data/`, `run.bat`) не меняется.

## Запуск (Python 3, только стандартная библиотека, без сети и ключей)

Linux / macOS:
```bash
cd prototypes/city-evidence
python3 serve.py            # → http://127.0.0.1:8765/   (python3 serve.py 8765 --open — открыть браузер)
```
Windows: двойной щелчок по `prototypes\city-evidence\run-demo.bat` или в консоли:
```bat
cd prototypes\city-evidence
py -3 serve.py 8765 --open
```
Можно и просто открыть `web/index.html` в браузере (file://).
**Проверено только на Linux.** `run-demo.bat` и команды Windows автором не запускались.

## Что на экране
- Шымкент / Астана: при смене города сбрасываются выбор, точка, подсказка и ожидающее объяснение.
- Слои объектов и дорог, фильтр 7 категорий, раскраска дорог по данным о проходе пешком. Расстояния — только по прямой.
- **QA-метки:** группа записей с одинаковыми координатами (в Шымкенте 10 записей в точке 69.5958, 42.3167) обведена на карте. В карточке объекта — список остальных записей этой точки, кандидаты в дубликаты и сомнение в категории с правилом и причиной. Записи не удаляются.
- Район по правилу K03 v2. Неоднозначный район не присваивается, показываются кандидаты.
- Каталог фактов и «Объяснить срез». «0 записей» означает ноль в полном ответе запроса по квадрату; «нет данных» — значение неизвестно, причина указана.
- Источники: атрибуция по `sources[]` записей (K08), ссылки на `web/attribution/ATTRIBUTION.md` и тексты лицензий.
- **«Если добавить объект»** (раунд 7, гипотеза, `web/whatif.js`, контракт `city-whatif-v1`): школа или поликлиника; 1–10 контрольных точек и один проектный объект (поставить / передвинуть / удалить). Таблица «до / после / разница» — расстояние **по прямой в пределах среза** до ближайшей записи категории, с источником и QA-метками этой записи. Проектный объект — отдельный слой с подписью «Проектный объект», в счётчики, таблицу объектов и QA не попадает. Смена города или категории сбрасывает сценарий с объяснением. Сохранение/загрузка JSON (≤256 KiB, строгая проверка, числа из файла пересчитываются; при ошибке состояние не меняется) и шаблонное объяснение по вычисленным фактам.
- **«Несколько объектов (v2)»** (раунд 8, `web/plan.js` + `web/plan-ui.js`, контракт `city-plan-v2`): переключатель «Один объект (v1) / Несколько объектов (v2)» в карточке «Сценарии». До 25 контрольных точек с весами 1..100 (приоритет, не жители), до 16 кандидатных мест со стоимостью в **условных единицах**, бюджет, максимум объектов (0..5), радиус охвата (по прямой, не норматив), «обязателен / исключён». Ручной план с допустимостью и таблицей до/после. **Точный перебор** всех наборов (≤ 65 536) по трём целям — «Среднее», «Худшая точка», «Охват» — с Парето (таблица + график) и бюджетами 0 / B/2 / B; поиск идёт порциями, его можно отменить, устаревший ответ отбрасывается, найденный план применяется только кнопкой «Применить». Шаблонное объяснение (не LLM), строгий JSON-экспорт/импорт (подделанные derived_results отклоняются), HTML-отчёт без скриптов. Синтетический демо-набор подписан как выдуманный. Оптимум — только среди введённых мест, не рекомендация строить.
- Клавиатура: Escape сбрасывает выбор и выходит из режима постановки; на карте в фокусе стрелки сдвигают её, «+»/«−» меняют масштаб, в режиме точки Enter ставит точку.

## Проверка
```bash
cd prototypes/city-evidence
python3 tools/check_all.py [--log check.json]     # входы, пакет K10, контракт, сборка, свежесть привязки, факты, unit-тесты
python3 tools/check_evidence_fresh.py             # быстро: evidence.js построен из текущих K03 и data.js (без shapely)
NODE_PATH="$(npm root -g)" node tests/smoke.cjs   # браузер (Playwright + Chromium), отдельно; вывод в tests/out/
NODE_PATH="$(npm root -g)" node tests/whatif_smoke.cjs   # браузер: сценарий «Если добавить объект» в обоих городах
node tests/whatif.cjs                              # whatif.js = Python-эталон tools/whatif_ref.py + правила импорта
node tests/plan.cjs                                # plan.js = независимый Python-оракул tools/plan_oracle.py + правила city-plan-v2
NODE_PATH="$(npm root -g)" node tests/plan_smoke.cjs     # браузер: сценарий v2 в обоих городах (поиск, отмена, применение, файлы)
NODE_PATH="$(npm root -g)" node tools/bench_plan.cjs     # замер 16×25 (только эта машина)
```
`check_all` без shapely/pyproj помечает пересборку `evidence.js` как SKIP, а не как PASS. Полная проверка: `pip install -r requirements-build.txt`. Без сети после установки зависимостей.

## Обновление входов (не нужно для демонстрации)
Сборщики отказывают с `INTEGRITY:` или `SEMANTIC:` и ничего не записывают, если входы не согласованы: хэш не совпадает, манифест не закреплён в `source_manifest.json`, NaN, повтор ключа, чужой bbox/выпуск/город. Поэтому новые данные K10 подключаются только полным циклом: `copy_inputs.py` → наблюдения K05 для нового файла → атрибуция K08 → `build_data.py` → `build_evidence.py`. Прямая правка файла в `inputs/` намеренно не пройдёт.

## Ограничения
- Квадраты выбраны по максимуму объектов: это не репрезентативная выборка и не сравнение городов.
- Районы — OSM/Overture, юридически не проверены. Совпадающие координаты делают район записи ненадёжным.
- Права прохода у большинства сегментов неизвестны, маршрутного режима нет. Длины — геометрические длины сегментов K10.
- Казахские подписи — черновик. Грамматика единиц шаблонная («1 записей»).
- K08 F5: в Астане 26 источников ссылаются на `routes`, колонка не извлечена; восстановить из пакета нельзя.
