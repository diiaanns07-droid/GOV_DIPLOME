## 2. Показатель и его точный охват

`overture_place_records.<group>.conf_ge_<t>`. Это **число записей** Overture places выпуска `2026-09-23.1`:
- группа определяется правилом K10 `places_by_district.group()`;
- confidence ≥ t (0.0 или 0.5);
- точка лежит в полигоне района того же выпуска;
- учитываются только записи из выгрузки K10 в рамке `query_bbox`.

Единица — `records`, а не «школы». Это не число школ в городе и не официальный реестр: K10 называет полноту Overture неизвестной. Запись типа `derived` (подсчёт, точка в полигоне, правило группировки), период — снимок `2026-09-23`.

Вторая форма — `k10_sample_rows.<group>`: строки образца K10. Образец берёт до 15 строк на группу по убыванию confidence (`cap_per_group=15`, `complete=false`).

### Новая находка: рамка выгрузки K10 не покрывает города целиком

В `overture_extract.py` рамки названы «с запасом», но они уже полигонов городов:

| Город | Рамка K10 | Охват полигона | Районы с неполным охватом |
|---|---|---|---|
| Шымкент | 69.35–69.95 / 42.10–42.55 | 98,11% площади (вне рамки 22,17 км²; запад, долгота < 69.35) | Абай 95,54% |
| Астана | 71.15–71.80 / 50.95–51.35 | 97,23% (вне рамки 22,15 км²; юг, широта < 50.95) | Есиль 94,33%, Байконур 99,95% |

Площади посчитаны геодезически (pyproj WGS84, shapely 2.1.2) по полигонам K10. Следствия:
- Счётчики K10 E02 для Абая, Есиля и Байконура — **нижние границы**. Адаптер ставит им `coverage.complete=false` и `area_fraction`.
- Городские суммы тоже неполные. Например, по Астане school ≥ 0.5 = 114 при `coverage_complete=false`.
- Доля площади вне рамки ≠ доля пропущенных объектов (окраины). Сколько записей потеряно, неизвестно до повторной выгрузки с полигоном или широкой рамкой.

Для K10: рамку стоит строить из полигона города с буфером.

### Сверка образца с E02 (независимая)

Для групп, где в городе меньше 15 записей, образец должен содержать их все. Это совпало: Шымкент preschool 7 = 7, government_office 13 = 13. Сумма school ≥ 0.0 по Шымкенту = 79, как в STATUS K10. Внутренняя согласованность E02 и образца подтверждена. Сами строки Overture я заново не выгружал.

## 4. Контракт k05-obs-v1.1: что добавлено к v1

v1 остаётся без изменений (`research/next-round/K05/`). В v1.1 добавлено:
- обязательные поля `coverage` {complete, scope, selection, area_fraction, cap_per_group}, `method` {id, steps, parameters} и `boundary_version`;
- `period` может быть `unknown`, но только без числа;
- `release`;
- `missing_reason` (`source_access_denied`, `not_collected`, `not_in_source`, `zero_in_partial_coverage`, `suppressed_by_publisher`);
- у источника должен быть `sha256` или `url`, есть поле `evidence`.

Новые семантические правила:
- `ZERO_ON_PARTIAL`, `PARTIAL_COVERAGE`, `PERIOD_UNKNOWN`, `MISSING_REASON`;
- `STALE` считается от конца периода (даты снимка), а не от времени скачивания;
- `SUPERSEDED`, `BOUNDARY_MISMATCH`, `BOUNDARY_VERSION_UNKNOWN`, `BOUNDARY_UNVERIFIED`.

Агрегат отклоняет смешение городов, периодов, единиц, показателей, версий данных и типов (synthetic/hypothesis с измерениями), а также повтор территории. `null` в агрегате не превращается в 0, неполный охват передаётся итогу.

## 5. Ограничения

- **Overture — вторичный неофициальный источник.** Записи POI — агрегат коммерческих и открытых данных; границы — OSM на дату выпуска. Официальные данные (stat.gov.kz, data.egov.kz) недоступны из среды: в K10 access_log CONNECT 403. Я их повторно не запрашивал. Из сети этого раунда — один запрос к публичному S3 Overture (список выпусков, HTTP 200).
- **Сырые выгрузки K10 (3–22 МБ) не в git.** В записях есть их sha256 из `raw_extracts.sha256`, но заново пересчитать E02 по сырым строкам я не мог: использованы счётчики K10 E02. Независимо проверены только образцы, площади и согласованность образца с E02.
- `max_age_days=45` — параметр примера, а не норматив.
- Оценки пар-дубликатов — гипотезы. Правило «та же группа + номер дома + < 50 м» даёт ложные срабатывания (Terra Pharm / Europharma), поэтому это очередь на проверку.
- Сарайшык в Overture — `locality`, а не `county`. В E02 он учтён как район; пересечений с районами K10 не нашёл.
- 11,03 км² Астаны не входят ни в один район (находка K10). Точек POI там 0, поэтому сумма по районам = счёт по городу в рамке.
